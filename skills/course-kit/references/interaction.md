# 交互与动效

用途：有哪些交互方式可选、互动怎么设计才好玩又不难、键盘和触屏怎么做、动效四类的时长和开关细则。底线在 `SKILL.md` 第三、四节；各组件的结构在 `components.md`。**API 以 `kit/README.md` 为准**；表里 G6–G10、M1 的翻牌（`.vl-flip`）、M2 热区、K5 投票、E2 拖线、`.vl-pad` 的代码在 `kit/vl-interact.js`，G11 活图在 `kit/vl-plot.js`，写法见 kit/README.md 第七节；G1–G5 只有外壳 `.vl-board` 和控件类，舞台由章节自写；M1 的 draw、then-run kit 里暂无。

## 二、互动设计规则

好互动的标准：**意图清楚、上手不难。** 下面每条都围绕这一点。

| # | 规则 | 怎么查 | 正例 / 反例 |
|---|---|---|---|
| 1 | 出场前一句话说清它要回答什么问题 | 互动台标题本身就是那个问题；读者不读后文也知道玩它是为了弄清什么 | 正例：轰炸机图——问题就是"装甲加在哪"，点一个部位就是回答；反例：标题只写"实验室""模拟器" |
| 2 | 控件少，3 秒内知道怎么玩 | 主控件 ≤3 组；第一眼能看出"拖这个 / 点这个"；不需要读说明书 | 正例：拆房子——点一块拆一块；反例：一排五六个滑块同时可调 |
| 3 | 先预测，再看结果 | 能先猜的都先猜（M1 then-run：选了预测才能运行） | 正例：先猜再跑的模拟 |
| 4 | 每次操作都有看得见的后果 | 点完、拖完，图、读数或反馈句至少一样变；后果是概念的后果（塔垮了、曲线弯了），不是只变颜色 | 正例：核心循环环形图，点一环就削弱或拆掉它，循环跟着断开 |
| 5 | 能撤销、能重来 | 每台都有"重来"；多步操作有"撤销一步" | — |
| 6 | "试试看"给可观察的目标，完成时 JS 判定并给反馈 | 目标写成能检查的状态；默认状态不能不动就达成 | 反例："玩一玩看"，没有完成条件 |
| 7 | 输出画成图或一句话，不吐一串数字 | 读数只留 1–3 个关键量，其余画进图里 | 反例：代码实验室输出一串数，读者看不出意思 |
| 8 | 一个互动只服务一个概念 | 删除测试：删掉它，读者会少懂哪件事？说不出就删；两个互动讲同一件事就合并 | — |
| 9 | 考懂没懂，不考手准不准、不考记忆力 | 小游戏输了按读者实际错处诊断，不靠反应速度定胜负（概念本身是反应速度时除外） | 正例：小游戏复盘写意思，不报数 |
| 10 | 难的玩法进进阶抽屉 | 主线互动用最简单的那一版；多参数、自由模式、第二关以后放进 P4 支线"多玩一会儿"，摘要写"几局、约几分钟、可以跳过" | — |
| 11 | 读者亲手撞上概念，不是看机器撞上 | 读者做的动作就是概念里的那个动作（读者自己挑人 → 自己造出选择偏差） | 正例：池塘撒网：读者自己选在岸边撒网，就亲手造出了"以为黄鱼多"的偏差 |
| 12 | 选择题只在练习里 | 正文里的"选一个"只用于 M1 预测，且每个选项有各自的反馈 | — |
| 13 | 互动不能是唯一的讲解 | 正文给不玩的读者讲清"玩了会看到什么" | 小游戏的正文里讲清游戏发生了什么 |
| 14 | 一章大互动合计 ≤5 | 招牌 1–2 + 辅助 0–2（content-rules.md 一A）；两个大互动之间至少隔一段文字和一张静态图 | — |

**设计一个互动前，先写这三行**（写不出就别做）：
1. 它回答的问题：____？
2. 读者的动作：拖 / 点 / 拆 ____。
3. 读者会看到的后果，以及这后果说明了什么：____。

## 三、键盘与触屏

| 场景 | 键盘 | 触屏 |
|---|---|---|
| 所有可点的东西 | 是 `button` / `a`，或 `tabindex=0` + `role=button` + Enter / 空格 | 目标 ≥44×44px，相邻目标间距 ≥8px |
| 焦点 | `:focus-visible` 有清晰描边（皮肤给样式，不能去掉） | — |
| 弹层、面板 | Esc 关；关后焦点回触发按钮；点外面关 | 点外面关 |
| 横翻 | ←→ 翻；只在组件获得焦点时生效，不劫持整页 | 横滑 >50px 翻；只滚页签条不滚整页 |
| 拖拽 | Tab 选中对象，方向键移动，Shift 大步，Enter 放下 | pointer 事件 + `setPointerCapture` + `touch-action:none`；不用 mouse / touch 两套 |
| 画曲线（M1 draw） | ↑↓ 调各段高度，或改成几个滑块 | 手指画；画完可重画 |
| 滑块 | 原生 range（方向键、Home、End） | 拇指块 ≥28px |
| 小游戏 | `keys` 映射；舞台可聚焦，聚焦时方向键不滚页面 | 屏幕方向键 `.vl-pad` 3×3 |
| 分拣 / 配对 | 点选卡 → 点目标（"放进这里"） | 同左，拖放可选 |
| 状态播报 | 读数、反馈句 `aria-live=polite` | — |
| 颜色之外 | 对错、类型、状态都另配 ✓ ✗、虚线、删除线或文字 | — |

验收：`node <skill>/tools/check.mjs <课程绝对路径> chNN`（第 5 步调 `qa.mjs`）在 420px 和 1100px 点按钮、拖滑块；再手动从页首 Tab 到页尾，每个互动都要能完成"试试看"。拖拽、画预期曲线这类互动最容易漏掉键盘操作，要实测。

## 四、动效细则

### 1 四类

| 类 | 是什么 | 时长 | 缓动 | 关掉 / 减少动态时 | 谁来写 |
|---|---|---|---|---|---|
| 帮助理解 | 动效本身在教：垮塌、落球、换步、逐格亮起、条变长 | 换步 ≤350ms；条长 200–400ms；垮塌 ≤600ms；模拟按需 | `--ease` | **不播过程，直接显示最终状态**，必要时改成手动翻页；信息一点不丢 | 组件 / 章节 |
| 反馈操作 | 回应读者的手：按下、切换、揭晓、抖一下 | 按下 100–150ms；切换、揭晓 ≤300ms；失败轻抖 280ms | `--ease`；像素皮肤 `steps(n)` | 只留颜色 / 文字变化，不位移 | 组件，位移量归皮肤 |
| 阅读激励 | 读懂了的庆祝：盖章、点亮、收进图鉴 | 一次 ≤1.2s，不循环 | 皮肤定 | 不播，但状态照样记录 | 激励模块 + 皮肤外观 |
| 氛围 | 正文以外的生气：题头云、开场、过场、背景 | 循环动画周期 ≥8s（慢）；开场 ≤1.2s | 皮肤定 | 静止或不出现 | 皮肤 |

**氛围动效只在正文以外**（题头、背景、页边、过场）。正文区的元素不做常驻动画，不做滚动翻出以外的入场特效。

**阅读激励只在读懂后触发**：试试看完成、测验全对、综合关通关。不由滚动百分比或停留时长触发（反例：滚到 98.5% 放彩纸、概念卡停 1.5s 飞纸飞机）。每个事件只播一次。

### 2 时长与缓动

| 动效 | 建议值 |
|---|---|
| 按钮悬停 / 按下 | 100–150ms |
| 折叠箭头 | ≤200ms；内容显隐不做高度动画 |
| 目录面板弹出 | ≤250ms |
| 揭晓、例子切换 | ≤300ms（纸片翻页 .42s 要压到 300ms） |
| 失败轻抖 | 280ms，`VL.shake(el)` |
| 热区高亮、公式联动 | ≤200ms，只变透明度 / 描边 |
| 翻牌 3D | 400ms 左右（帮理解，不受 300ms 限） |
| 激励（徽章、盖章） | ≤1.2s，一次（2s 的对决动画太长） |

`--ease` 默认 `cubic-bezier(.2,.8,.3,1)`；`--dur-fb` 默认 200ms；像素皮肤用 `--steps`（`steps(3)`–`steps(6)`）代替平滑缓动。值由皮肤在变量里给（见 `skin-contract.md`），组件只引用变量。

### 3 三档开关

- 档位类挂在 `<html>`：`html.vl-fx-full` / `.vl-fx-lite` / `.vl-fx-off`（`kit/vl-head.js` 在首屏前写，`vl.js` 改档时更新并派发 `vl:fx {level}`）。
- **自动判定**（代码在 `kit/vl-head.js`）：系统"减少动态"或无头浏览器 → off；宽度 ≤700px 或 `pointer:coarse` → lite；其余 full。
- **顶栏手动**："显示"弹层里"自动 / 全开 / 轻量 / 关"，读者选了就覆盖自动结果并存档（键 `vl-fx`，不带课程前缀，跨课、两种语言共用）。系统开了"减少动态"时**始终是 off**，手动选择不生效，弹层里写明原因。
- 各档允许什么：

  | | full | lite | off |
  |---|---|---|---|
  | 帮助理解 | 播 | 播 | 直接显示终态 |
  | 反馈操作 | 播 | 播 | 只变色 |
  | 阅读激励 | 播 | 播（粒子减半） | 不播，照样记录 |
  | 氛围 | 播 | 静止（只留开场，缩短） | 不出现 |
  | 跨页过场 | 播（≤0.9s） | 缩短（≤0.55s） | 直接跳转 |

- 全局兜底：
  ```css
  @media (prefers-reduced-motion: reduce){
    *{animation:none!important;transition:none!important;scroll-behavior:auto!important}
  }
  ```
  kit 的 `vl.css` 已带这条，另有 `html.vl-fx-off *{animation:none!important;transition:none!important}`。JS 驱动的动画（rAF、Web Animations、粒子）不受这两条管，要自己读档位：`if (!VL.motion()) { 画终态; return; }`（`VL.fx()` 返回 full / lite / off）。
- 截图和测试：无头浏览器默认 off；网址加 `?fx=1` 让无头也按正常档位判定（kit 已有）；`?scheme=dark|sepia` 临时换配色、不存档（kit 已有）；`?freeze=秒` 停在某帧（kit 里暂无，paper、pixel 皮肤自带）。

### 4 哪些属于皮肤

| 归组件（与皮肤无关） | 归皮肤 |
|---|---|
| 时长上限、触发时机、档位逻辑、关掉后显示什么 | 缓动曲线、位移量、是否用 `steps()` |
| 失败抖、揭晓、切换、条长过渡、换步 | 纸片翻页、像素弹出、按钮"按进纸里"的样子 |
| 激励事件（`vl:try`、`vl:quiz-perfect`、`vl:answer`、`vl:guess`） | 激励外观（盖章、亮灯、金币） |
| — | 题头环境动画、开场、跨页过场、背景视差、扫描线 |
| — | 手绘抖动、歪斜摆放（这些是静态，不算动画） |

章节专属的大动画（如垮塌动画、果汁台）由章节自写，但必须读档位、遵守上面四类的规矩。
