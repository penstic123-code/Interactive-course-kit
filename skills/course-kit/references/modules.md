# 可选模块

用途：开新课时逐项决定加不加的模块——什么时候值得加、怎么做、有哪些坑。决定写进课程项目文档。总原则在 `SKILL.md` 第五节；content-rules.md 第三节的"可选功能表"管内容侧的取舍，这里管做法。**API 以 `kit/README.md` 为准**；模块代码在 `kit/modules/`，写法见 kit/README.md 第八节。开关写在课程 `js/course.js` 的 `VL_COURSE.modules`（starter 模板里有；代码读的是 `collect`、`companion`、`sound`、`related`、`relatedFuture`，见 kit/README.md 第八节“配置”）。

| 模块 | 默认 | 一句话 |
|---|---|---|
| 阅读激励 | 不加 | 读懂一处就收集一件东西，外观随皮肤 |
| 陪伴角色 | 不加 | 一个会说话的角色，点了才说 |
| 概念关系图 | 概念多时加 | 全课概念怎么连；和概念卡、图鉴共用一份数据 |
| 术语悬停 / 术语表 / 闪卡 | 术语多时加 | 一份术语数据三处用 |
| 声音 | 不加 | 默认静音的短音效 |
| 学习路径 | 读者起点差别大时加 | 几条路线，点一条其余变暗 |
| 目录即地图 | 皮肤本身是地图时 | 一张地图 = 全课进度 + 本章目录 |
| 大事年表 | 历史分量大时加 | 全课发明故事按年份串起 |

---

## 一、阅读激励

**什么时候值得加**：读者年纪小、课程长、需要一点"往下读"的动力；有世界观的皮肤（爬塔、关卡）最自然。严肃的成人课可以不加。

**只奖励"读懂了"**：

| 触发（读懂的证据） | 记录键 |
|---|---|
| "试试看"完成（JS 判定） | `<课程id>-try`（kit） |
| 本章测验全对 | `<课程id>-progress`（kit）；徽章另存，键见 kit/README.md 第八节 |
| 篇末综合关每回合答对 / 通关 | 见 kit/README.md 第八节 |
| 测验连对 3 题（可选，小庆祝，不存） | — |

**明确不做**（本条是全 skill 唯一保留处，其余文件指向这里）：滚动百分比触发（反例：读到 92% 记"读过"、98.5% 放彩纸）、停留时长触发（反例：概念卡停 1.5s 就放纸飞机）、分数排行、血条、失败结局、连续打卡。原因：读到底或停得久不等于读懂，奖励错了位置，读者就会去刷进度。

**通用内核 × 各皮肤外观**（下表供设计参考；各皮肤现成的外观在 `skins/<名>/modules.css`）

| 内核 | 做什么 | 笔记本 | 纸片（爬塔 / 戏台） | 像素（GB / FC） |
|---|---|---|---|---|
| 单元徽章 | 每章一件代表本章概念的东西，点开可复习释义 | 邮票，贴进集邮册 | 道具收进背包 / 戏台道具箱 | 卡带、奖杯 |
| 子概念小卡 | 每个子概念一张，集齐一组有庆祝 | 图鉴页上一格 | 小物件进收藏册 | 金币、物品格 |
| 进度点亮 | 全课地图上读懂的章亮起 | 目录页盖章 | 塔窗亮灯 / 戏单打勾 | ★ + 章节方块变绿 |
| 任务打钩 | 试试看完成 | 便签打勾 | 便签白勾 + 纸屑 | CLEAR! |
| 未得剪影 | 还没得的显示剪影 + "读懂第 N 章就能拿到" | 空邮票框 | 灰剪影 + "？" | 问号砖 |
| 下一步推荐 | 指向第一个还没读懂的章 | 书签 | 小旗"接着爬" | 闪烁的关卡入口 |
| 完成仪式 | 读懂一章时一次 | 盖章"读懂了" | 守层者碎裂 / 谢幕 | STAGE CLEAR + 烟花 |

**怎么做**
- 组件只派事件（kit 现有：`vl:try {id, el, first}`、`vl:quiz-perfect {ch, firstTry, n}`、`vl:answer {i, firstTry}`；篇末综合关的回合事件见 kit/README.md 第七节），激励模块订阅、记录、播外观，只在 `first` 时给奖励。组件里不写奖励逻辑。
- 徽章数据和概念关系图、概念卡共用一份概念数据（见第三节），徽章的释义就是概念卡的"通俗地说"。
- 收藏处是对话框：Tab 走格子、←→ 翻页、Esc 关；每件可展开释义（`aria-expanded`）。
- 动效按"阅读激励"类（时长见 `interaction.md` 第四节）：off 档不播但照样记录。

**坑**
- 激励外观抢正文：庆祝层盖住正文超过激励时长上限，或每个小操作都放纸屑。只在读懂一处时放一次。
- "读过"和"读懂"混用：顶栏进度、目录页亮灯都只由测验全对决定。
- 徽章画成和概念无关的装饰物：每件东西要能让人想起那个概念（如背包里每件道具对应一章的概念）。

## 二、陪伴角色

**什么时候值得加**：皮肤有世界观（如爬塔的主角、掌机里的小机器人），或读者年纪小。默认不加。

**两种形式**
1. 正文对话框：作者写的台词，静态，随正文出现（某课例：`.npc`，56 处）。
2. 点击会说话的角色：固定在页边或进度条上（如爬塔里的主角）。

**规则**

| 规则 | 做法 |
|---|---|
| 点击才说话 | 主动冒话只在少数关键时刻（试试看完成、通关），每章 ≤3 次（经验值：再多就像在催读者说话） |
| 台词随内容 | 每节 `data-lines` 写 1–3 句，按当前节取；这一节没写就不说话，不拿通用台词凑 |
| 可关 | 顶栏开关，和动效、声音并列，存档 |
| 键盘可触发 | 角色是 `button`，有可读名称（"小伙伴，点一下听它说话"）；Enter / 空格触发；气泡 `aria-live=polite` |
| 语气 | 见 `zh-teaching-prose`「对话」（疑问、犯错、发现、情绪时出场；不卖萌、不替作者念定义），另外不说答案 |
| 不挡正文 | 气泡 `pointer-events:none`、不遮正文、滚动即收、约 2.6s 消失（经验值：够读完一两句，再长会挡住正文） |
| 当贯穿线索时 | 角色的成长写进项目文档（content-rules.md 一B ②） |

台词示例（同一节"选择偏差"）：✓"原来我只在岸边撒网，难怪全是黄鱼。"；✗"勇者大人，数据的迷雾正笼罩着我们！"；✗"选择偏差是指样本在收集前被筛选的现象。"（这是在念定义）

## 三、概念关系图

**什么时候值得加**：概念多（经验值 40 个以上：再少，读者靠目录和概念卡就找得到关系，不需要图）、彼此牵连、有先修关系。

**一份概念数据，三处用**：

课程的 `js/concepts.js` 写 `window.VL_CONCEPTS = {items, links, terms}`，由 `kit/modules/vl-concepts.js` 读成 `VL.concepts`；字段和边类型见 `kit/modules/concepts-schema.md`，API 见 kit/README.md 第八节。

| 用在哪 | 取哪些字段 |
|---|---|
| 概念卡 K1 | `zh en def plain illus`（卡片 HTML 可由数据生成，避免两处不一致） |
| 关系图 `map.html` | 全部；边类型：前置、解释、应用、对照 |
| 章末"相关章节" N5 | `links` 推出的章节 |
| 图鉴 / 背包（激励） | `zh plain illus` |
| 术语表 | `terms` |

**怎么做**：节点 = 概念名 + 章号；点节点亮它的邻居、旁边显示 def 和"去第 N 章"；按篇着色并加文字图例；世界观原理也登记成节点（content-rules.md 一D）。

**坑**
- 节点不能键盘操作（反例：节点没有 tabindex）：每个节点 `tabindex=0`，Enter 选中，方向键在邻居间走。
- 手机横滚（反例：给 SVG 写死 `min-width:900px`）：窄屏改成按篇分组的列表 + 点开看邻居。
- 力导向布局乱成一团：节点多到 60 个以上（经验值）时按篇分区排，不纯靠自动布局，否则会缠成一团。
- 未开放的章节的概念不进图，或显示为灰色且不可跳。

## 四、术语悬停、术语表、闪卡

**什么时候值得加**：术语多、读者零基础时三件一起加；一份数据三处用。

| 件 | 做法 | 坑 |
|---|---|---|
| 悬停释义 | 正文 `.vl-term[data-def]`（`components.md` K7）；JS 释义框夹在视口内 | 纯 CSS `::after` 在屏幕边缘出屏 |
| 术语表 `glossary.html` | `kit/modules/build-concepts.mjs --write` 把各章 `.vl-term[data-def]` 汇进 `js/concepts.js` 的 `terms`，`VL.glossary` 读它，按拼音 / 字母排；每条链回所在章 | 同一术语多处定义不一致：脚本报 ✗，以首次出现处为准 |
| 闪卡 `flashcards.html` | 莱特纳 4 盒：答对进下一盒、答错回第一盒；只出已读懂章的术语 | 不能键盘翻面：空格翻面、←→ 判对错；不用 emoji |

英文版三件都要有英文字段；存档键两种语言共用。

## 五、声音

**什么时候值得加**：游戏化皮肤（像素、爬塔）、低龄读者。默认不加；加了也**默认静音**。

**怎么做**
- 顶栏一个喇叭开关，存档（`<课程id>-sound`）；WebAudio 合成短音，不带外部音频文件。代码 `kit/modules/sound.js`，`modules.sound:false` 时整个模块不出现，见 kit/README.md 第八节。
- 音色归皮肤：皮肤 CSS 写 `:root{--vl-snd:paper|sine|square|triangle}`（`kit/modules/sound.js` 只认这四个）；notebook、paper、fieldbook = paper（铅笔 / 纸声），像素皮肤应为 square（方波 8-bit）。写在各皮肤的 `modules.css` 里，只引了 skin.css 没引 modules.css 时退回 sine。
- 教学用声音（如试听台）属于互动本身，同样默认静音、可关。

**坑**：静音复选框默认不勾，等于默认有声——要默认勾上。音效跟着每次滚动响会很烦，只跟操作和读懂事件。

## 六、学习路径

**什么时候值得加**：读者起点差别大、章数多（经验值 20 章以上：一次读不完，读者需要选路线）。

**怎么做**：目录页 2–5 条路线（如"一周入门""完整路线""底层原理路线"），每条 = 名字 + 一句"适合谁" + 章号列表；点一条，其余章变暗、路线上的章连线；路线数据写在课程 `js/course.js` 的 `VL_COURSE.paths`（`{name, who, chs}`，vl.js 不读，目录页读；`starter/index.html` 已做好"点一条其余变暗"）。

**坑**：路线跳过了后面章要用的先修概念——每条路线都要过一遍"每章用到的概念前面讲过"检查。

## 七、目录即地图

**什么时候值得加**：皮肤本身就是一张地图（塔、关卡路线）。

**怎么做**：目录页一张图三合一——全课地图、累计进度（读懂的章点亮）、本章目录（点图上的点跳到对应小节）。

**坑**
- 替代了 N4 浮钮后，窄屏行为要单独测。
- 键盘：地图上每个入口是 `button`，Tab 可达，有文字名。
- 章节插画要和地图同一套画法，否则风格互相打架。

## 八、大事年表

**什么时候值得加**：历史分量大、发明故事多的课。

**怎么做**：全课发明故事按年份串起，按类型筛，点事件跳到对应章节的故事框（kit 里暂无年表模块）。事件数据从各章 K10 / T5 汇出，不另写一份。

**坑**：年表上的年份、人名要和章内一致——从同一份数据生成。
