# 可选模块

用途：开新课时逐项决定加不加的模块——什么时候值得加、怎么做、有哪些坑。决定写进课程项目文档。总原则在 `SKILL.md` 第五节；content-rules.md 第三节的"可选功能表"管内容侧的取舍，这里管做法。**API 以 `kit/README.md` 为准**；模块代码在 `kit/modules/`，写法见 kit/README.md 第八节。开关写在课程 `js/course.js` 的 `VL_COURSE.modules`（starter 模板里有，现在代码读的是 `sound`、`related`、`relatedFuture`）。

| 模块 | 默认 | 一句话 |
|---|---|---|
| 阅读激励 | 不加 | 读懂一处就收集一件东西，外观随皮肤 |
| 陪伴角色 | 不加 | 一个会说话的角色，点了才说 |
| 概念关系图 | 概念多时加 | 全课概念怎么连；和概念卡、图鉴共用一份数据 |
| 术语悬停 / 术语表 / 闪卡 | 术语多时加 | 一份术语数据三处用 |
| 声音 | 不加 | 默认静音的短音效 |
| 学习路径 | 读者起点差别大时加 | 几条路线，点一条其余变暗 |
| 小镇式目录 | 只在有离线出图的皮肤 | 一张地图 = 全课进度 + 本章目录 |
| 大事年表 | 历史分量大时加 | 全课发明故事按年份串起 |
| 读者换配色 | 必做 | 亮 / 暗 / 护眼，属皮肤契约 |

---

## 一、阅读激励

**什么时候值得加**：读者年纪小、课程长、需要一点"往下读"的动力；有世界观的皮肤（爬塔、关卡）最自然。严肃的成人课可以不加。

**只奖励"读懂了"**：

| 触发（读懂的证据） | 记录键 |
|---|---|
| "试试看"完成（JS 判定） | `<课程id>-try`（kit） |
| 本章测验全对 | `<课程id>-progress`（kit）；徽章另存，键见 kit/README.md 第八节 |
| 篇末综合关每回合答对 / 通关 | 见 kit/README.md 第八节 |
| 测验连对 3 题（可选，小庆祝，不存） | — |

**明确不做**：滚动百分比触发（反例：DS 读到 92% 记"读过"、98.5% 放彩纸 + 塔顶亮灯）、停留时长触发（反例：DS 概念卡停 1.5s 纸飞机飞向背包）、分数排行、血条、失败结局、连续打卡。

**通用内核 × 各皮肤外观**

| 内核 | 做什么 | 笔记本 | 纸片（爬塔 / 戏台） | 像素（GB / FC） | 小镇 |
|---|---|---|---|---|---|
| 单元徽章 | 每章一件代表本章概念的东西，点开可复习释义 | 邮票，贴进集邮册 | 道具收进背包 / 戏台道具箱 | 卡带、奖杯 | 镇上新盖一栋楼 |
| 子概念小卡 | 每个子概念一张，集齐一组有庆祝 | 图鉴页上一格 | 小物件进收藏册 | 金币、物品格 | 楼里一件家具 |
| 进度点亮 | 全课地图上读懂的章亮起 | 目录页盖章 | 塔窗亮灯 / 戏单打勾 | ★ + 章节方块变绿 | 楼从脚手架变成盖好 |
| 任务打钩 | 试试看完成 | 便签打勾 | 便签白勾 + 纸屑 | CLEAR! | 黏土珠变绿 |
| 未得剪影 | 还没得的显示剪影 + "读懂第 N 章就能拿到" | 空邮票框 | 灰剪影 + "？" | 问号砖 | 空地基 |
| 下一步推荐 | 指向第一个还没读懂的章 | 书签 | 小旗"接着爬" | 闪烁的关卡入口 | 路牌 |
| 完成仪式 | 读懂一章时一次 | 盖章"读懂了" | 守层者碎裂 / 谢幕 | STAGE CLEAR + 烟花 | 小旗升起 |

**怎么做**
- 组件只派事件（kit 现有：`vl:try {id, el, first}`、`vl:quiz-perfect {ch, firstTry, n}`、`vl:answer {i, firstTry}`；篇末综合关的回合事件见 kit/README.md 第七节），激励模块订阅、记录、播外观，只在 `first` 时给奖励。组件里不写奖励逻辑。
- 徽章数据和概念关系图、概念卡共用一份概念数据（见第三节），徽章的释义就是概念卡的"通俗地说"。
- 收藏处是对话框：Tab 走格子、←→ 翻页、Esc 关；每件可展开释义（`aria-expanded`）。
- 动效按"阅读激励"类：一次 ≤1.2s，off 档不播但照样记录。

**坑**
- 激励外观抢正文：庆祝层盖住正文超过 1.2s，或每个小操作都放纸屑。只在读懂一处时放一次。
- "读过"和"读懂"混用：顶栏进度、目录页亮灯都只由测验全对决定（三课里 GD、AI 已是，DS 要改）。
- 徽章画成和概念无关的装饰物：每件东西要能让人想起那个概念（DS 背包 16 件道具各对应一章概念）。

## 二、陪伴角色

**什么时候值得加**：皮肤有世界观（爬塔的勇士、AI 课的小比特），或读者年纪小。默认不加。现有课程保留：AI 小比特是全课贯穿线索；DS 勇士用户很喜欢（"点击勇士可以让它说话，让页面更有趣"）。

**两种形式**
1. 正文对话框：作者写的台词，静态，随正文出现（AI `.npc`，56 处）。
2. 点击会说话的角色：固定在页边或进度条上（DS 勇士）。

**规则**

| 规则 | 做法 |
|---|---|
| 点击才说话 | 主动冒话只在少数关键时刻（试试看完成、通关），每章 ≤3 次 |
| 台词随内容 | 每节 `data-lines` 写 1–3 句，按当前节取；这一节没写就不说话，不拿通用台词凑 |
| 可关 | 顶栏开关，和动效、声音并列，存档 |
| 键盘可触发 | 角色是 `button`，有可读名称（"勇士，点一下听它说话"）；Enter / 空格触发；气泡 `aria-live=polite` |
| 语气平常 | 像一个一起读书的同伴：疑问、犯错、发现、情绪时出场；不卖萌、不神神叨叨、不替作者念定义、不说答案 |
| 不挡正文 | 气泡 `pointer-events:none`、不遮正文、滚动即收、约 2.6s 消失 |
| 当贯穿线索时 | 角色的成长写进项目文档（content-rules.md 一B ②） |

台词示例（同一节"选择偏差"）：✓"原来我只在岸边撒网，难怪全是黄鱼。"；✗"勇者大人，数据的迷雾正笼罩着我们！"；✗"选择偏差是指样本在收集前被筛选的现象。"（这是在念定义）

**DS 勇士现状的缺口**

| 缺口 | 现状 | 要改成 |
|---|---|---|
| 台词与内容无关 | 8 句通用台词轮换；`data-hero-lines` 0 章在用 | 每节 `data-lines` |
| 不能键盘触发 | 角色 `aria-hidden`、不可聚焦 | `button` + 可读名称 |
| 没有关闭开关 | 只能随动效档位 | 顶栏独立开关 |
| 沿台阶走 | 跟着滚动走（位置显示，可保留） | 不能因此触发任何奖励 |

## 三、概念关系图

**什么时候值得加**：概念多（>40）、彼此牵连、有先修关系。GD（110 个概念）、AI 都有 `map.html`。

**一份概念数据，三处用**：

```js
// 示意。现行写法：课程的 js/concepts.js 写 window.VL_CONCEPTS = {items, links, terms}，
// 由 kit/modules/vl-concepts.js 读成 VL.concepts；字段见 kit/README.md 第八节
VL.concepts = [
  { id:'core-loop', ch:2, zh:'核心循环', en:'Core loop',
    def:'玩家一遍遍重复的那组动作……',    // = 概念卡"通俗地说" = 徽章释义
    illus:'cc-core-loop',                 // = 概念卡图位 = 图鉴里的小图
    links:[{to:'flow', type:'explains'}, {to:'feedback', type:'prereq'}] }
];
```

| 用在哪 | 取哪些字段 |
|---|---|
| 概念卡 K1 | zh、en、def、illus（卡片 HTML 可由数据生成，避免两处不一致） |
| 关系图 `map.html` | 全部；边类型：先修、解释、应用、对照 |
| 章末"相关章节" N5 | links 推出的章节 |
| 图鉴 / 背包（激励） | zh、def、illus |
| 术语表 | 可合并进术语数据 |

**怎么做**：节点 = 概念名 + 章号；点节点亮它的邻居、旁边显示 def 和"去第 N 章"；按篇着色并加文字图例；世界观原理也登记成节点（content-rules.md 一D）。

**坑**
- 节点不能键盘操作（反例：GD `map.html` 节点无 tabindex）：每个节点 `tabindex=0`，Enter 选中，方向键在邻居间走。
- 手机横滚（反例：GD `#gsvg{min-width:900px}`）：窄屏改成按篇分组的列表 + 点开看邻居。
- 力导向布局乱成一团：节点 >60 时按篇分区排，不纯靠自动布局。
- 未开放的章节的概念不进图，或显示为灰色且不可跳。

## 四、术语悬停、术语表、闪卡

**什么时候值得加**：术语多、读者零基础时三件一起加；一份数据三处用。

| 件 | 做法 | 坑 |
|---|---|---|
| 悬停释义 | 正文 `.vl-term[data-def]`（`components.md` K7）；JS 释义框夹在视口内 | 纯 CSS `::after` 在屏幕边缘出屏（GD / AI 旧版） |
| 术语表 `glossary.html` | `tools/build_glossary.py` 从各章 `data-def` 汇出；按拼音 / 字母排；每条链回首次出现的章 | 同一术语多处定义不一致：脚本报冲突，以首次出现处为准 |
| 闪卡 `flashcards.html` | 莱特纳 4 盒：答对进下一盒、答错回第一盒；只出已读懂章的术语 | 不能键盘翻面（GD 旧版）：空格翻面、←→ 判对错；去掉 emoji（AI 旧版仍有） |

英文版三件都要有英文字段；存档键两种语言共用。

## 五、声音

**什么时候值得加**：游戏化皮肤（像素、爬塔）、低龄读者。默认不加；加了也**默认静音**。

**怎么做**
- 顶栏一个喇叭开关，存档（`<课程id>-sound`）；WebAudio 合成短音，不带外部音频文件。代码 `kit/modules/sound.js`，`modules.sound:false` 时整个模块不出现，见 kit/README.md 第八节。
- 音色归皮肤：皮肤 CSS 写 `:root{--vl-snd:paper|sine|square|triangle}`；像素 = 方波 8-bit；纸片 = 正弦短音；笔记本 = paper（铅笔 / 纸声；notebook 的 skin.css 还没写这个变量，现在退回 sine）。
- 教学用声音（GD `ch12` 试听台）属于互动本身，同样默认静音、可关。

**坑**：GD `ch12` 静音复选框默认不勾，等于默认有声——要改成默认勾上。音效跟着每次滚动响会很烦，只跟操作和读懂事件。

## 六、学习路径

**什么时候值得加**：读者起点差别大、章数多（>20）。

**怎么做**：目录页 2–5 条路线（如"一周入门""完整路线""底层原理路线"），每条 = 名字 + 一句"适合谁" + 章号列表；点一条，其余章变暗、路线上的章连线；路线数据写在课程 `js/course.js` 的 `VL_COURSE.paths`（`{name, who, chs}`，vl.js 不读，目录页读；`starter/index.html` 已做好"点一条其余变暗"）。正例：GD 5 条、DS 快速路线、AI 浮条。

**坑**：路线跳过了后面章要用的先修概念——每条路线都要过一遍"每章用到的概念前面讲过"检查。

## 七、小镇式目录（及其他"目录即地图"）

**什么时候值得加**：皮肤本身就是一张地图（小镇、塔、关卡路线），且有离线出图的流水线。

**怎么做**：一张地图三合一——全课地图、累计进度（读懂的章"盖好"）、本章目录（点建筑跳到对应小节）。正例：AI W4 `js/w4-town.js` + `tools/render-town.mjs` 离线渲染透明 PNG，章节页不跑 three.js。

**坑**
- 替代了 N4 浮钮后，窄屏行为要单独测（AI W4 未测）。
- 键盘：地图上每个建筑是 `button`，Tab 可达，有文字名。
- 章节插画要和地图同一套画法（AI W4 章插画仍是像素，和小镇渲染不一致）。

## 八、大事年表

**什么时候值得加**：历史分量大、发明故事多的课。

**怎么做**：全课发明故事按年份串起，按类型筛，点事件跳到对应章节的故事框（正例：AI `timeline.html` + `js/timeline.js`）。事件数据从各章 K10 / T5 汇出，不另写一份。

**坑**：年表上的年份、人名要和章内一致——从同一份数据生成。

## 九、读者换配色

不是可选项，是皮肤契约的一部分（`skin-contract.md`）：每套皮肤给亮 / 暗 / 护眼三套配色，顶栏"显示"里切换，存档（键 `vl-scheme`，跨课共用）。**皮肤在开课时定，读者只换配色**，因为插画是按皮肤画法画的，运行时换不了画法。
