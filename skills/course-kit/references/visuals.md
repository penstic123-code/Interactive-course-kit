# 配图

用途：一章该配哪种图、真实图片从哪找和怎么登记、插画画法的坑、怎么查配图密度。人物规范、真实图片的授权底线在 `references/content-rules.md` 第二节，这里不重复，只补做法和常见的坑。按"这一段在干什么"选视觉的总表在 `SKILL.md` 第一节。

## 一、配图种类

| 种类 | 用途 | 来源 / 做法 | 组件 |
|---|---|---|---|
| 场景插画 | 抛出处境、给例子和反例画面；节首节尾的"有温度的图" | 插图库绘制工具按皮肤画 | T1、E1 |
| 机制图解 | 讲清一个结构：循环、嵌套、因果、对比、分类 | `VL.diagram.*`（12 种，见 `diagrams.md`）；模板画不了的才手写 SVG | T3 |
| 数据图表 | 真实或示意的数据：柱、线、分布 | 柱线图用 `VL.plot`（G11）；散点等它画不了的手写 SVG 放进 `figure.vl-fig`；边缘笔直；示意数据标"示意" | T3、G11 |
| 活图 | "改一个数会怎样" | 滑块 `label.vl-ctl`（见 kit/README.md 第三节“互动台与控件”）+ `VL.plot` 的 `p.set(…)` 重画；天平类可直接用 `VL.diagram.balance` 的 `slider` | G2、G11 |
| 带图时间线 | 发明故事的 3–5 个节点 | 每节点一张插画或真实图片；放在发明故事框里收起 | T5、K10 |
| 真实图片 | 历史人物、实物、地点、原始文献，让读者相信"这真发生过" | Wikimedia Commons 等（见第二节） | T4 |
| 概念图标 | 概念卡、并列卡阵里的小图，画出概念的要素 | 插图库小图（≤240px），不用 emoji | K1、K2 |
| 漫画格 | 一段过程或故事，替代"框里超过 2 段" | 2–4 格插画 + 短旁白 | T6 |
| 对比图 | 正反、前后，只差一处 | 两张同构图插画或图解 | E2 |
| 文档道具 | 把一段叙事做成一件东西（报纸、信、案卷） | HTML + 皮肤材质（`.vl-doc`，见 kit/README.md 第七节） | K9 |
| 大数字 | 一个惊人的数 | 候补组件 `.bignum`，一章一个就够，多了就不惊人 | 候补 |
| 关系图 | 全课概念怎么连 | `map.html` + 概念数据（见 `modules.md`） | 模块 |

**选图顺序**：讲真人真事先找真实图片（用户希望多用）；讲结构用图解；讲处境和例子用插画；要读者感受变化用活图。插画不代替能找到的真实照片（斯诺的地图就该用原图，不该重画）。

## 二、真实图片：找、下、核、注、登

### 1 去哪找

| 来源 | 适合 | 授权通常是 |
|---|---|---|
| Wikimedia Commons | 历史人物、名画、地图、实物、论文插图 | 每张不同，逐张核 |
| NASA / JPL | 天文、航天 | NASA 自产为公有领域；合成图可能另有 CC（AI `ch03` 谷神星图即如此） |
| 美国联邦政府作品（军方、国会图书馆、NOAA） | 二战、历史照片 | 公有领域（如 1952 年飞行员座舱照） |
| Wellcome Collection | 医学史 | CC BY 或公有领域 |
| Smithsonian Open Access | 实物、标本 | CC0 |

Commons 上搜英文关键词 + 年份最快；人物先找"File:人名.jpg"，再看 Category 页。

### 2 核授权
- 用 Commons API 读 `extmetadata`，不只看页面印象（在 `img/CREDITS.md` 开头写明"授权均在下载当天用 Commons API 核对"）：
  `https://commons.wikimedia.org/w/api.php?action=query&titles=File:John_Snow.jpg&prop=imageinfo&iiprop=url|extmetadata&iiurlwidth=1280&format=json`
  看 `LicenseShortName`、`Artist`、`Credit`、`AttributionRequired`。
- **能用**：公有领域、CC0、CC BY、CC BY-SA。**不用**：NC、ND、"合理使用"（fair use）、授权不明、只写"来自网络"的。
- 来源之间说法不一时，按更严的那个署名（如同一幅讽刺画，Commons 标公有领域、Wellcome 标 CC BY 4.0，图注就写上 Wellcome）。
- 拍摄的现代照片（博物馆展品、纪念物）授权属于摄影者，要单独核（如水泵复制品照片是 CC BY-SA 4.0，必须署名摄影者）。

### 3 下载与存放
- 下 Commons 生成的缩略图，宽 960–1280px（人像 640–960px），不下几十 MB 的原图；单张 ≤600KB。
- 存 `img/chNN/英文短横线名.jpg`（`snow-map-1854.jpg`），不外链。
- 缩小、裁剪、去透明底都算改动：CC BY-SA 的要在登记表里写"已缩小 / 已裁剪"，并按相同方式共享。

### 4 图注
- 格式：一句说明这张图让读者看什么 + `.vl-src`（作者，年份，授权，来源）。
  ✓"斯诺把每户死亡画成一道黑杠，黑杠全挤在宽街水泵周围。〔John Snow, 1855，公有领域，Wikimedia Commons〕"
- CC BY / BY-SA 必须写作者和授权名；公有领域建议也写作者和来源。
- 解释写进正文，图注不超过两行（图注长会让图文两栏留大片空白）。

### 5 登记
每张一行，写进课程项目文档的"图片来源清单"（`starter/项目规则与经验.template.md` 第八节已留好这张表；图多时整表移到 `img/CREDITS.md`，项目文档只留链接），用下面六列：

| 文件 | 内容 | 作者 / 来源 | 授权 | 来源页 URL | 署名要求 |
|---|---|---|---|---|---|
| img/ch01/snow-map-1854.jpg | 斯诺霍乱地图，1280px 缩略图 | John Snow，1855 | 公有领域 | https://commons.wikimedia.org/wiki/File:Snow-cholera-map-1.jpg | 无强制；建议署名 |

查不到授权就不用，换成插画或删掉；登记表里没有的图不许出现在页面上。

## 三、插画画法的坑

通则（人物靠服饰区分、脚落地、手握物、文字不压图、逐张截图）见 content-rules.md 第二节。下面是补充：

| 坑 | 改法 |
|---|---|
| 给每人加不同颜色上衣色块，结果像"一块透明色块"，和线条风格不协调 | 笔记本皮肤靠帽子、发型、配饰区分，不用衣服色块；同一幅图里由绘图函数按顺序自动换装 |
| 帽子压住眼睛、胡子盖住嘴 | 帽子抬高、胡子下移，写进绘图函数 |
| 小人缩小后嘴像胡子 | 嘴用深红，不用墨色 |
| 戴眼镜的小人像戴面罩、看不见眼睛 | 像素人不画眼镜（陪伴角色的标志性眼镜例外） |
| 拿东西的手和物件分开画，东西离手 | `arms:"hold"` 配 `kit.holding(x, y, opts, 物件)`；自画物件用 `kit.hands(x, y, opts)` 取两手坐标 |
| 机器人手臂紧贴身体、僵直 | 手臂离开身体、带一点外角 |
| 坐着没有椅子、屏幕或书悬空 | 坐姿自动配椅子，写进函数比事后逐张改省事 |
| 手臂朝画面外而不是对象；捂耳朵画成捂眼睛；该躲在石头后却站在前面；动作和说明对不上 | 只能人眼查：把全部插图排开逐张看（skill 里没有现成的全课图库页；可以仿 `skins/notebook/gallery.html` 写一页，引入各章插图包，遍历 `VL.illus.lib` 逐个画出并标图名和 alt） |
| 人物和望远镜等物件重叠 | `tools/illus-overlap.mjs` 查重叠 |
| 文字压在形状边框上、挤在线旁、比框还宽 | 文字离线 ≥4px，嵌套图用引线 + 外部标签（`diagrams.md`）；`tools/qa.mjs` 的碰撞检查 |
| 气泡尾巴指向空处 | `kit.bubble(x, y, w, h, [尾尖x, 尾尖y])` 尾尖对准说话人 |
| 镜像人物时字也翻了 | `look:-1`（或 `flip`）只镜像四肢；字放在 `VL.illus.add` 的文字层，不随人物翻 |
| 题头小窗里天空太深，像一个黑洞 | 小尺寸里的大色块调浅一档，截图看缩略效果 |
| 插画是"白底小人加标签"，显得廉价 | 插画有场景、地面和光影（站在哪、什么时候），不是白底上的孤立小人 |
| 反例图和正例图看不出差别 | 反例画出缺的那一项或错在哪（缺腿的桌子、空掉的格子），并加文字签 |

**画插画前先问**：这张图画出了什么"为什么"？如果答案是"让页面不那么空"，换成能说明机制的图，或者不画。

**检查**：每张插画用 `node <skill>/tools/shot.mjs <html绝对路径> <out.png> "选择器@序号" 1100` 截单元素放大看（人物重叠用 `tools/illus-overlap.mjs` 辅助）；一个检查员管 3–5 章，按"没手没腿、悬空、朝向、文字压线"清单逐张过。

## 四、配图密度检查

`SKILL.md` 第一节节奏规则 1：不留文字墙，两个视觉之间的正文不超过约 220 字，单段不超过约 160 字，框里的文字也算（这两个数是检查脚本的阈值，脚本报错，不放宽）。检查方法：

1. **自动扫**：`node <skill>/tools/check.mjs <课程绝对路径> --fast` 的第 3 步。它按源码顺序扫 `<main>`，累加正文字数（框里的文字也算；英文按词数 × 1.5 折成字），遇到视觉清零，两个视觉之间超过 220 字就报；单个 `<p>` 超过 160 字也报。算作视觉的：`img svg canvas figure video iframe` 标签、`data-illus`、`data-diagram`、类名 `vl-board vl-dg vl-fig vl-eg vl-cc-fig vl-illus vl-photo vl-comic vl-plot`，以及小互动 `vl-guess vl-flip vl-philo vl-hot`（先猜后揭晓、翻牌、立场卡、热区）。默认收起的 `details`（发明故事框、支线）不计入，脚本跳过它们；但展开后的内文同样要满足“框也算正文”，靠截图展开后人眼查。脚本生成的内容（页面 JS 里拼的 HTML）它看不到，那部分靠截图人眼看。
2. **搭配**：数一章里图解、插画 / 照片 / 例子、互动各几个，由内容定，不设固定比例（数学多的课图解多，历史多的课照片多）；看有没有哪一类缺位或扎堆。
3. **相邻**：列出视觉序列，查有没有两张静态图解紧挨着（中间要隔插画、例子或互动）。
4. **重复**：全课 grep `data-illus="…"` 和 `img src`，同一个名字出现两次就是重复用图。
5. **温度**：每节开头、结尾的视觉宜是插画、照片或例子，而不是图解（审美偏好）。
6. **人眼**：420px 和 1100px 各截一张整页，缩小到一屏看"文字墙"在哪里。
