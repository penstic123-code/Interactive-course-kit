# 配图

用途：一章该配哪种图、真实图片从哪找和怎么登记、插画画法的坑、怎么查配图密度。人物规范、真实图片的授权底线在`references/content-rules.md` 第二节，这里不重复，只补做法和三门课踩过的坑。按"这一段在干什么"选视觉的总表在 `SKILL.md` 第一节。

## 一、配图种类

| 种类 | 用途 | 来源 / 做法 | 组件 | 正例 |
|---|---|---|---|---|
| 场景插画 | 抛出处境、给例子和反例画面；节首节尾的"有温度的图" | 插图库绘制工具按皮肤画 | T1、E1 | DS `ch05-luck-and-skill.html` 的例子插画（`ch05-eg-exam`、`ch05-eg-rookie`） |
| 机制图解 | 讲清一个结构：循环、嵌套、因果、对比、分类 | `VL.diagram.*`（12 种，见 `diagrams.md`）；模板画不了的才手写 SVG | T3 | GD `ch02-core-loop.html` 三层循环 |
| 数据图表 | 真实或示意的数据：柱、线、散点、分布 | 手写 SVG 放进 `figure.vl-fig`（共享绘图函数 `VL.plot()` kit 里暂无）；边缘笔直；示意数据标"示意" | T3 | DS `ch01-cholera.html` 两家水公司死亡率柱图 |
| 活图 | "改一个数会怎样" | 滑块 `label.vl-ctl` + 页内重画的 SVG（见 kit/README.md 第三节“互动台与控件”）；天平类可直接用 `VL.diagram.balance` 的 `slider` | G2 | AI `ch08-classic-algorithms.html` sigmoid 活图 |
| 带图时间线 | 发明故事的 3–5 个节点 | 每节点一张插画或真实图片；放在发明故事框里收起 | T5、K10 | GD `ch24-case-mario.html` 1-1 教学时间线 |
| 真实图片 | 历史人物、实物、地点、原始文献，让读者相信"这真发生过" | Wikimedia Commons 等（见第二节） | T4 | DS `ch01-cholera.html` 斯诺地图、肖像、水泵 |
| 概念图标 | 概念卡、并列卡阵里的小图，画出概念的要素 | 插图库小图（≤240px），不用 emoji | K1、K2 | AI 概念道具全课不重复、回指复用 |
| 漫画格 | 一段过程或故事，替代"框里超过 2 段" | 2–4 格插画 + 短旁白 | T6 | AI `ch02-rules-vs-learning.html` 的 `.comic`（全课仅此 1 处，可多用） |
| 对比图 | 正反、前后，只差一处 | 两张同构图插画或图解 | E2 | GD `ch07-game-feel.html` 有无反馈的方块 |
| 文档道具 | 把一段叙事做成一件东西（报纸、信、案卷） | HTML + 皮肤材质（`.vl-doc`，见 kit/README.md 第七节） | K9 | AI `ch10-perceptron.html` 报纸 |
| 大数字 | 一个惊人的数 | 候补组件 `.bignum`，每章 ≤1 | 候补 | AI `.bignum` |
| 关系图 | 全课概念怎么连 | `map.html` + 概念数据（见 `modules.md`） | 模块 | GD / AI `map.html` |

**选图顺序**：讲真人真事先找真实图片（用户希望多用）；讲结构用图解；讲处境和例子用插画；要读者感受变化用活图。插画不代替能找到的真实照片（斯诺的地图就该用原图，不该重画）。

## 二、真实图片：找、下、核、注、登

### 1 去哪找

| 来源 | 适合 | 授权通常是 |
|---|---|---|
| Wikimedia Commons | 历史人物、名画、地图、实物、论文插图 | 每张不同，逐张核 |
| NASA / JPL | 天文、航天 | NASA 自产为公有领域；合成图可能另有 CC（AI `ch03` 谷神星图即如此） |
| 美国联邦政府作品（军方、国会图书馆、NOAA） | 二战、历史照片 | 公有领域（DS `ch03` 1952 年飞行员座舱照） |
| Wellcome Collection | 医学史 | CC BY 或公有领域 |
| Smithsonian Open Access | 实物、标本 | CC0 |

Commons 上搜英文关键词 + 年份最快；人物先找"File:人名.jpg"，再看 Category 页。

### 2 核授权
- 用 Commons API 读 `extmetadata`，不只看页面印象（正例：DS `img/CREDITS.md` 开头写明"授权均在下载当天用 Commons API 核对"）：
  `https://commons.wikimedia.org/w/api.php?action=query&titles=File:John_Snow.jpg&prop=imageinfo&iiprop=url|extmetadata&iiurlwidth=1280&format=json`
  看 `LicenseShortName`、`Artist`、`Credit`、`AttributionRequired`。
- **能用**：公有领域、CC0、CC BY、CC BY-SA。**不用**：NC、ND、"合理使用"（fair use）、授权不明、只写"来自网络"的。
- 来源之间说法不一时，按更严的那个署名（DS `ch01` 讽刺画：Commons 标公有领域，Wellcome 标 CC BY 4.0，图注顺手写上 Wellcome）。
- 拍摄的现代照片（博物馆展品、纪念物）授权属于摄影者，要单独核（DS `ch01` 水泵复制品照片是 CC BY-SA 4.0，必须署名 Jamzze）。

### 3 下载与存放
- 下 Commons 生成的缩略图，宽 960–1280px（人像 640–960px），不下几十 MB 的原图；单张 ≤600KB。
- 存 `img/chNN/英文短横线名.jpg`（`snow-map-1854.jpg`），不外链。
- 缩小、裁剪、去透明底都算改动：CC BY-SA 的要在登记表里写"已缩小 / 已裁剪"，并按相同方式共享。

### 4 图注
- 格式：一句说明这张图让读者看什么 + `.vl-src`（作者，年份，授权，来源）。
  ✓"斯诺把每户死亡画成一道黑杠，黑杠全挤在宽街水泵周围。〔John Snow, 1855，公有领域，Wikimedia Commons〕"
- CC BY / BY-SA 必须写作者和授权名；公有领域建议也写作者和来源。
- 解释写进正文，图注不超过两行（DS 用户反馈：图注长会让图文两栏留大片空白）。

### 5 登记
每张一行，写进课程项目文档的"图片来源清单"（`starter/项目规则与经验.template.md` 第八节已留好这张表；图多时整表移到 `img/CREDITS.md`，项目文档只留链接）。DS 的六列最全，照抄：

| 文件 | 内容 | 作者 / 来源 | 授权 | 来源页 URL | 署名要求 |
|---|---|---|---|---|---|
| img/ch01/snow-map-1854.jpg | 斯诺霍乱地图，1280px 缩略图 | John Snow，1855 | 公有领域 | https://commons.wikimedia.org/wiki/File:Snow-cholera-map-1.jpg | 无强制；建议署名 |

查不到授权就不用，换成插画或删掉；登记表里没有的图不许出现在页面上。

## 三、插画画法：三门课踩过的坑

通则（人物靠服饰区分、脚落地、手握物、文字不压图、逐张截图）见 content-rules.md 第二节。下面是补充：

| 坑 | 出在哪 | 改法 |
|---|---|---|
| 给每人加不同颜色上衣色块，结果像"一块透明色块"，和线条风格不协调 | GD 火柴人 | 笔记本皮肤靠帽子、发型、配饰区分，不用衣服色块；同一幅图里由绘图函数按顺序自动换装 |
| 帽子压住眼睛、胡子盖住嘴 | GD | 帽子抬高、胡子下移，写进绘图函数 |
| 小人缩小后嘴像胡子 | AI 像素 | 嘴用深红，不用墨色 |
| 戴眼镜的小人像戴面罩、看不见眼睛 | AI 像素 | 像素人不画眼镜（陪伴角色的标志性眼镜例外） |
| 拿东西的手和物件分开画，东西离手 | AI | `arms:"hold"` 配 `kit.holding(x, y, opts, 物件)`；自画物件用 `kit.hands(x, y, opts)` 取两手坐标 |
| 机器人手臂紧贴身体、僵直 | AI | 手臂离开身体、带一点外角 |
| 坐着没有椅子、屏幕或书悬空 | GD | 坐姿自动配椅子，写进函数比事后逐张改省事 |
| 手臂朝画面外而不是对象；捂耳朵画成捂眼睛；该躲在石头后却站在前面；动作和说明对不上 | GD | 只能人眼查：把全部插图排开逐张看（skill 里没有现成的全课图库页；可以仿 `skins/notebook/gallery.html` 写一页，引入各章插图包，遍历 `VL.illus.lib` 逐个画出并标图名和 alt） |
| 人物和望远镜等物件重叠 | AI | `tools/illus-overlap.mjs` 查重叠 |
| 文字压在形状边框上、挤在线旁、比框还宽 | GD（同心椭圆、嵌套图最多） | 文字离线 ≥4px，嵌套图用引线 + 外部标签（`diagrams.md`）；`tools/qa.mjs` 的碰撞检查 |
| 气泡尾巴指向空处 | 三课 | `kit.bubble(x, y, w, h, [尾尖x, 尾尖y])` 尾尖对准说话人 |
| 镜像人物时字也翻了 | AI | `look:-1`（或 `flip`）只镜像四肢；字放在 `VL.illus.add` 的文字层，不随人物翻 |
| 题头小窗里天空太深，像一个黑洞 | DS 第 3 篇 | 小尺寸里的大色块调浅一档，截图看缩略效果 |
| 插画是"白底小人加标签"，显得廉价 | 三课早期 | 插画有场景、地面和光影（站在哪、什么时候），不是白底上的孤立小人 |
| 同一页混两套画法（像素插画配离线渲染小镇） | AI W4 | 一页只用一套画法；皮肤的绘制工具没做完就先别开这一皮肤的章 |
| 反例图和正例图看不出差别 | GD 早期 | 反例画出缺的那一项或错在哪（缺腿的桌子、空掉的格子），并加文字签 |
| 用户第一轮就抱怨浅灰小字 | GD | 图中次要文字也 ≥4.5:1 |

**画插画前先问**：这张图画出了什么"为什么"？如果答案是"让页面不那么空"，换成能说明机制的图，或者不画。

**检查**：每张插画用 `node <skill>/tools/shot.mjs <html绝对路径> <out.png> "选择器@序号" 1100` 截单元素放大看（人物重叠用 `tools/illus-overlap.mjs` 辅助）；一个检查员管 3–5 章，按"没手没腿、悬空、朝向、文字压线"清单逐张过（GD 经验：一次能修掉约一半问题）。

## 四、配图密度检查

`SKILL.md` 规定：每 1–2 段正文就有一个视觉，两个视觉之间的正文不超过约 300 字，框里的文字也算。检查方法：

1. **自动扫**：`node <skill>/tools/check.mjs <课程绝对路径> --fast` 的第 3 步。它按源码顺序扫 `<main>`，累加正文字数（框里的文字也算；英文按词数 × 1.5 折成字），遇到视觉清零，两个视觉之间超过 300 字就报。算作视觉的：`img svg canvas figure video iframe` 标签、`data-illus`、`data-diagram`、类名 `vl-board vl-dg vl-fig vl-eg vl-cc-fig vl-illus vl-photo vl-comic`。默认收起的 `details`（发明故事框、支线）不计入，脚本跳过它们；但展开后的内文同样要满足“框也算正文”，靠截图展开后人眼查。脚本生成的内容（页面 JS 里拼的 HTML）它看不到，那部分靠截图人眼看。
2. **配比**：数一章里图解、插画 / 照片 / 例子、互动各几个，大致 1/3 : 1/2 : 其余（数学多的课图解多，历史多的课照片多）。
3. **相邻**：列出视觉序列，查有没有两张静态图解紧挨着（中间要隔插画、例子或互动）。
4. **重复**：全课 grep `data-illus="…"` 和 `img src`，同一个名字出现两次就是重复用图。
5. **温度**：每节开头、结尾的视觉是不是插画、照片或例子，而不是图解。
6. **人眼**：420px 和 1100px 各截一张整页，缩小到一屏看"文字墙"在哪里。
