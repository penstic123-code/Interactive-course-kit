# 互动学习网页课程：内容规范

用途：互动学习网页课程的内容规范（讲什么、讲到多深、一章和全课的验收标准、工作流）。课程专属的规则和数字写在各课程文件夹的 `项目规则与经验.md`（由 `starter/` 生成）。可以整份复制到你的项目里当 `content-rules.md` 用。

用来制作**任意领域**的互动学习网页课程：每门课一个文件夹。
读者：想系统学会一个领域的普通人。不假设基础，但讲到真正的深度，**读起来有趣、读得懂**。

- 第一至九节是与风格无关的通用规范；第十节讲选风格与通用美学，具体样式由每门课的风格决定。
- 下文的"章"指课程的学习单元，也可以是关卡、课时或课程自定的单位。规矩分三档：**原则**（说明保护什么，给默认做法，可以不照做时在章纲里写明理由；只有事实准确、术语先讲后用、故事不顶替概念名三条是硬规则）、**可选做法**（有合适的内容才做）、**技术底线**（无障碍、检查脚本的报错线，不动；字数阈值里只有"连着 500 字以上没有视觉"这条报错线是硬的，360 / 220 字只提示，由人判断）。文中的数字、结构顺序、文件命名都是**默认值和参考值**，数字后面写着它保护什么；这门课用不着就改，改了写进项目文档。
- 正文文风统一用 `zh-teaching-prose` skill（古典风格 + 非虚构写作），本文件不重复它的细则。
- 视觉、组件、版式、配图、交互、动效、皮肤和一键检查见 course-kit 的 `SKILL.md`，本文件不重复。
- 工具在 course-kit 的 `tools/`：`check.mjs` 一键检查（规则见 `SKILL.md` 第七节）、`qa.mjs` 自动点击测试、`shot.mjs` 整页/单元素截图、`readable.py` 读者视图、`illus-overlap.mjs` 插画重叠检查；浏览器由 `browser.mjs` 自动找（Edge 或 Chrome，或用环境变量 `EDGE_PATH` 指定）。

## 一、内容原则（最重要）

前八条是**原则**：决定读者能不能懂，每条写明保护什么，给默认做法，做法灵活，可以不照做时在章纲里写明理由；动笔前写进章纲（第四节），写完由审读检查（第八节）。其中"术语先讲后用"（第 2 条）是硬规则。后四条管内容是否完整、准确，第 11 条（事实准确）也是硬规则。

1. **一章一个问题，一节回答一个由上一节逼出来的问题。** 为什么：读者要把新东西挂到一个已经在等答案的空位上，没有问题的答案只能硬记。问题链是规划和审读的工具：章纲里每节写一行"此刻的问题 → 答案 → 留下的问题"，问题只用读者此刻已有的词写；正文不必每节开头都摆出一个问句（避免"那么问题来了"式的套路），衔接靠上一节真留下了东西、下一节接住它，遮住小标题也能顺着读下去。一章也可以是围绕一个主题的巡礼（历史、案例），此时"问题"可以很宽。每节开头一两句之内，读者就该知道这一节在回答什么；可以用一个处境开头，处境默认只占一两句，不铺垫成一小段（这一节本身就是在讲一个故事或案例时，场景可以长，但第一句就要让读者知道为什么讲它）。
   ✓ "四要素说明游戏由什么构成，没说它为什么让人快乐"，接着讲游戏为什么让人快乐。
   ✗ 节末留了问题，下一节却换去讲另一件读者还没想问的事。
   ✗ 一节先铺四五句场景，读到第三段才知道它要回答什么。
2. **先有经验，后给名字。** 为什么：名字是给读者已经抓住的东西贴的标签，没有经验先给名字，读者只存下一个空词。每个新概念依次走：麻烦 → 读者亲身碰到（场景、手算或互动）→ 起名 → 说准 → 边界。互动可以就是那次经验（先玩定义检验器，再讲维特根斯坦）。互动标题、试试看、按钮、练习里不出现正文还没起名的**新**词；读者早就认识的名字（"AI""游戏"）可以先出现，规矩管的是新术语。这次经验要短：一屏之内，读者就该知道这章讲哪个概念——章名写出它（章名和小标题里的名字只是定位，不算起名；起名指正文里第一次用荧光笔标出、配概念卡），开场的场景、类比或任务只有几句话，紧接着给主概念起名并配概念卡；之后各节再把它拆开讲（是什么、有哪几部分、每部分为什么需要）。名字第一次出现之前，不放好几个互动，也不做长铺垫；概念必须先亲手算一次或玩一次才懂时，那一次就放在起名之前，同样要短，并让读者知道在找什么。
   ✗ 任务"把损失降到 0.5 以下"出现在"这个分数叫损失"之前。
   ✗ 三个互动做完，主概念才第一次起名；读者读了半页还不知道这章讲什么。
3. **一段一个新东西；要记住的数放进图表。** 为什么：工作记忆一次只握得住几样（约 4 个组块）。新术语、新符号、新运算、要记到下一句的数，各算一个"新东西"。默认的粒度跟着读者水平走：读者基础越好，一段可以多带一点；但默认不要在一段里同时放两个互相依赖、读者又都不熟的新东西（其中一个读者已经很熟时可以）。读者后面要用的数放在表、图或读数里，句子只指过去；手算一次亮一步。
   ✗ 一段里先算预测，再算误差，再平方，再解释为什么平方，再取平均：五样新东西挤在一起。
4. **先用稳，再往上盖。** 为什么：后一个概念建在前一个上，前一个还停在"刚听说"，读者就是在沙地上盖楼。被依赖的概念先让读者亲手用过一次（手算一步、一个小互动、一道判断），再讲依赖它的概念；读者早已熟悉的日常经验不必专门安排。做不到就拆章。
5. **篇幅跟着难度走。** 一章的预算按难度分估，不按概念个数（算法、警戒线和篇幅表见一A）；越过警戒线先考虑拆章，不拆就在章纲里写明理由。先修概念要么前面章节讲过（一句回指，读者容易忘的再加一张提醒图或表），要么在本章当新概念全额讲，不用一段压缩版带过。
6. **每个元素服务于理解或阅读体验。** 为什么：既不帮理解、也不帮阅读的元素抢注意力，读者还得猜它为什么在这里。章纲的元素表每行写：它回答问题链上的哪一问，或者它给阅读什么（密集文字后喘口气的插画、帮记忆的回顾、保持兴趣的小趣味），读者做什么或看什么，看完明白什么或感觉什么。两样都写不出的纯装饰就不做；元素数量由内容定，没有配额。
7. **用正例和反例划出概念的边界。** 为什么：只有一个例子，读者会把例子当成概念本身；反例或"差一点就对"的例子告诉他概念到哪里为止（作业有目标、有规则、有反馈，却缺"自愿"，所以不是游戏）。难度 ≥2 的核心概念至少有一个这样的反例或差一点，默认 ≥3 个具体例子，具体到能想象画面；难度 1 的概念一个例子即可。一个主例子可以贯穿全章、反复回指，新例子各说一件主例子说不了的事。来源随课程层次：入门课多取日常生活和本领域的现成处境；学术或数学较重的课，例子可以是学术的（经典例题、真实数据集、论文里的实验、典型考题式的题）。用哪类例子是各课的选择，写进项目文档。
8. **让读者知道自己懂没懂。** 为什么：读了不等于懂了，读者自己也分不清。难度 ≥2 的核心概念都要有一个读者自己用它、并得到反馈的时刻：试试看、一次预测、一道练习，不能只读；难度 1 的概念由章末练习兜住即可。可选的收尾：让读者把本章概念用到自己的事情上（"把一件普通的事设计成游戏，写下它的目标、规则、反馈"），这是检验迁移最直接的办法，配"你的思考"框。
9. **讲透一个核心概念，五层都要走到**（写完自检，不是节的顺序，也不是配额；小标题不挂层级标签）：
   - **是什么**：定义 + 直觉例子 + 示意图。
   - **为什么需要它**：解决了什么麻烦。有可靠历史时讲**发明故事**：站在学习者角度还原——当时遇到什么问题 → 之前的尝试为什么不行 → 关键洞察 → 怎样演化到今天，让读者觉得它**非发明不可**；读者能猜、猜了又能暴露一个错误直觉时，先让读者猜或试，再揭晓；配带插图的时间线或"问题→方案→新问题"演化图；正文留一两句关键洞察，完整故事放进默认收起的发明故事框。没有可靠历史就在正文讲它解决的痛点。
   - **为什么成立**：底层原理（心理学、数学、系统、物理……随领域而定），**标出处**（谁、哪本书或哪项研究）；读者能亲手验证、验证后真有收获时，配一个验证实验。难度 ≥2 的核心概念默认走这一层；确实没有可标出处的底层原理时（比如一种划分方式），讲清为什么这样划分、依据是什么，不硬凑出处。
   - **怎么用**：真实场景 + 互动与练习，读者亲手做一次（第 8 条）。
   - **边界**：局限、争议、常见误区（第 7 条的反例也算）。争议紧挨着被质疑的观点讲，章末误区节只放跨概念的误解；争议观点在需要处说一次"这是某某的观点"；有复制争议的研究如实说明。
   难度分 1 的概念讲到"是什么 + 为什么需要 + 一个例子"即可；次要概念不走全，其余收进支线。
10. **聚焦且成体系，覆盖全课**：每章围绕一个主题娓娓道来，从熟悉的处境出发一层层展开；先画整门课的知识地图（分篇、依赖、顺序）；先直觉和例子，再定义，再原理。全课覆盖：基础概念 → 底层原理 → 世界观知识 → 案例拆解 → 实战项目；定目录时列出"从业者每天会遇到什么"，对照查缺口。
11. **事实准确**：人名、年份、数字、引语不确定就联网核实（优先原论文、官方文档等原始来源；世界观原理的出处也在用之前核实）；查不到就删或改成保守说法；不编造数据；教学用示意模型标"示意"；数学与模拟要算对。
12. **只讲需要的，但讲透；历史与哲学穿插在每章，不单独成篇**：
    - **删除测试**：删掉这句，读者对核心概念的理解会变差吗？不会就删。时间线只留推动故事的节点（节点数见 `components.md` K4）；人名、版本、产品、参数举一两个代表；实现细节点到"为什么重要"为止。正文难度适中，讲到读者"懂了"就停，推导、数学、研究细节进默认收起的抽屉，深度留给想深入的读者。砍的是无关细节，不是解释：每个新概念、例子、故事都讲到零基础读者真正理解，宁可多写两三句讲透一个点，也不要五个点各写一句。核心概念的讲解留在正文：概念卡只是摘要，每个核心概念在正文里讲清它回答什么问题、边界在哪、配一个例子；理解它必需的话不收进抽屉，抽屉只放推导和延伸。
    - **历史**就是发明故事（见第 9 条），讲清"为什么非有不可"。
    - **哲学时刻**：每篇争取一个，挂在概念真的引出一个值得想的问题处（2–3 种立场并标明是谁的观点，不给标准答案，最后留一个开放问题）；确实没有这样的问题就不做，不为凑数硬加。

## 一A、单章验收清单

分三档。**原则**决定读者能不能懂，每章都查：表里是默认标准，可以不照做，但要在章纲里写明保护的东西怎么保住了；其中只有"术语先讲后用"（先经验后名字一行）是硬规则，另两条硬规则是事实准确（第一节第 11 条）和故事不顶替概念名（一C）。**可选做法**有合适的内容才做，做了就按标准做；**技术底线**每章都查，不动。表中数字是默认值，后面写着它保护什么；这门课用不着就改，改了写进项目文档。

**难度分**（章纲里给每个概念打一次分，相对于本课读者）：起点 1 = 给读者已有的经验起名或归类；2 = 要读者改一个旧想法（新区分、反直觉结论）；3 = 要读者搭一个会动的新模型（量的关系、因果链、迭代）。带新符号或公式 +1；依赖本章刚讲、还没用稳的概念 +1。前面章节讲过的先修计 0（处理方式见第一节第 5 条）；没讲过的就是本章的新概念，按全分计。这套算法刻意做得粗，是规划时的估计，不是硬上限：目的是让人在动笔前看见"这章装不下"，决定哪里拆章、哪里多给篇幅；警戒线 ≤8 读者审读后可以调；不为凑数字而硬塞或硬拆。

锚点：一章讲"什么是游戏"的四个生活概念（四要素 1、玩法分类 1、"家族相似"2、"游戏态度"2，加一个小练习）约 7 分，在预算内；一章同时讲梯度、斜率、学习率、局部最小值约 23 分，应拆成三章左右。

| 篇幅规则 | 默认值（保护什么） |
|---|---|
| 一章合计 | ≤8 分，约 40 分钟，作为警戒线（读者一次读完不过载）；入门短课可以 ≤6，读者审读后按卡点调整 |
| 重概念 | 单项 ≥3 分的概念一章最多 2 个（每个重概念要独占一节、含手算或互动） |
| 每分的篇幅 | 1 分：1–2 段 + 1 个视觉，几个 1 分概念可以同在一节；2 分：独占一节，含一次读者亲身经历；3 分：独占一节，含手算或互动；≥4 分：至少两节，或单独成章 |
| 超预算 | 在全课方案阶段就拆章，不在写正文时硬塞；现有课不追溯拆章，重写时再定 |

| 原则 | 默认标准 | 谁查 |
|---|---|---|
| 章纲 | 有章纲，过了逻辑审读；成品每节回答的就是章纲里那一问；元素表每行写得出它服务哪一问或哪种阅读体验，两样都写不出的不做（第 6 条） | 逻辑审读、主控 |
| 难度预算（第 5 条） | 合计不越过警戒线（见上表），越过了有理由；难度分打低会让估计失效，所以审读复核，读者审读的卡点反过来校准 | 章纲 |
| 问题链（第 1 条） | 一个驱动问题；每节第一句接住上一节留下的问题 | 读者审读重建问题链 |
| 先经验后名字（第 2 条，硬规则） | 新概念起名前读者已经亲身碰到过它；互动、任务、练习不用未起名的新词（读者早就认识的名字除外） | check.mjs 2c（提示）、审读 |
| 负荷（第 3 条） | 一段一个新东西（读者基础好可以多一点，但不放两个互相依赖的生词）；要记的数在图表里 | check.mjs 2d（提示）、审读 |
| 先用稳（第 4 条） | 被依赖的概念先让读者用过一次 | 章纲、闭卷自测 |
| 讲透（第 7、9 条） | 核心概念五层走到；难度 ≥2 的概念至少一个反例或"差一点"划出边界（例子数量见第 7 条） | 章纲、审读 |
| 自测（第 8 条） | 难度 ≥2 的核心概念有一个读者自己用它并得到反馈的时刻（试试看、预测或练习） | 章纲、闭卷自测 |
| 开场 | 一屏内交代要解决什么、手里有什么（做法见 `zh-teaching-prose`），读者说得出这章讲哪个概念（第一节第 2 条）；不以定义开场，也不以和概念无关的故事或比喻开场 | 审读 |
| 视觉 | 有结构或机制的理解难点有一张画出它的图；视觉的间隔、字数阈值见 course-kit `SKILL.md` 第一节第 5.1 条，挑法见第 3 条和 `visuals.md` | 截图、check.mjs 3 |
| 凸显 | 做法见 course-kit `SKILL.md` 第一节第 4 条 | check.mjs 2b |
| 练习 | 默认 4–6 题带解析（够检验学习目标又不拖）；能检验学习目标，≥1 题考"为什么" | 主控 |

| 可选做法 | 什么时候做 | 做了的标准 |
|---|---|---|
| 招牌互动 | 难度 ≥2 的核心概念的关键时刻（"改一个东西会怎样"、读者亲手撞上概念），而且动手能看到静态图看不到的东西。替代测试：一张图或一句话讲得一样清楚，就不做互动 | 直接操作、即时视觉反馈、可撤销或重来，配"试试看"，完成时给反馈；一章大互动的上限见 `interaction.md` 第二节规则 14 |
| 微互动 | 能暴露一个错误直觉，或让读者亲手撞上概念时（点击高亮、悬停提示、先猜后揭晓、一键对比） | 每个选项有各自的反馈；只是心算一个数的不做；不为凑配图间隔而加 |
| 发明故事框 | 有可靠历史，且历史能说明"为什么非有不可" | 第一节第 9、12 条；每个核心概念最多一个 |
| 原理框 | 有一条值得单讲、能标出处的"为什么" | 原理 + 出处；验证实验只在读者能亲手确认、确认后真有收获时配 |
| 世界观原理 | 按一D 矩阵分到本章 | 挂在具体现象下，和本章概念有明确联系，第二次出现时回指 |
| 哲学时刻 | 本章概念引出一个值得想的问题；每篇争取一个 | 第一节第 12 条 |
| 时间线、支线、笔记框 | 有可选的深入内容、开放问题时 | 见 components.md |

| 技术底线 | 标准 |
|---|---|
| 篇幅 | 用时按课程定位定，写进项目文档；节数由问题链定，每节回答一个问题；不留文字墙，字数默认值、提示和报错的阈值见 course-kit `SKILL.md` 第一节节奏规则 1 |
| 术语 | 新术语出现时当场一句话说清；用了悬停释义、术语表或闪卡（见可选功能表）时汇入其中 |
| 跨章 | 不写元语言、不预告后文（见 `zh-teaching-prose` "段落"）；用了概念关系图时，本章概念登记进 `js/concepts.js` |
| 无障碍 | 颜色不是唯一信息；对比度见 `skin-contract.md` 第一节；有结构或机制的图带 `aria-label`；互动可用键盘；尊重"减少动态"；声音默认静音可关 |
| 检查 | 通过第八节的脚本检查，改动后重跑 |

## 一C、写作风格

正文文风（句子、段落、禁用词、小标题、对话、强调标记、开场和结构）全部按 `zh-teaching-prose` skill；给写作和审读 agent 派任务时怎么写任务书，见第八节第 3 条。各课在自己的项目文档里只补本课特有的写法。

下面是 skill 之外、课程结构特有的写作要求：

- **不写元语言、不预告**：写法见 `zh-teaching-prose` "段落"；章间关联交给"相关章节"。
- **不用只有作者知道的说法**：规则见 `zh-teaching-prose` "读者知道什么"。课程里最常漏出来的是制作过程中的叫法：章纲、问题链、难度分、元素表、组件编号（如 K4）、项目文档里的代号，正文、界面文字和练习里都不出现；要提到就换成读者在页面上看得见的说法。
- **开篇先交代前因后果，再引入概念**：开场必须交代前因后果，做法见 `zh-teaching-prose` 的"叙事与结构"；回指前一章只用一句话，本章用到的数据、定义、算例在本章亮出来，没读过上一章也能跟上。主概念什么时候起名，见第一节第 2 条。
- **概念站在前台，故事退到背景**（有背景故事或角色的课）：故事只在开头简报、题头小图、陪伴角色偶尔一句里露面；背景故事和关卡简报不替代开场一屏的前因后果，放在题头区或开场之后的收起框；正文主语是概念本身，例子取领域里的真实处境，互动任务也用概念的说法（"6 步内把损失降到 0.5 以下"）。不拿故事里的东西替换概念的名字，比如把损失叫"敌人血量"，读者就没法在真实场景里认出它。简报要自洽，是一条讲得通的因果链（对手或对象是什么 → 哪里不对 → 要做什么），并且只用已经起过名的词。
  ✗ 简报写"熵增正在侵蚀营地，去稳住它"，而熵还没讲，读者既不知道对手是什么，也不知道要做什么。
- **概念为主，数学为辅**（有数学的课程；用户原话："不要一大段孤立的数学""不想像僵硬的教材"）：
  - 每个公式都属于一个概念，紧挨着那个概念的图或互动出现；读者先懂了概念，公式才作为简写出场。
  - 正文不设符号表、纯数学分节、塞满多个概念的"补给站"（数学较重的课，符号速查可以放进收起的抽屉）；符号第一次出现时在句子里顺手说清。
  - 推导和额外数学放进章末默认收起的"进阶抽屉"。
  - 重要的公式写成跨章反复出现的"家族"（同一个模式在不同主题里再见），帮读者建立意义。
- **数学走五级台阶**：处境 → 具体数字 → 换符号 → 公式拆解互动 → 活图再算，目标是数学直觉；完整做法见 `references/optional-ai-math.md` 第二部分。
- **让人思考，不像教材**：每节开头让读者感到有个问题在等答案（不必是问句），关键处让读者先猜、先试，在互动里自己发现规律，再点破、起名字；节末若后面还有节，留下的是读者自己想问的下一个问题，不是总结。
- **自检**：遮住小标题读一遍，能否顺着读下去、知道每句话为什么出现？像提纲就重写（问题链见第一节第 1 条，小标题怎么写见 `zh-teaching-prose` 的"叙事与结构"和"写课程时另看"）。

## 二、互动与可视化

- **招牌互动**是像"拆房子"那样的直接操作：读者亲手拆、拼、拖、调参数、搭，立刻看到概念的后果。控件少而明确，用"试试看"任务给出目的；关键处"先预测，再看结果"。选择题的位置见 `interaction.md` 第二节规则 12。
- **反馈**：每次点击都有看得见的变化，能撤销/重来。
- **图的种类**：关系、流程、循环、坐标、对比、时间线、分布；文字够大，手机可读。
- **真实图片**：历史人物、实物、地点、论文页面等真实图片能帮助阅读、保持兴趣。只用公共领域或 CC 授权的（优先 Wikimedia Commons、NASA、政府作品），下载到课程本地，图注写来源与授权，并登记在课程的图片来源清单里；查不到授权就不用。
- **配图版式**：大段文字配插画时图文并排，版式见 `components.md` T2。同组例子用页签/轮播，一次显示一个，反例有明显区分。
- **插画画出"为什么"**：正例画出要素齐全，反例画出缺的那一项或错在哪。每门课建自己的插图库（人物、物件、绘制工具），各章在其上画。
- **插画人物规范**：
  - 全课人物画法统一；不同人物靠发型、帽子、眼镜、服装、配饰区分，不只换颜色。
  - 符合物理：站着的人脚落在地面，坐着的人有椅子或凳子；拿东西的手真的握住物件（物件在两手之间，不离手、不压在身上），指东西的手指向画面里的东西；人物和机器人手脚齐全；戴眼镜看得见眼睛。
  - 文字不压图：气泡、标签不与人物和图形重叠；气泡里的字短；人物别画太小。
  - 每张插画单独截图放大检查（`tools/shot.mjs` 截单个元素）。

## 三、结构与导航

- **章内导航**（共享脚本生成）：分节折叠、本章目录（高亮当前节、全部展开/收起、回顶部）、阅读进度、打印时全展开。
- **学习辅助组件**：概念卡、原理框、发明故事框、立场卡等各有一个组件（`components.md`），另有进度打钩（小标题不挂层级标签，见第一节第 9 条）。
- **章与章的小幅变化**：同篇各章在主色、背景纹理、标题装饰上做小变化，字体、组件形状、描边方式等风格骨架不变。

**可选功能表**：开新课时逐项想一想要不要加，决定写进项目文档。读者要反复查、反复练的课程更值得加。

| 功能 | 帮读者做什么 | 什么时候值得加 | 做法 |
|---|---|---|---|
| 学习地图 | 一眼看到全课分几块、先学什么 | 章数多、有先修关系 | 目录页按篇分组的地图 |
| 学习路径 | 不同读者走不同路线 | 读者起点差别大 | 目录页几条路线，如"一周入门""完整路线""底层原理路线" |
| 概念关系图 | 看概念之间的前置、解释、应用、对照关系 | 概念多、彼此牵连 | `map.html` + `js/concepts.js`（节点 = 概念，边 = 关系；代码 `kit/modules/graph.js`） |
| 相关章节 | 读完一章知道接着看哪几章 | 有关系图时顺带生成 | `kit/modules/vl-concepts.js` 从 `js/concepts.js` 生成 |
| 术语悬停释义 | 读到术语时不用离开正文 | 术语多、读者零基础 | 共享脚本 + 术语数据 |

| 闪卡 | 记住术语和要点 | 要背的东西多 | `flashcards.html` |
| 总复习章 | 学完串一遍 | 课程长 | 最后一章 |
| 笔记 / "你的思考" | 读者写下自己的想法 | 有开放问题、哲学时刻 | 自动保存的文本框 |
| 声音 | 反馈或氛围 | 游戏化、低龄读者 | 默认静音，可关 |

## 四、每章结构：先写章纲，外壳固定

每章动笔前写一页章纲，存在课程文件夹的 `章纲/chNN.md`。章纲比整章便宜得多，顺序、先修和跳跃的问题在这里改，成本最低。章纲是规划和审读的工具，不是要机械填满的表；游戏关卡等其他形式在项目文档里写自己的结构，但第一节的原则和五层内容不能少。

**章纲模板**

1. 驱动问题：一句，用读者的话写；围绕一个主题的巡礼可以写得宽。
2. 读者起点：本章可以直接用的概念（前面章节讲过的）、读者的数学和背景起点。
3. 开场做法：一句写具体内容（做法见 `zh-teaching-prose` 的"叙事与结构"）。
4. 问题链：

| 节 | 此刻的问题（只用已有的词） | 这节的答案（一句） | 新东西（默认每段 ≤1 个） | 读者亲身碰到的方式 | 留下的问题 |
|---|---|---|---|---|---|

5. 概念与难度：每个概念一行：名字、起点分、+符号、+依赖、合计、依赖谁、在哪一节先用稳、划边界的反例、读者自己用它的时刻。
6. 元素表：每行：元素（组件编号）、服务于哪一问或哪种阅读体验、读者做什么或看什么、看完明白什么或感觉什么。
7. 关键例子：主例子一个，加反例和其余例子各一句。
8. 收起的内容：发明故事、推导、支线各一句。

**章的外壳**（顺序固定，中间的节由问题链决定）：题头（章号徽记 + 写出主题的标题 + 一句副标题 + 小插画；标题和副标题的写法见 `zh-teaching-prose`）→ 学习目标（3 条"读完你能……" + 用时）→ 开场 → 按问题链的若干节 → 常见误区（有跨概念的误解才写，只放这类）→ 要点 + 一句话总结 → 练习（每篇最后一章加本篇回顾 + 综合题）→ "你的思考"文本框（可选，自动保存）→ 上一章 / 下一章；有关系图时加相关章节（共享脚本生成）。哲学时刻、发明故事框、原理框都是中间的节里按内容放的可选件，没有固定位置。

## 七、技术约束

- 纯前端、离线可用，双击 html 就能打开；存储用共享脚本里带 try/catch 的封装。
- **能原生做就原生做**。确需引入库时：①下载到课程 `lib/`，固定版本，不依赖 CDN；②只在需要的页面加载；③选宽松协议（MIT 等），在 `lib/README.md` 登记名称、用途、版本、协议；④不用需要构建步骤的框架。可评估的库：Rough.js（手绘）、KaTeX（公式）、p5.js（生成艺术）、Matter.js（物理）、D3（数据可视化）、Three.js（3D）、Tone.js（音乐）。
- 网络字体用 JS 异步插入 `<link>`，并有系统字体兜底；不要在 CSS 里 `@import` 网络字体（网慢时会阻塞整页脚本）。
- `</main>` 后先加载 kit 脚本再加载页面脚本；页面特有样式写页内 `<style>`，id 和类名加章节前缀，不重新定义共享类名（会覆盖共享样式）。
- 键盘、触控目标、pointer 事件的做法见 `interaction.md` 第三节；手机宽度单列；有打印样式。

## 八、工作流与质量闸门

**每章的流水线**（第 3–5 项写每一步的细节）：

| 步 | 做什么 | 谁做 | 过关条件 |
|---|---|---|---|
| ① 章纲 | 按第四节模板写 `章纲/chNN.md` | 写作 agent | 难度分不越过警戒线（或有理由）；元素表每行写得出它服务什么 |
| ② 逻辑审读 | 只读章纲和项目文档的读者定位，查顺序、先修、跳跃、负荷 | 无上下文 agent（任务书见第 5 项） | 没有"问题里用了没讲过的新词""答案逼不出下一问""依赖前没有用稳"三类问题 |
| ③ 用户确认章纲 | 样板章、每篇第一章逐章确认；其余章纲按篇合成一份，用户扫读 | 用户 | 用户点头；用户的修改在章纲上改 |
| ④ 写正文 | 照章纲写；要改先改章纲；整章重构时先备份旧页，按新章纲重搭结构，不在旧页上叠补丁 | 写作 agent | 难度分高（合计接近警戒线或含 ≥4 分概念）的章，前两节写完先做一次快速读者审读（只做 A 段），再写后面 |
| ⑤ 脚本检查 | 流程、提示行怎么汇报见 course-kit `SKILL.md` 第七节 | 写作 agent | 无 ✗；按文风 skill 的 review.md 逐句自审过 |
| ⑥ 读者审读 | 读成品，逐节记录 + 重建问题链 + 闭卷自测 | 无上下文 agent（任务书见第 5 项） | 主控对照章纲，列出修改清单发回写作 agent |
| ⑦ 主控验收 | 自己跑完整检查、看截图、扫全部小标题、对照章纲逐节看 | 主控 | 子 agent 的汇报也可能有误；不能只看截图和检查结果，至少读开场一节和中段一节的正文 |
| ⑧ 用户看成品 | 样板章逐章看；之后每篇抽一章 | 用户 | — |

1. 先问美术风格（course-kit `SKILL.md` 第六节），再问读者、篇幅、语言、模块，然后交课程方案（知识地图、章节表含驱动问题和难度分合计、学完能做到什么）给用户确认；问法见 course-kit `SKILL.md` 第六节。改编号、新增章节等大改动先给方案。
2. 先定结构（默认第四、五节，或本课自己的结构）和可选功能 → 搭共享骨架（用 `starter/new-course.mjs` 生成：样式、kit、目录页、章节表、插图库，选了的可选功能）→ 做一章样板让用户确认章纲、写作与版式 → 再铺开。并行写章之前样板章的文风先过用户验收：文风的毛病一旦定型，会同时出现在十几章里。
3. 给子 agent 的 brief 完整自足：章节表、章纲、必读文件、文风（写上 `zh-teaching-prose` 路径，并把本课最要紧的文风规则连同反面例子原样贴进来，不压成"按 skill 写"）、世界观原理分配、事实核实要求、互动清单、校验要求、汇报格式。子 agent 只改自己的文件，不碰共享文件；同一批文件不同时派给两个 agent；临时文件放 scratchpad 下各自的子目录；任务书里点名的脚本只写这次专门准备的，别指向名字相近的旧脚本（曾有 agent 误跑改 skill 的脚本，把 SKILL.md 改坏）。改已有章的文风时，写明"整章逐段通读，不是只改检查脚本提示的句子"（脚本抓不到句间转折和概念段同一骨架，只修提示会改得很轻），汇报要贴整段改前改后。子 agent 中断（如额度用完）时用消息续跑，不要重开。并行几个由各课项目文档定。
4. **每章检查**：命令、步骤、提示行汇报和流程见 course-kit `SKILL.md` 第七节。补充两点：`qa.mjs` 中文页和 `en/` 英文页都会测；截图用 `shot.mjs`，不直接用 `msedge --screenshot`（窄于约 500px 时布局不准）。
5. **两种审读**，都派无上下文的 agent，任务书写明身份、输入、固定的汇报格式：
   - **逻辑审读（读章纲）**：身份是教学设计编辑，不改文风，只查逻辑。输入：`章纲/chNN.md`、项目文档的读者定位（读者、数学起点）、前面各章的概念清单。逐条给"位置｜问题｜建议"：①每节的"此刻的问题"是否只用了读者起点里的词或本章已起名的词；②答案是否自然逼出下一节的问题，有没有硬切；③每段的新东西是否过载；④被依赖的概念前面有没有安排"用稳"；⑤难度分是否打低（对照一A 的锚点），合计是否超警戒线；⑥元素表里有没有既不服务理解、也不服务阅读体验的行；⑦每个核心概念有没有划边界的反例和读者自己用它的时刻；⑧开场做法能不能让读者说出"在做什么、为什么"。最后一行回答：这一章该拆吗，怎么拆。
   - **读者审读（读成品）**：身份严格按项目文档的目标读者扮演，写明数学和背景起点；不看章纲，不看之前的讨论。输入：`PYTHONIOENCODING=utf-8 python <skill>/tools/readable.py <html绝对路径>` 的输出，它会标出正确答案（测验、先猜后揭晓的正确项带 ✓，估数题写出答案，排序题列出正确顺序），所以任务书里写明：先只读正文，做完练习、记下自己的答案，再看 ✓ 对照。汇报分五段：**A 逐节记录**（每节读完写一行，不回头改："第 N 节｜我懂了什么（一句，自己的话）｜我现在想问什么｜哪个词、数、句子没跟上（原句前 15 字）"）；**B 凭记忆重建**（合上全文：这章在回答什么问题；每节怎么接上一节；每个核心概念用自己的话说清并举一个文中没有的例子）；**C 闭卷练习**（错的题写"我为什么会这么选"）；**D 元素**（每个互动和图写"它让我明白了什么"或"它给了我什么阅读感受"，两样都说不出的标"无用"；互动任务里有没有我还不认识的词；每句界面说明文字（"怎么看"、试试看、按钮提示）读完脑子里能不能出现屏幕上的画面，出现不了或出现错的，标出原句，规则见 interaction.md 第二节第 16 条；脚本回放要覆盖每个任务的完成条件和数值；反例：一个互动同时塞进迷雾、轨迹、血条、曲线和两个任务）；**E 节奏与文风**（哪里是一大片字、哪里同时要记太多东西；读者审读是第三方读，AI 味只报最明显的 5 处；写作自审按 `zh-teaching-prose/references/review.md` 全报）。不写客套和总体评价。
   - 主控用法：B 段的问题链和章纲逐行对照，对不上的那一节就是断点；A 段"想问什么"和下一节的问题不一致，就是衔接断了；C 段错题回章纲查是否"用稳"；D 段"无用"的元素先砍；卡点集中的概念，难度分调高一分。
6. 全部完成后做体检（人工），对照一A、一B 逐项查，重点看问题链是否连贯、发明故事是否讲清"为什么非有不可"、互动是否有用不堆砌、语言是否自然、有无前向预告。
7. 再做选定的可选功能（术语表、闪卡、学习路径等），最后做英文版。
8. 交付汇报怎么写见 course-kit `SKILL.md` 第七节"交付汇报必须写"；另要如实说明哪些事实不确定。

## 十、视觉风格与通用美学

**选风格**：开课第一件事是让用户选皮肤，流程见 course-kit `SKILL.md` 第六节（可以说明推荐哪套和理由，不替用户默认）。样式由所选皮肤决定，内容结构、互动、导航、写作规范不变。

**通用美学原则（所有风格）**：
- **可读性优先**：正文、次要文字、图注、图中文字的对比度要求见 `skin-contract.md` 第一节，不用浅灰小字；长文放在安静的底色上。
- **字体**：读得清是底线，细则见 `skin-contract.md` 第一节"字体规则"。风格感靠配色、边框、纹理、插画和数字字体体现。
- **不做廉价 PPT 卡片**：见 course-kit `SKILL.md` 第二节"安静的底子"。
- **层级与留白**：标题、正文、注释层级分明，留出呼吸空间，装饰不抢正文。
- **图服务于理解**：图和特效都要帮助理解或反馈操作；动态效果可关闭，尊重"减少动态"偏好。
- **风格 = 一份样式 + 少量装饰**（配色变量、字体栈、边框、纹理、插画笔触、徽章）；导航、测验、轮播、关系图等脚本与风格无关，直接复用。
- **滤镜要验证**：用 SVG 滤镜做手绘抖动等效果时，属性写 `in="SourceGraphic"`（写错一个词全图变噪点），文字放在滤镜组之外。
