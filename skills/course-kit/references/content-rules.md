# 互动学习网页课程：内容规范

用途：互动学习网页课程的内容规范（讲什么、讲到多深、一章和全课的验收标准、工作流）。课程专属的规则和数字写在各课程文件夹的 `项目规则与经验.md`（由 `starter/` 生成）。可以整份复制到你的项目里当 `content-rules.md` 用。

用来制作**任意领域**的互动学习网页课程：每门课一个文件夹。
读者：想系统学会一个领域的普通人。不假设基础，但讲到真正的深度，**读起来有趣、读得懂**。

- 第一至九节是与风格无关的通用规范；第十节讲选风格与通用美学，具体样式由每门课的风格决定。
- 下文的"章"指课程的学习单元，也可以是关卡、课时或课程自定的单位；文中的数字、结构顺序、文件命名都是**默认值和参考值**，各课按自己的定位调整，写进项目文档。
- 正文文风统一用 `zh-teaching-prose` skill（古典风格 + 非虚构写作），本文件不重复它的细则。
- 视觉、组件、版式、配图、交互、动效、皮肤和一键检查见 course-kit 的 `SKILL.md`，本文件不重复。
- 工具在 course-kit 的 `tools/`：`check.mjs` 一键检查（含下面第八节的三道检查）、`qa.mjs` 自动点击测试、`shot.mjs` 整页/单元素截图、`readable.py` 读者视图、`illus-overlap.mjs` 插画重叠检查；浏览器由 `browser.mjs` 自动找（Edge 或 Chrome，或用环境变量 `EDGE_PATH` 指定）。

## 一、内容原则（最重要）

1. **每个核心概念按五层讲**（五层是每个概念的配料，按概念交织出现，不按章分块；核心概念五层走全，次要概念讲"是什么 + 为什么成立"，其余收进支线；五层只用于写作自检，小标题不挂层级标签）：
   - **是什么**：定义 + 直觉例子 + 示意图。
   - **发明故事**：站在学习者角度还原——当时遇到什么问题 → 之前的尝试为什么不行 → 关键洞察 → 怎样演化到今天，让读者觉得它**非发明不可**。先让读者猜或试，再揭晓；配带插图的时间线或"问题→方案→新问题"演化图。正文留一两句关键洞察，完整故事放进默认收起的发明故事框。没有可靠历史就讲"它解决了什么痛点"。
   - **为什么成立**：底层原理（心理学、数学、系统、物理……随领域而定），**标出处**（谁、哪本书/哪项研究），配一个能亲手验证的实验。
   - **怎么用**：真实场景 + 互动与练习。
   - **反思**：局限、争议、常见误区。争议紧挨着被质疑的观点讲，章末误区节只放跨概念的误解。争议观点在需要处说一次"这是某某的观点"；有复制争议的研究如实说明。
2. **例子要足**：每个核心概念 ≥3 个具体例子，来自本领域和日常生活，含 1 个反例或"差一点就对"，具体到能想象画面。
3. **聚焦且成体系**：每章围绕一个主题娓娓道来，从熟悉的处境出发一层层展开，每段接住上一段留下的问题；讲最重要的 1–3 个核心概念，其余放"延伸"；先画整门课的知识地图（分篇、依赖、顺序）；先直觉/例子，再定义，再原理。
4. **全课覆盖**：基础概念 → 底层原理 → 世界观知识 → 案例拆解 → 实战项目；定目录时列出"从业者每天会遇到什么"，对照查缺口。
5. **事实准确**：人名、年份、数字、引语不确定就联网核实（优先原论文、官方文档等原始来源）；查不到就删或改成保守说法；不编造数据；教学用示意模型标"示意"；数学与模拟要算对。
6. **只讲需要的，但讲透**：删除测试——删掉这句，读者对核心概念的理解会变差吗？不会就删。时间线留 3–5 个节点；人名、版本、产品、参数举一两个代表；实现细节点到"为什么重要"为止。正文难度适中，讲到读者"懂了"就停，推导、数学、研究细节进默认收起的抽屉，深度留给想深入的读者。砍的是无关细节，不是解释：每个新概念、例子、故事都讲到零基础读者真正理解，宁可多写两三句讲透一个点，也不要五个点各写一句。
7. **历史和哲学穿插在每章，不单独成篇**：历史就是"发明故事"；哲学是每章 1–2 个"哲学时刻"——一个真正值得想的问题，2–3 种立场并标明是谁的观点，不给标准答案，最后留一个开放问题。

## 一C、写作风格

正文文风（句子、段落、禁用词、小标题、对话、强调标记、开场和结构）全部按 `zh-teaching-prose` skill；写作和审读 agent 的任务书里写上它的路径，让它先读 SKILL.md 和两份 references。各课在自己的项目文档里只补本课特有的写法。

下面是 skill 之外、课程结构特有的写作要求：

- **不写元语言**：正文不写"本章""本课""下一节会讲""第N章会详细介绍"；可以自然回指前面（"还记得捉迷藏的例子吗"），章间关联交给"相关章节"。
- **概念站在前台，故事退到背景**（有背景故事或角色的课）：故事只在开头简报、题头小图、陪伴角色偶尔一句里露面；正文主语是概念本身，例子取领域里的真实处境，互动任务也用概念的说法（"6 步内把损失降到 0.5 以下"）。不拿故事里的东西替换概念的名字，比如把损失叫"敌人血量"，读者就没法在真实场景里认出它。
- **概念为主，数学为辅**（有数学的课程；用户原话："不要一大段孤立的数学""不想像僵硬的教材"）：
  - 每个公式都属于一个概念，紧挨着那个概念的图或互动出现；读者先懂了概念，公式才作为简写出场。
  - 不设符号表、纯数学分节、塞满多个概念的"补给站"；符号第一次出现时在句子里顺手说清。
  - 推导和额外数学放进章末默认收起的"进阶抽屉"。
  - 重要的公式写成跨章反复出现的"家族"（同一个模式在不同主题里再见），帮读者建立意义。
- **数学走五级台阶**：
  1. 先给处境和麻烦，让读者需要一个办法；
  2. 用具体数字把例子算一遍，不出现字母；
  3. 指出规律，把文字逐个换成符号，每次 ≤2 个新符号，当场说读法和对应的数；
  4. 关键公式做成"公式拆解"互动：公式片段与白话解释同色联动；
  5. 用公式和活图（滑块改数、图立刻变）再算一遍。
  每个数学概念或符号出场前先铺垫：现实场景、可视化、数字例子三者至少有一样，越难越抽象就给得越多。先确定读者的数学起点，超出的都当新知识就地铺垫。目标是**建立数学直觉**：它像什么、为什么长这样、改一个数会怎样。宁可少一个公式，也不要一个读者看不懂的公式。
- **让人思考，不像教材**：每节从问题或处境开始，让读者先猜、先试，在互动里自己发现规律，再点破、起名字；每节留一个真正值得想的问题。
- **自检**：遮住小标题读一遍，能否顺着读下去、知道每句话为什么出现？像提纲就重写。

## 一D、世界观知识库与穿插规则

这类知识让读者"换一种方式看世界"，用户特别喜欢。它们编进各章的"为什么成立"，在 2–3 个情境里**螺旋式重复出现**。分量足够大的可以单独成"世界观章"（一条能亲手验证的规律，不是哲学漫谈），前面埋伏笔、后面回指。用之前联网核实出处。

**穿插规则**：
1. 做"原理—章节"矩阵：每个重要原理在 ≥2 个章节以不同情境出现，每章承载 1–2 个原理。
2. 原理挂在具体现象下出现（"为什么抽卡会让人上头？"→预测误差）。
3. 第二次出现时回指第一次，换一个新角度。
4. 标出处与争议；在关系图里登记为节点，和用到它的概念连线。
5. 世界观章同样走五层结构，配一个验证这条规律的招牌互动。

## 二、互动与可视化

- **招牌互动**是像"拆房子"那样的直接操作：读者亲手拆、拼、拖、调参数、搭，立刻看到概念的后果。控件少而明确，用"试试看"任务给出目的；最好"先预测，再看结果"。选择题只放在练习里。
- **反馈**：每次点击都有看得见的变化，能撤销/重来。
- **图的种类**：关系、流程、循环、坐标、对比、时间线、分布；文字够大，手机可读。
- **真实图片**：历史人物、实物、地点、论文页面等真实图片能帮助阅读、保持兴趣。只用公共领域或 CC 授权的（优先 Wikimedia Commons、NASA、政府作品），下载到课程本地，图注写来源与授权，并登记在课程的图片来源清单里；查不到授权就不用。
- **配图版式**：大段文字配插画时图文并排，宽屏一栏文字一栏图，顶端对齐，不绕排、不垂直居中；窄屏上下排。同组例子用页签/轮播，一次显示一个，反例有明显区分。
- **插画画出"为什么"**：正例画出要素齐全，反例画出缺的那一项或错在哪。每门课建自己的插图库（人物、物件、绘制工具），各章在其上画。
- **插画人物规范**：
  - 全课人物画法统一；不同人物靠发型、帽子、眼镜、服装、配饰区分，不只换颜色。
  - 符合物理：站着的人脚落在地面，坐着的人有椅子或凳子；拿东西的手真的握住物件（物件在两手之间，不离手、不压在身上），指东西的手指向画面里的东西；人物和机器人手脚齐全；戴眼镜看得见眼睛。
  - 文字不压图：气泡、标签不与人物和图形重叠；气泡里的字短；人物别画太小。
  - 每张插画单独截图放大检查（`tools/shot.mjs` 截单个元素）。

## 三、结构与导航

- **章内导航**（共享脚本生成）：分节折叠、本章目录（高亮当前节、全部展开/收起、回顶部）、阅读进度、打印时全展开。
- **学习辅助组件**：第四节各模块各有一个组件，另有进度打钩（小标题不挂层级标签，见第一节第 1 条）。
- **章与章的小幅变化**：同篇各章在主色、背景纹理、标题装饰上做小变化，字体、组件形状、描边方式等风格骨架不变。

**可选功能表**：开新课时逐项想一想要不要加，决定写进项目文档。读者要反复查、反复练的课程更值得加。

| 功能 | 帮读者做什么 | 什么时候值得加 | 做法 |
|---|---|---|---|
| 学习地图 | 一眼看到全课分几块、先学什么 | 章数多、有先修关系 | 目录页按篇分组的地图 |
| 学习路径 | 不同读者走不同路线 | 读者起点差别大 | 目录页几条路线，如"一周入门""完整路线""底层原理路线" |
| 概念关系图 | 看概念之间的前置、解释、应用、对照关系 | 概念多、彼此牵连 | `map.html` + `js/concepts.js`（节点 = 概念，边 = 关系；代码 `kit/modules/graph.js`） |
| 相关章节 | 读完一章知道接着看哪几章 | 有关系图时顺带生成 | `kit/modules/vl-concepts.js` 从 `js/concepts.js` 生成 |
| 术语悬停释义 | 读到术语时不用离开正文 | 术语多、读者零基础 | 共享脚本 + 术语数据 |
| 术语表 | 集中查所有术语 | 术语多 | `glossary.html`，数据是 `js/concepts.js` 的 `terms`（`kit/modules/build-concepts.mjs --write` 从各章汇入） |
| 闪卡 | 记住术语和要点 | 要背的东西多 | `flashcards.html` |
| 总复习章 | 学完串一遍 | 课程长 | 最后一章 |
| 笔记 / "你的思考" | 读者写下自己的想法 | 有开放问题、哲学时刻 | 自动保存的文本框 |
| 声音 | 反馈或氛围 | 游戏化、低龄读者 | 默认静音，可关 |

## 四、每章结构（默认顺序）

下面是单个核心概念的默认讲法顺序，一章里几个概念交替各走一遍，按课程需要调整或合并；游戏关卡等其他形式在项目文档里写自己的结构，但五层内容（是什么、发明故事、为什么成立、怎么用、反思）不能少。

1. 题头：章号徽记 + 标题（直接写出本章的核心概念或主题，看标题就知道讲什么，写法见 `zh-teaching-prose`）+ 一句话副标题 + 小插画
2. 学习目标（3 条"读完你能……" + 用时）
3. 【是什么】示意图 + 例子轮播（带插图）
4. 【发明故事】问题 → 早期尝试 → 关键洞察 → 演化；先猜后揭晓 + 带图时间线（发明故事框默认收起，露标题和一句介绍）
5. 【为什么成立】原理框（含出处）+ 验证实验 + 世界观原理
6. 【怎么用】招牌互动
7. 常见误区 → 反思与争议
8. 要点 + 一句话总结
9. 练习；每篇最后一章在其后加"本篇回顾 + 综合题"
10. "你的思考"文本框（可选，自动保存）
11. 上/下一章；有关系图时加相关章节（共享脚本生成）

"哲学时刻"放在第 4–6 项里最贴切的位置。

下面是默认结构，按课程调整（例如游戏课用 `level-xxx.html`）；可选功能的文件只在选了时才有。


## 六、中英双语

- 英文在 `en/` 下同名文件；顶栏和目录页有语言切换；进度与笔记的 key 两种语言共用。
- 完整翻译正文、图中文字、互动 JS 字符串、测验、占位符、术语释义；id、结构、逻辑不变；英文同样遵守一C；有 `js/concepts.js` 时它也含英文字段。
- 中文定稿后再翻译；英文完成后才显示语言切换按钮。

## 七、技术约束

- 纯前端、离线可用，双击 html 就能打开；存储用共享脚本里带 try/catch 的封装。
- **能原生做就原生做**。确需引入库时：①下载到课程 `lib/`，固定版本，不依赖 CDN；②只在需要的页面加载；③选宽松协议（MIT 等），在 `lib/README.md` 登记名称、用途、版本、协议；④不用需要构建步骤的框架。可评估的库：Rough.js（手绘）、KaTeX（公式）、p5.js（生成艺术）、Matter.js（物理）、D3（数据可视化）、Three.js（3D）、Tone.js（音乐）。
- 网络字体用 JS 异步插入 `<link>`，并有系统字体兜底；不要在 CSS 里 `@import` 网络字体（网慢时会阻塞整页脚本）。
- `</main>` 后先加载 kit 脚本再加载页面脚本；页面特有样式写页内 `<style>`，id 和类名加章节前缀，不重新定义共享类名（会覆盖共享样式）。
- canvas 用 pointer 事件；手机宽度单列、触控目标够大；有打印样式。
- **Windows 环境**：临时文件用 scratchpad 绝对路径（Git Bash 与 Python 的 `/tmp` 不是同一处）；输出中文的 Python 脚本加 `PYTHONIOENCODING=utf-8`（控制台是 GBK）；改大段中文用 Edit 工具，不用 shell heredoc。

## 八、工作流与质量闸门

1. 先问美术风格（第十节），再问读者、篇幅、语言、模块，然后交课程方案（知识地图、章节表、学完能做到什么）给用户确认；问法见 course-kit `SKILL.md` 第六节。改编号、新增章节等大改动先给方案。
2. 先定结构（默认第四、五节，或本课自己的结构）和可选功能 → 搭共享骨架（用 `starter/new-course.mjs` 生成：样式、kit、目录页、章节表、插图库，选了的可选功能）→ 做一章样板让用户确认写作与版式 → 再铺开。
3. 给子 agent 的 brief 完整自足：章节表、结构模板、必读文件、文风（写上 `zh-teaching-prose` 路径）、世界观原理分配、事实核实要求、互动清单、校验要求、汇报格式。子 agent 只改自己的文件，不碰共享文件；同一批文件不同时派给两个 agent；临时文件放 scratchpad 下各自的子目录。子 agent 中断（如额度用完）时用消息续跑，不要重开。并行几个由各课项目文档定。
4. **每章三道检查**（`node <skill>/tools/check.mjs <课程文件夹绝对路径> chNN` 一条命令跑完，步骤和流程见 course-kit `SKILL.md` 第七节）：
   - **语法**：提取内联 `<script>`，逐段 `new Function(code)`。
   - **运行**：`node tools/qa.mjs <课程文件夹绝对路径> [chNN]`，在 420px 和 1100px 下点击所有按钮、拖所有滑块，检查 JS 报错与横向溢出。必须传绝对路径（相对路径会被拒绝）；中文页和 `en/` 下的英文页都会测。
   - **看画面**：`node tools/shot.mjs <html绝对路径> <输出.png> page <宽度>` 截整页（420 和 1100 各一张），再截单张插画/图表放大看：图是否显示、文字是否重叠、对比度是否够。不直接用 `msedge --screenshot`（窄于约 500px 时布局不准）。
5. **读者审读**：每章交付后派一个无上下文的审读 agent，扮演本课读者，用 `tools/readable.py` 读读者视图，先闭卷自测，再报卡点、跳跃、AI 味和节奏；主控核实后把修改清单发回写作 agent。readable.py 的输出会标出正确答案（测验、先猜后揭晓的正确项带 ✓，估数题写出答案，排序题列出正确顺序），所以任务书里写明：先只读正文，做完练习、记下自己的答案，再看带 ✓ 的答案对照。
6. **主控验收**：子 agent 交付后，主控自己截图看一遍，单独扫一遍全部小标题，并复查它列出的"未核实/不确定"清单；子 agent 的汇报也可能有误。
7. 全部完成后做体检（人工），对照一A、一B 逐项查，重点看发明故事是否讲清"为什么非有不可"、互动是否有用不堆砌、语言是否自然、有无前向预告。
8. 再做选定的可选功能（术语表、闪卡、学习路径等），最后做英文版。
9. 交付时如实说明：哪些验证过、哪些没验证、哪些事实不确定。

## 九、沟通偏好

- 用中文回复，先回答问题再说下一步；简洁，表格/列表优先；给明确建议，不罗列选项。
- 如实汇报，不夸大；"语法通过"不等于"测试过"。
- 改名、删除、覆盖等不可逆动作前先看目标；用户已确认的方案不再反复征求同意。
- 收到反馈后，先在一章样板上改好给用户看，再推广。用户说"看不懂"时先问清卡在哪，再改。
- **改文档在原条目上改**：找到最贴切的现有条目改写，或删掉冲突的旧条目；不追加"补充/新增"节，节号和节标题不变；冲突时以用户最新的话为准；同一个东西全文档用同一个词，内容优先写成表格和短列表，每份文档开头一行写用途。这条只管文档；课程页面反而要每章结构、元素不一样。

## 十、视觉风格与通用美学

**选风格**：开课第一件事是让用户从 course-kit `skins/` 里验收过的皮肤中选一套（每套一句"适合什么课"，附验收页；可以说明推荐哪套和理由，但不替用户默认），用户选定后再动手。样式由所选皮肤决定，内容结构、互动、导航、写作规范不变。

**通用美学原则（所有风格）**：
- **可读性优先**：正文、次要文字、图注、图中文字对背景的对比度都 ≥4.5:1，不用浅灰小字；长文放在安静的底色上。
- **字体**：书法、粉笔等装饰字体只用于大标题；验证过清晰的手写体（字母数字另配清晰字体）可用于小标题、按钮、标签和图中文字；正文用清晰字体。风格感靠配色、边框、纹理、插画和数字字体体现。
- **不做廉价 PPT 卡片**：长文直接排在底上（墙、纸、版面），不在平涂底色上浮一张卡片放长文；只有"东西"才有实体（画框+卡纸、裱板、展柜，带同向投影）；底面要有细微真实质感，光要有来由。
- **层级与留白**：标题、正文、注释层级分明，留出呼吸空间，装饰不抢正文。
- **图服务于理解**：图和特效都要帮助理解或反馈操作；动态效果可关闭，尊重"减少动态"偏好。
- **风格 = 一份样式 + 少量装饰**（配色变量、字体栈、边框、纹理、插画笔触、徽章）；导航、测验、轮播、关系图等脚本与风格无关，直接复用。
- **滤镜要验证**：用 SVG 滤镜做手绘抖动等效果时，属性写 `in="SourceGraphic"`（写错一个词全图变噪点），文字放在滤镜组之外。
