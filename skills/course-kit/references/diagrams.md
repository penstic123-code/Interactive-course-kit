# 概念图解模板库

用途：讲一个"结构"（循环、层级、因果、对比、分类……）时选哪种图解、怎么画、别犯哪些错。图解是 `components.md` T3 编号图里的一族；什么时候配图解、和插画怎么交替，见 `SKILL.md` 第一节。模板 1–12 已在 `kit/diagrams.js` 实现（`VL.diagram.cycle / nested / flow / quadrant / compare / timeline / tree / venn / balance / network / spectrum / stack`），写法和参数见 `kit/README.md` 第九节，**以它为准**；13–14（频数树、推理链）kit 里还没有，只有画法，按页内 SVG 手画。

用户最看重的就是这类图：循环图、嵌套圈这种，**每个节点有名字 + 一行具体例子，图注写"为什么"，能点一层看一层，标签在图外用引线。**

## 一、所有图解共守的画法

| # | 规则 | 怎么做 | 正例 / 反例 |
|---|---|---|---|
| 1 | 节点 = 名字 + 一行例子 | 名字默认 ≤6 字粗体；下面一行具体例子默认 ≤14 字（"秒级：按键跳一下"，字数服从图中字 ≥13px 放得下），不写抽象释义 | 正例：AI `ch07-learning-as-search.html` 变异→选择→遗传，"每件事下"写了例子；反例：只有"行动 / 反馈 / 奖励"三个词的圈，读者看了不知道指什么 |
| 2 | 颜色分工 | 结构（框、箭头、轴）用墨色 `--dg-ink`；**全图只一个强调色**给当前要看的那一块（选中态 `--dg-hi`）；节点底色 `--dg-c1…c6` 用色号 `c` 分类，不按节点轮换颜色；对错用 `--ok/--no` 并加 ✓✗；量用 `--q1…--q6`，和正文、公式同色。**同一样东西整章同一个颜色**（类别 A 永远橙、B 永远蓝，不同图里也一样），读者靠颜色认出"又是它" | 反例：每个节点一种颜色、五颜六色（AI 用户反馈"像 AI 拼的"）；上一张图橙色是猫，下一张图橙色成了狗 |
| 3 | 标签在图外，用引线 | 嵌套圈、同心椭圆、曲线旁的说明，放在图形外侧，用细引线（1–1.5px）连到所指部位；不把字塞在边框上 | 正例：三层嵌套循环在右侧用引线标出每一层 |
| 4 | 文字离线 ≥4px | 文字包围盒离任何框、线、圈 ≥4px；挤不下就加高画布，不缩字 | `tools/qa.mjs` 的图内文字检查（出界、压边框、挤线、重叠）能抓出大量出界、压线问题 |
| 5 | 图中字 ≥13px，对比度 ≥4.5:1 | 手写体可用于图中文字，但要验证过清晰，字母数字另配清晰字体（`unicode-range`） | 反例：手写体的"VR5"被看成"9R5" |
| 6 | 图注写"为什么" | 图注说这张图证明 / 说明了什么，不复述图里的字；≤40 字 | ✓"秒、分、天三层套在一起，所以一局玩腻了还有更大的圈拉你回来"；✗"核心循环的三个层级" |
| 7 | 可点就能点一层看一层 | kit 的图解默认可选：点中的块高亮、其余变淡，信息行换成这块的 `info`；键盘、`select:false`、事件见 `kit/README.md` 第九节 | 正例：AI `ch01-what-is-ai.html` 套娃图"点任意一层，看它比外层多了什么" |
| 8 | 静态版信息完整 | 不点也能读懂；点开只是放大细节。打印、关掉动效时全部可见 | — |
| 9 | 有 `aria-label` | 写清画了什么、怎么连（读屏读者靠它）；颜色不是唯一信息。kit 的图解不给 `label` 时自动生成 | 每张内联图都写完整的 `aria-label` |
| 10 | 一张图只讲一个意思；默认和正文同宽、约 2:1、高 ≤300px（太高要滚动才看全，竖向的链、树可以例外） | 开画前能用一句话说出这张图讲什么；说不成一句就拆。节点多时宁可拆成两张，不缩小 | — |
| 11 | 边缘：概念图可随皮肤手绘抖动，数据图笔直 | 抖动滤镜 `in="SourceGraphic"`，文字放滤镜组外 | 数据图用 `o.wob = 0` |
| 12 | 画出机制，读者能顺着走一遍 | 有量的图把倍数或数值写在边上，读者能顺着图重算一遍；没有量的图（循环、分类）用箭头和位置画出谁导致谁、谁属于谁 | 正例：树的每条边写"×0.3"，叶子写乘出来的数；反例：只有"原因→结果"空箭头 |
| 13 | 图里的数就是正文刚用的数 | 同一组数不在图里换一套；能用代码时，图和正文从同一组数据生成，改数时两边一起变 | 反例：正文说 36 张，图里画 40 格 |
| 14 | 线型有含义，全课一致 | 只用一种线就不需要说明；用了两种以上，在线旁直接标注，或在图角放一行图例；颜色不是唯一区分（规则 2、模板 10） | 反例：虚线时而是"相关"、时而是"额外条件" |
| 15 | 向不熟概率的读者讲概率，先写成个数 | 第一次引入概率时用"100 个里有 36 个"（自然频率），不用百分数或 p 值起步；个数能直接数、直接乘，百分数要读者自己换算（依据：Gigerenzer & Hoffrage, 1995, *Psychological Review*，频数格式能显著提升贝叶斯推理的正确率） | 正例：频数树（模板 13） |

## 二、模板

### 1 循环
- **讲什么**：一件事的结果又成为下一轮的起点——反馈回路、核心循环、迭代、学习循环、恶性循环。
- **例子**：行动→反馈→奖励→成长→新目标；大富翁正反馈；恶性循环；迭代循环；游戏循环；强化学习循环，用开场喂零食来标；k-means 认旗 / 挪旗循环。
- **画法**：3–6 个节点沿圆或圆角矩形排；箭头首尾相接，回到起点的那一段画粗或加 ↺ 标；节点 = 名字 + 用本章开场例子的一行（AI `ch06` 的做法最好：循环的每一步都用"喂零食"那个场景来标）。正反馈 / 负反馈在箭头上标 + / −。
- **常见错误**：节点超过 6 个，圈变成一串字；所有箭头一样粗，看不出哪里是回路；节点只写抽象词。

### 2 嵌套圈 / 套娃
- **讲什么**：A 包含 B、B 包含 C；或同一个模式在不同时间尺度上嵌套。
- **例子**：人工智能 ⊃ 机器学习 ⊃ 深度学习 ⊃ 大语言模型，可点每层；秒级 / 分钟级 / 天周级三层循环；魔圈：圈内规则、圈外现实。
- **画法**：同心圆或同心圆角矩形，层间留 ≥18px 让引线穿过；**每层的名字和例子都在图外右侧**，引线连到该层的边；最内层可放一个小图标；点一层 = 这层描边加粗 + 填强调色淡底，其余变淡，信息框写"它比外层多了什么"。
- **常见错误**：把层名写在圆环里、压在边框上（最常见的毛病）；层太多（>4）挤成一团；读者分不清"包含"还是"先后"——包含用嵌套，先后用流程。

### 3 流程 / 管道
- **讲什么**：一件东西经过几道工序变成另一件东西；有方向、不回头。
- **例子**：约定奖励→被感知为控制→自主感下降→兴趣更低；一个事件同时走画面、声音、震动三条通道；纸面原型六步；HTML→DOM→渲染树；计算图从左往右。
- **画法**：从左到右（窄屏改从上到下）；每道工序一个框，框之间的箭头上写"发生了什么"（动词）；进出的东西画成小物件（纸条、方块），让读者看见"东西在流动"。分叉用 Y 形，汇合用 ⋀。
- **常见错误**：箭头上不写字，读者不知道每步做了什么；把循环画成流程（最后一步回到起点就该用模板 1）；超过 6 步不拆。

### 4 坐标 / 象限
- **讲什么**：两个独立维度决定位置；或四类东西由两条轴切出。
- **例子**：技能 × 挑战的心流通道，左上焦虑、右下无聊；Bartle 四象限；UI 四象限；研究方法：自述↔行为 × 定性↔定量；多大 × 多重的地板坐标图。
- **画法**：两条轴两端都写白话（"太简单 ↔ 太难"），不只写变量名；象限名放在象限内角、离轴 ≥8px，各配一个代表例子的小图；要读者判断位置时做成 G4 拖拽（"把这个游戏拖到你觉得的位置"）。
- **常见错误**：轴只有名字没有方向；象限名压在轴线上；四个象限用四种颜色却没有文字区分。

### 5 对比两栏
- **讲什么**：同一件事的两种做法、改前改后、正例反例。
- **例子**：无反馈方块 vs 有反馈方块；一次定稿 vs 每轮反馈；等待输入型 vs 游戏循环；独热向量 vs 嵌入。
- **画法**：两栏同尺寸、同构图、同起点，**只让要比的那一处不同**；左右各一个文字签 ✓ / ✗ 或"之前 / 之后"；差异处用强调色圈出。要看细微差别时用 E2 拖线对比。
- **常见错误**：两栏画法不同，读者分不清差异来自概念还是画法；差异点没圈出；用颜色当唯一区分。

### 6 时间轴 / 节奏曲线
- **讲什么**：量随时间起伏（节奏、强度、记忆），或事件在时间上的先后。
- **例子**：关卡紧张度起伏，休息点在波谷；一次打击的反馈时间线：确认、顿帧、挤压、余震，可点；1-1 教学时间线；输入随机→决策→输出随机；年份带。
- **画法**：横轴是时间，刻度写白话单位（"第 1 秒""第 3 关"）；关键时刻打竖虚线 + 图外标签；起伏曲线的波峰波谷各配一个场景小图；可点的时刻做成热区。发明故事的年份时间线用 T5，不用这里。
- **常见错误**：曲线标签贴着线写，和线重叠；刻度太密；把示意曲线画得像真实数据却不标"示意"。

### 7 树 / 分类
- **讲什么**：一分为几、再分为几；决策分叉；技能 / 分支结构。
- **例子**：决策树，选项标收益 / 风险 / 代价；分支树不断分叉；点数之争的决策树；技能树：线性、分叉、汇合；所有可能的时间线。
- **画法**：根在上或左；同一层节点对齐；层数 ≤4，每层 ≤5 个，超出折叠成"……还有 3 种"；叶子节点配小图或例子；概率 / 数值写在边上，离线 ≥4px。决策树可做成"点一枝看结果"。
- **常见错误**：分类标准混用（同一层既按颜色又按大小分）；树太宽，手机上横滚看不全（要么竖排、要么拆两张）。

### 8 维恩 / 重叠
- **讲什么**：两三类东西有交集——"既是 A 又是 B"的那一块才是重点。
- **例子**：用得少。最接近的是两张各剪一刀的半透明纸叠起来，只认两张都盖到的地方；家族相似（交叠的相似性网络）。遇到"交集"类概念时优先考虑它。
- **画法**：最多 3 个圈；圈用半透明淡底 + 墨色描边，交集区单独填强调色；每个区域放一个具体例子（不是区域名），区域名放圈外用引线；点一个区域高亮它并说明"为什么落在这里"。
- **常见错误**：圈名写在交集里；4 个以上的圈（看不懂，改用表格）；例子落在边界线上，看不出属于哪块。

### 9 天平 / 拉锯
- **讲什么**：两股力量此消彼长、要找平衡点；权衡、取舍、相克。
- **例子**：天平：权重砝码 vs 门槛砝码；跷跷板上的平均；算力定了，参数和数据此消彼长；重剑 vs 弓的权衡；三角相克，圆圈大小随参数变；挑人之后身高和球技像跷跷板。
- **画法**：支点和两端都画成实物（砝码、小人、跷跷板），两端各写"是什么在往这边压"；倾斜角度跟着读者的参数变（做成 G2 活图最好）；平衡点用强调色标。
- **常见错误**：只画静态天平，读者感受不到"此消彼长"；两端的量没有单位或例子。

### 10 网络 / 关系
- **讲什么**：多个东西两两相连，关系本身就是重点——因果图、偏差来源、概念关系、社会网络。
- **例子**：因果图搭建台，六个变量可拖、可连箭头；选择偏差关系图；四种偏差流向"你"；进度系统类型以"进度"为中心；三个条件一起指向心流；全课的概念关系图（`map.html`）。
- **画法**：节点 ≤8（多了做成 `modules.md` 的概念关系图）；**边的类型靠线型 + 文字区分**（实线 = 导致，虚线 = 相关，箭头方向 = 谁影响谁），不只靠颜色；中心节点最大；点一个节点只亮它的邻居。
- **常见错误**：线交叉成一团（先手排位置，不用力导向自动布局）；边没有标签，读者不知道线代表什么。

### 11 光谱轴（补充）
- **讲什么**：一个维度上从一端到另一端的连续变化，各种实例按程度排开。
- **例子**：嬉戏 paidia → 竞技 ludus；纯合作 → 纯竞争；卖选择 → 卖痛苦；游戏 → 现实。
- **画法**：一条粗轴，两端写白话极端（"毫无规则 / 规则严密"）；实例画成小图挂在轴上，名字在下方；可做成 G4 拖拽"你觉得它在哪"。
- **常见错误**：实例只写名字没有小图；中间一段没有例子，读者以为只有两极。

### 12 层叠 / 堆积（补充）
- **讲什么**：一个整体由几层叠成，或几部分加起来等于总量。
- **例子**：期末误差拆成噪声 / 偏差 / 方差三层；四级台阶：短边→形状→部件→物体；简单规则→相互作用→整体；从飘字到升级弹窗的反馈层次。
- **画法**：底层画在下面（地基感）；每层 = 名字 + 例子，放在层的右侧图外；能点一层看这一层贡献了多少；堆积柱用 `--q*` 编码和正文一致。
- **常见错误**：层名写在层里被色块吃掉；层的顺序和"谁依赖谁"不一致。

### 13 频数树（只有画法，kit 未实现，按页内 SVG 手画）
- **讲什么**：用"个数"而不是百分数，算出"在看到某个特征的人里，有多少真的属于某一类"——条件概率、贝叶斯、检测的假阳性。
- **例子**：100 只动物先分猫 / 狗，再分"耳朵尖 / 不尖"，最后问"耳朵尖的里面，几只是猫"；检测题：1000 人里 10 人患病，检测呈阳性的里面几个真患病。
- **画法**：自上而下四层。①总数框（"100 只"）；②按类别分叉，**每条边写倍数或比例**（"×0.3""×0.7"），子框写乘出来的整数；③再按特征分叉，边上同样写倍数，叶子写个数；④底部一个结论框，写"尖耳朵共 N 只，其中猫 M 只，M ÷ N"。要找的那几个叶子和结论框用强调色，数字和正文同源（规则 13）；选能除尽的总数，让每个子框都是整数、相加对得上总数。
- **常见错误**：边上不写倍数，读者算不出子框的数；叶子写百分数；数不取整、加起来对不上；把要问的那一组叶子和无关的叶子画得一样。

### 14 推理链（只有画法，kit 未实现，按页内 SVG 手画）
- **讲什么**：几条规则连起来推：一条规则的结论成为另一条规则的条件，最后得出一个动作——专家系统、规则引擎、逻辑推理、诊断流程。
- **例子**：症状（发烧、咳嗽）→ 规则 1"疑似感染"→ 规则 2"疑似感染且白细胞高 → 细菌感染"→ 动作"开抗生素"。
- **画法**：左边是输入事实（小框），中间是规则节点（圆角框，里写"如果……就……"的一句话），右边是动作。输入用实线箭头进规则；**规则的结论画成一个小标签，再用箭头接进下一条规则的条件口**；规则要的"额外条件"用虚线箭头，图角有图例；最终的动作用强调色。从左到右排，箭头不交叉。
- **常见错误**：规则节点和结论分不清（结论要单独成标签）；实线虚线不加图例；规则一多就铺满，超过 5 条规则拆成两张。

## 四、HTML 结构示意

kit 的写法（以模板 2 为例；其余模板同样是声明式或 `VL.diagram.<名>()`）：声明式或 JS 调用，SVG、引线、信息行都由 `diagrams.js` 生成，不手写。


## 五、什么时候不画图解

| 情况 | 改用 |
|---|---|
| 这段话没有结构，只有一个场景或一件事 | 场景插画、真实照片 |
| 要讲"改一个数会怎样" | G2 活图（图解只能画一种状态） |
| 只有两三个并列名词，没有关系 | K2 并列卡阵，或一句话说完 |
| 图解只是把正文的句子装进框里、加了箭头 | 删掉——删掉后读者理解不变差，它就不该在 |
| 上一个视觉也是静态图解 | 中间先隔一个插画、例子或互动（`SKILL.md` 节奏规则 3） |
| 关系太多（>8 个节点、>3 个圈、>4 层） | 拆成两张，或换成表格 T8 / 概念关系图模块 |
| 讲历史、人物 | 真实图片、带图时间线 T5 |
| 已经有一张图讲过同一个结构 | 回指"看图 3"，不重画；同一张图全课只用一次 |
