# 组件库

用途：每个核心组件做什么、什么时候用、内容怎么写、交互和皮肤样子；排版式、选组件时逐个对照。总规则（节奏、视觉底线、互动底线）在 `SKILL.md`，这里不重复。类名前缀 `vl-`，JS 命名空间 `VL`；下面的 HTML 已按 kit 现有代码写（`kit/vl.js`、`kit/README.md`）；标“kit 里暂无”的，代码还没进 kit，写法只是示意。**API 以 `kit/README.md` 为准**，两处不一致时以代码为准。

课程简称（这套规矩的来源课；下文的“正例 / 反例”只说明规矩从哪来，那些课程文件不随 skill 提供）：GD = 游戏设计课（笔记本），DS = 数据科学课（纸片爬塔），AI = AI 课（各世界复古媒介）。

## 零、所有组件共守的四条

| # | 规则 | 正例 / 反例 |
|---|---|---|
| 1 | 组件只管结构、交互、无障碍；颜色、字体、描边、纹理由皮肤给。组件里不写死颜色，界面文字走 `VL.t()`，不写进 CSS `::before` | 反例：GD `css/style.css` 的 `.tldr::before`、`.eg::before` 写死"一句话总结""例 / 反例"，英文版只能打补丁 |
| 2 | **框也算正文**：任何框里超过 2 段就配图，或拆成"图 + 短文"；有正文的框都留图位（概念卡 `.vl-cc-fig`、原理框 `.vl-why-fig`） | 反例：GD 原理框约 72 个超过 250 字且无图（如 `ch05-emergence-systems.html`） |
| 3 | 不用 emoji 当图标；图标走插图库小图 | 反例：GD `.card.mini .ico` 大量 emoji；AI 已全课去掉 |
| 4 | 动效按四类（帮助理解 / 反馈操作 / 阅读激励 / 氛围）归档，细则见 `interaction.md`；组件自己只播反馈类，激励类只派事件 | 正例：DS `DS.tryDone()` 只打勾存档，纸屑由别的模块订阅 |

"各皮肤样子"一栏固定四种：笔记本｜纸片｜像素｜小镇。W5–W8 只有样稿，不写。

## 二、导航

### N1 顶栏
- **功能**：回目录、看全课进度、跳到任一章、开关偏好（配色亮 / 暗 / 护眼——暗色和护眼还没完整验收，开课默认用亮色、截图验收也只看亮色；动效 自动 / 全开 / 轻量 / 关、语言）。声音开关、激励面板由可选模块加进顶栏，见 kit/README.md 第八节。
- **用 / 不用**：每页都用，vl.js 按章节表（`js/course.js` 的 `VL_COURSE`）和 `<body data-ch>` 自动生成，章节不手写；`data-part` 由 vl.js 写，不用手写。`VL_COURSE.topbar:false` 可关。
- **内容**：只放导航和开关，不放正文提示。全课进度用"迷你图 + 弹层列表"两件套；手机上迷你图可以藏，弹层必须在（反例：AI 手机上隐藏章节点后无法跳章）。
- **交互与键盘**：全部是 `button` / `a`；弹层 Esc 关、点外面关、关后焦点回按钮；迷你图里的格子不能 `tabindex=-1` 又 `aria-hidden`（反例：DS 小楼条）。
- **动效**：反馈类。
- **皮肤**：笔记本＝墨线下边 + 篇色点阵｜纸片＝白纸条 + 小塔图标 + 亮灯窗｜像素＝深色 HUD 条 + 8×8 图标｜小镇＝胡桃木横梁。

```html
<body data-ch="3">   <!-- 顶栏 header.vl-topbar 由 vl.js 生成；vl.js 另写 body[data-part]、body[data-pat]、--vl-dh、--vl-chnum -->
```

### N2 章首
- **功能**：一屏内说清第几章、讲什么、读完能做到什么、要多久。
- **用 / 不用**：每章一个。章数 >15 时加"你在这里"小地图（kit 里暂无；顶栏的章节点 `.vl-tb-dots` 和“第 N / 共 M 章”弹层已能跳章）。
- **内容**：徽记（vl.js 自动补“第 N 章”）+ h1 + 副标题 1 句（≤30 字，从处境或反直觉问题出发，不写定义）+ **插画位（必有，走 T1，不手写 SVG）** + 学习目标 3 条（"读完你能……"，各 ≤25 字）+ 用时。
  反例：GD 题头小画直接写在 HTML 里，没进插图库，没法查重、没法换皮。
- **交互**："你在这里"格子可点跳章。
- **动效**：氛围类，全归皮肤，可关。
- **皮肤**：笔记本＝药丸徽记 -3° + 荧光笔 h1｜纸片＝题头天空带 + 主色纸签｜像素＝关卡标题卡 WORLD n-k｜小镇＝钉铜钉的木牌。

```html
<div class="vl-hero">
  <div class="vl-hero-txt"><h1>平均人不存在</h1>
    <p class="vl-sub">一架按"平均飞行员"造的座舱，为什么谁坐都不合适？</p></div>
  <span data-illus="c03-hero"></span>          <!-- 徽记 .vl-badge 缺了自动补 -->
</div>
<div class="vl-goals"><h3>读完你能</h3><span class="vl-time">约 30 分钟</span>
  <ul><li>……</li><li>……</li><li>……</li></ul></div>
```

### N3 分节
- **功能**：把一章切成 8–12 件"一件事"，可折叠。
- **用 / 不用**：每章都用。**小标题不挂"是什么 / 发明故事……"层级标签**，五层只用于写作自检（GD 旧的 `.tag.what/.why` 不进库）。
- **内容**：h2 用具体场景或具体问题，≤16 字，整组句式错开；**不写成摘要句**（✗"选择偏差让数据在到手前就被筛过"；✓"《文学文摘》寄出了一千万张明信片"）。每节从问题或处境开始。
- **交互与键盘**：点标题 / Enter / 空格折叠；`role=button aria-expanded`；打印前全展开。
- **动效**：反馈类（箭头 ≤200ms；内容显隐不做高度动画）。
- **皮肤**：笔记本＝accent2 圆编号 -5°｜纸片＝主色纸签 + 红图钉｜像素＝关卡方块｜小镇＝黏土圆片 + 沙土小路。

```html
<div class="vl-sec"><h2>《文学文摘》寄出了一千万张明信片</h2></div>
<p>……这一节的内容直接跟在后面……</p>
<!-- .vl-sec 必须是 <main> 的直接子元素；到下一个 .vl-sec 或 .vl-pager 之前的内容由 vl.js 收进 .vl-sec-body，节号 .vl-n 自动加 -->
```

### N4 章内目录与阅读进度
- **功能**：跳到任一节、一键全部展开 / 收起、回顶部、看读到哪了。
- **用 / 不用**：分节 ≥2 自动出现（右下浮钮 `.vl-fab` → 面板 `.vl-navpanel`；顶端进度条 `.vl-readbar`）。皮肤可以把它画成塔楼梯、小镇窄栏，功能和键盘行为不变（AI W4 用小镇窄栏代替浮钮，窄屏行为未测，换形态时要补测）。
- **内容**：目录项就是 h2 原文；当前节判定统一"顶边过视口 35%"。
- **交互与键盘**：浮钮 → 面板；Esc / 点外面关；点链接先展开那一节再滚过去。
- **动效**：反馈类（面板 ≤250ms）。
- **注意**：阅读进度条只显示位置，**不触发任何奖励或"已读"记录**（反例：DS 读到 92% 就 `Progress.done()`）。
- **皮肤**：笔记本＝歪斜浮钮｜纸片＝纸片圆钮 + 塔剖面台阶｜像素＝像素框 + 分格血条｜小镇＝右侧小镇窄栏。

### N5 章末导航
- **功能**：上一章 / 下一章（`nav.vl-pager`，vl.js 自动生成）；有概念关系图时加"相关章节"（先修与原理 / 延伸与应用 / 对照与关联，`modules/vl-concepts.js` 生成，见 kit/README.md 第八节）。
- **内容**：不预告后面章节的内容；未开放的章（章节表里 `open:false`）不给链接，翻页处写"第 N 章还在写"并回目录（正例：AI `.related`）。
- **动效**：反馈类；跨页过场属氛围（DS 登楼），可关。
- **皮肤**：笔记本＝白卡 + accent 投影｜纸片＝"上楼 / 下楼"纸牌｜像素＝关卡出口｜小镇＝路牌。

## 三、讲概念

### K1 概念卡
- **功能**：把一章的 1–3 个核心概念"立起来"，读者一眼知道这一章在讲什么。用户最看重的组件之一。
- **用 / 不用**：每个核心概念一张，放在**概念首次被命名处**（读者已经见过处境和例子之后）；次要概念不用卡，用 K7 起名标记。
- **内容**（固定字段，卡内不写第二段）：

  | 字段（类名） | 写什么 | 字数 |
  |---|---|---|
  | 名称 `.vl-cc-name` | 通行名，大字 | ≤10 字 |
  | 原文名 / 组成 `.vl-cc-en` | 英文原名，或"由哪几项组成" | 1 行 |
  | 出处 `.vl-cc-by` | 一个人 · 一本书或论文 · 年份；**只写一个名字**，不堆学者 | 1 行，可省 |
  | 通俗地说 `.vl-cc-plain` | 大白话的一句（小签"通俗地说"自动加） | 1 句 |
  | 定义 `.vl-cc-def` | 一句定义，皮肤加粗 | ≤60 字 |
  | 例子 `.vl-cc-eg` | 回指正文里已经讲过的那个例子，不新开例子，也不把例子再讲一遍（小签"例子"自动加） | ≤30 字 |
  | **图位 `.vl-cc-fig`（必有）** | 画出要素或机制的小图（不是装饰角标），≤240px；宽屏在右、窄屏在名称下；没有专门的图时写"看图 3"并给缩略图。缺了 vl.js 显示红色"缺概念图"占位并 console.warn | — |

  正例：GD `ch02-core-loop.html` 的 `cc-card`"核心循环"字段齐全、用 `<aside aria-label>`。反例：GD 102 张卡全无图位；AI `.cn-prop` 道具角标只是装饰，不算解释图。
- **重复规则**：同一个例子不在开场、概念卡、例子卡里讲三遍——概念卡只写一句回指。
- **交互**：无；阅读激励模块可在"读懂后"点亮它（见 `modules.md`），**不按停留时长**（反例：DS 卡停 1.5s 纸飞机飞向背包）。
- **动效**：无（激励挂钩除外）。
- **皮肤**：笔记本＝白卡 + 墨线 + 左厚边 + 硬投影 + 斜贴标签｜纸片＝象牙白纸 + 左厚边 + 纸片小图｜像素＝点阵框双线｜小镇＝小木牌。

```html
<aside class="vl-cc">                         <!-- 顶边小签"概念卡"（data-tag 可改）和 aria-label 自动加 -->
  <p class="vl-cc-name">核心循环</p>
  <p class="vl-cc-en">Core loop</p>
  <p class="vl-cc-by">（可省）一人 · 一书 · 年份</p>
  <p class="vl-cc-plain">玩家一遍遍重复的那组动作。</p>
  <p class="vl-cc-def">玩家在游戏里反复做的一串事情，做完回到起点，再来一轮。</p>
  <p class="vl-cc-eg">开头那局俄罗斯方块。</p>
  <div class="vl-cc-fig"><span data-illus="c02-cc-loop"></span></div>
</aside>
```

### K2 并列卡阵
- **功能**：一个概念下 3–7 个同级要素或类型并排看。
- **用 / 不用**：要素、分类、"可带走的经验"；不用于长文，不用于正反对比（用 E2），有层级或因果的用图解（`diagrams.md`）。
- **内容**：每张 = 小图（必有，插图库，不用 emoji）+ 名称 ≤8 字 + 一句话 ≤40 字；同组同一画法。
- **交互**：默认静态；可选"点一张看详情"（即 M2 的卡片版）。
- **皮肤**：笔记本＝歪贴小卡｜纸片＝错落小纸片｜像素＝物品格｜小镇＝木托盘上的小牌。

```html
<!-- kit 里暂无卡阵组件；现在用等宽栅格 .vl-grid2/3/4 排（≤700px 变单栏），卡片外观写在页内、类名加章节前缀 -->
<div class="vl-grid3">
  <div class="c03-card"><span data-illus="c03-mot-a"></span><b>自主</b><p>……</p></div>
</div>
```

### K3 原理框
- **功能**：讲"为什么成立"：一条原理 + 出处 + 一个能亲手验证的实验，必要时一句争议。
- **用 / 不用**：每章 ≥1 个，挂在具体现象之后；不放定义（定义进 K1）。
- **内容**：标题是一句原理（≤20 字，不写"原理"二字）；**正文 ≤2 段（约 200 字），超过就配图或拆成图 + 短文**；**图位必有**（`.vl-why-fig`：示意图、真实图片或上方互动的缩略图；代码不强制，缺了不报错，靠检查第 3 步配图密度兜底）；小签"为什么成立"自动加；出处行 = 谁 · 哪项研究 · 年份 + "验证：上面的××"；争议一句："也有人不同意：……（某某）"。
  正例：AI 原理框出处里写"验证：上面的模拟器"。反例：GD 原理框是带投影的平涂长文卡（平均 424 字），违反"不做 PPT 卡片"。
- **外形**：轻块（页边竖线 + 小签），不是浮起来的卡片。
- **皮肤**：笔记本＝页边竖线 + 手绘放大镜小签｜纸片＝铜图钉钉住的薄纸｜像素＝细线框 + 色方块标题｜小镇＝钉在石膏板上的说明卡。

```html
<div class="vl-why">                          <!-- 有 .vl-why-fig 时宽屏两栏，图 34% 在右 -->
  <h3>大脑对"比预期好"反应最强</h3>
  <div class="vl-why-fig"><span data-illus="c02-why-rpe"></span></div>
  <p>……（≤2 段）</p>
  <p class="vl-src">舒尔茨的猴子实验，1997。验证：上面的抽卡模拟。</p>
</div>
```

### K4 演化链
- **功能**：把"问题 → 方案 → 新问题 → 新方案"画成一串，让读者看到概念是被逼出来的。
- **用 / 不用**：发明故事的骨架、状态转移；没有先后因果的并列内容不用（用 K2）。
- **内容**：3–5 个节点；每节点 = 小图 + ≤20 字。先给前两个节点让读者猜下一个（接 M1），再揭晓。
  正例：AI `ch03-fitting-gradient-descent.html`、`ch06-reinforcement-learning.html` 的"上排问题、下排办法"演化流程图。
- **交互**：可选逐个揭晓（"然后呢？"按钮；kit 里暂无，现在是静态链）。
- **动效**：帮助理解类（依次出现；关掉动效直接显示全部）。
- **皮肤**：笔记本＝手写箭头连小方块｜纸片＝纸条用图钉连起来｜像素＝关卡路线｜小镇＝沿小路的站牌。

```html
<ol class="vl-chain">
  <li><span data-illus="c03-ev1"></span>七次观测对不上一条轨道</li>
  <li class="vl-chain-ar" aria-hidden="true">→</li>
  <li>……</li>
</ol>
```

### K5 立场卡（哲学时刻 / 争议）
- **功能**：一个真正值得想的问题，先表态，再翻看 2–3 种立场（标明是谁的观点），最后留开放问题。
- **用 / 不用**：每章 1–2 个；有标准答案的题不用。
- **内容**：第一张 = 问题 + 表态按钮；中间每张一种立场，≤2 段、可带图，立场名写观点不写人名（"规则先于游戏"），人名放出处行；最后一张 = 开放问题，可接 P3。
- **交互与键盘**：表态 `aria-pressed`、可改票，翻到立场页时回显"你选的是……"；◀▶ / ←→ / 横滑 / 带立场名的圆点；打印全展开。
  反例：AI 投票在 13 章各写一份，进库后统一成一个组件（`.vl-philo` / `.vl-vote`，见 kit/README.md 第七节）。
- **动效**：反馈类（翻页 ≤300ms）。
- **皮肤**：笔记本＝虚线页 + 便签贴立场｜纸片＝淡紫纸 + "哲学时刻"签｜像素＝深色面板｜小镇＝胡桃木板。

```html

<div class="vl-philo" data-key="ch22-philo1">
  <div class="vl-philo-slide" data-t="问题">……<div class="vl-vote" data-options="会|不会|看情况"></div></div>
  <div class="vl-philo-slide" data-t="魔圈是真的">……<p class="vl-src">赫伊津哈，1938</p></div>
  <div class="vl-philo-slide" data-t="留给你">……</div>
</div>
```

### K6 收束块（常见误区 / 要点 / 一句话）
- **功能**：章末收紧理解：纠正最常见的错想法、列带走的东西、压成一句话。
- **内容**：误区每条 = 错想法原句（加粗）+ 为什么错 1–2 句；要点 3–5 条，各 ≤40 字；一句话 ≤40 字。**标签文字写在 HTML 里**（正例：DS `<p class="tldr"><b>一句话</b>：…</p>`）。误区多于 3 条时改成 M1 翻牌"你也这么想过吗"。
- **皮肤**：笔记本＝橙底误区 + 虚线要点 + 手写一句话条｜纸片＝杏色纸片 + 小签｜像素＝色方块标题细框｜小镇＝石膏板告示。

```html
<div class="vl-misc"><p><b>"随机就是均匀"</b>——……</p></div>
<div class="vl-key"><p><b>要点</b></p><ul><li>……</li></ul></div>
<p class="vl-tldr"><b>一句话</b>……</p>      <!-- 皮肤把第一个 <b> 排成小标签 -->
```

### K7 行内标记（术语释义 / 起名 / 着重）
- **功能**：新术语当场看一句释义；概念第一次起名被看见；一段里最要紧的一句被看见。
- **内容**：术语首次出现用 `.vl-term`，`data-def` 一句话、不重复术语名（`data-name` 可改释义框标题）；概念首次起名、着重号一段最多两处，不用 `<b>` 堆强调（起名用 `<span class="vl-cn">`，皮肤画成荧光笔，只给核心概念和次要概念第一次被命名处；着重用 `<span class="vl-em">`，笔记本皮肤画成着重号、英文页画成下划线；普通 `<b>` 只是加粗，不当起名用）。核心概念的名字要在小标题、起名标记、概念卡三处一致，见 SKILL.md 第一节。术语表 `glossary.html` 由 `kit/modules/terms.js` 从概念数据 `js/concepts.js` 的 `terms` 生成；`node kit/modules/build-concepts.mjs <课程绝对路径> --write` 把各章 `.vl-term[data-def]` 汇进这份数据（同一术语两处释义不同会报 ✗）。
- **交互与键盘**：`tabindex=0`（vl.js 自动加）；悬停 / 聚焦 / 轻点切换；Esc、滚动关闭；释义框用 JS 定位，夹在视口内、上下自动翻（正例：DS `.term-tip`；反例：GD / AI 纯 CSS `::after` 在屏幕边缘出屏）。
- **动效**：反馈类（≤150ms 或无动画）。
- **皮肤**：笔记本＝点线下划线 + 墨底气泡、荧光笔｜纸片＝点状下划线 + 白纸释义框｜像素＝点阵气泡｜小镇＝小纸签。

```html
<span class="vl-term" data-def="把一类东西里挑过的样本当成全体">选择偏差</span>
<span class="vl-cn">核心循环</span>   <!-- 起名：荧光笔，只用于概念第一次被命名 -->
<span class="vl-em">最里面的循环不好玩，外面再多层也转不起来</span>   <!-- 着重：一段最多两处 --> 
```

### K8 旁注与出处
- **功能**：放不进主线但有用的一句话、出处、"示意"声明、操作提示。
- **内容**：旁注 ≤3 行；出处跟在图、原理框、引用后；教学用示意模型必标"示意"。小字也 ≥4.5:1（下限参考 DS `--muted #4d566c`），小字用 Medium 字重。
- **皮肤**：笔记本＝页边铅笔小字｜纸片＝左 4px 主色条｜像素＝淡底左色条｜小镇＝铅笔写在石膏板边。

```html
<p class="vl-src">数字是示意。</p>  <p class="vl-src">John Snow, 1855，公有领域，Wikimedia Commons</p>
<!-- 注意：.vl-note 是笔记框 textarea 的类，不能拿来写旁注；旁注专用类 kit 里暂无，现在都用 .vl-src -->
```

### K9 文档道具
- **功能**：把一段叙事做成"一件东西"（案卷、报告、日记、报纸、实验笔记、纸条、信、告示），长文有实体，又不是平涂卡片。

- **内容**：`data-kind` 定外形；正文 ≤2 段，超出就分成两件或配图；纸条 ≤3 行。

### K10 发明故事框
- **功能**：装一个核心概念的发明故事（问题 → 早期尝试 → 关键洞察 → 演化），默认收起，想看的人点开。

- **动效**：反馈类（箭头 ≤200ms）。
- **皮肤**：笔记本＝夹在本子里的折页 + 旧纸色｜纸片＝米黄文件夹纸｜像素＝支线色块｜小镇＝小路岔口路牌。

## 四、图与配图

### T1 插画位
- **功能**：写一个名字，自动换成插图库里的图。图画出"为什么"：正例要素齐全，反例画出缺的那一项。
- **用 / 不用**：所有插画都走它；数据图、概念图解不走它（用 T3、G2）。
- **内容**：每张图全课只用一次；必有 alt；人物规范见 content-rules.md 第二节，三课踩过的坑见 `visuals.md`；文字放在滤镜组外。
- **装载**：`VL.illus.add(名字, alt, 图形, 文字层)` 注册，alt 自动成为 SVG 的 `aria-label`；缺图不报错，显示写着名字的占位 `.vl-illus-miss`；动态插入的内容用 `VL.illus.mount(根)` 或 `VL.enhance(根)` 补装（正例：DS `DS.illus(root)`）；每章插画包 `js/illus-chNN.js` 在 `kit/illus.js` 之后用 `<script>` 引入（kit 现在不按章节表自动加载）。
- **皮肤**：笔记本＝火柴人 + 抖动滤镜 + 平涂色块（viewBox 200×140）｜纸片＝剪纸层叠 + 白裁边 + 三级投影｜像素＝2px 网格像素｜小镇＝离线渲染 PNG。

```html
<span data-illus="c02-eg-tetris"></span>   <!-- alt 写在 VL.illus.add 的第二个参数里 -->
```

### T2 图文并排
- **功能**：长文旁边就有图。
- **规则**：宽屏一栏图（38%）一栏文字，**顶端对齐、不绕排、不垂直居中**；≤700px 上下排（图在上）。图注短，解释写进正文；人像等高图加 `.narrow`（图栏 26%）；默认图在左，`.rev` 图在右。文字比图长很多时，把图换成更高的竖图，或拆成两组并排，不让文字绕到图下。
  反例：GD `.withimg` 垂直居中（`style.css` 第 251 行）；AI `.withimg` 浮动绕排；DS `layout.js` 的 `wi-wrap` 在文字更长时又回到绕排。正例：DS 栅格 38% / 1fr 顶端对齐（DS 另有自己的版式检查脚本，不随 skill 提供；这里用 `tools/shot.mjs` 截 420 / 1100 两张图人眼查）。
- **皮肤**：只改图框（笔记本＝胶带｜纸片＝白边 + 投影｜像素＝墨框硬投影｜小镇＝木相框）。

```html
<div class="vl-withimg">                    <!-- 第一个子元素是图，第二个是文字 -->
  <figure class="vl-fig"><span data-illus="c01-pump"></span><figcaption>……</figcaption></figure>
  <div><p>……</p><p>……</p></div>
</div>
```

### T3 编号图
- **功能**：示意图、概念图解、数据图带"图 N"和图注，正文可以说"见图 3"。
- **内容**：和正文同宽、约 2:1、高 ≤300px；一张图一个强调色；图中字 ≥13px；`role=img aria-label` 写清图里画了什么；**图注写"为什么"**（这张图说明了什么），不复述图里的字；数据图边缘笔直，不加抖动。编号由 vl.js 自动生成，图注前写"图 N"，不要手写；正文用 `<a data-figref="图的id" href="#图的id">图</a>` 回指，自动改成"图 N"；动态加图后调 `VL.figs()`（正例：DS `figure.fig` + `data-n`；反例：GD 内联 SVG 约 120 个无编号无图注）。
- **皮肤**：笔记本＝手绘抖动线、手写图中字｜纸片＝纸片色块、直边数据图｜像素＝像素线 + 深底"图 N"签｜小镇＝蓝图纸。

```html
<figure class="vl-fig" id="fig-axis"><svg role="img" aria-label="……" viewBox="0 0 700 300">…</svg>

```

- **皮肤**：笔记本＝胶带贴在本子上｜纸片＝白相纸 + 胶带｜像素＝三层墨白相框｜小镇＝木框挂画。

## 六、微互动

### M1 预测 → 揭晓
- **功能**：先让读者猜，再揭晓；差距本身就是教学。
- **用 / 不用**：节开头的钩子、发明故事"他们当时怎么办"、模拟前的预测。不能代替招牌互动。
- **模式**（一个组件 `.vl-guess`，`data-mode` 切换；kit/vl.js 现有 think、pick、estimate；cards 用 `.vl-flip`（kit/README.md 第七节“M1 补：翻牌”）；draw、then-run kit 里暂无，要用时在页内自写）：

  | 模式 | 写法 | 正例 |
  |---|---|---|
  | think | 问题 + "看看想法"按钮 + 答案 | 三课 `.reveal` |
  | pick | 选项 chip + 每项各自的反馈（`.right/.wrong/.miss`） | GD `ch17` 先选 |
  | estimate | 滑块（线性 / 对数）+ 你 / 答案两标记 + 偏差 + 评语 | AI `.guess` |
  | draw | 在图上手画曲线 → 真实曲线 + 差值 | AI `ch03` 训练曲线画板 |
  | cards | 2–6 张翻牌 | AI `.flip` |
  | then-run | 选了预测才能点"运行"，结果对照预测 | DS `ch04`、`ch06` |
- **内容**：问题 ≤40 字，答案 ≤2 段；揭晓后要说"为什么"，不只给对错。

## 七、招牌互动骨架

互动设计规则（一句话说清问题、3 秒上手、先预测、可撤销、难玩法进抽屉）在 `interaction.md`，下面只写骨架。

### G1 互动台
- **功能**：所有招牌 / 辅助互动的外壳：问题句 + 试试看 + 舞台 + 控制行 + 读数 + 反馈句 + 重来。
- **内容**：标题就是这台互动要回答的问题（✓"定义检验器：你能写出零错误的定义吗？"）；控件 ≤3 组；必须有"重来"或"撤销"。**全课只有互动台和概念图解用最重的实体感**（粗框、垫层、投影）。
- **控件族**：`.vl-btn`（主；`.alt` 次；`disabled`）、`.vl-chip`（`.on/.right/.wrong/.miss`）、`label.vl-ctl > output + input[type=range]`、分段切换 `role=group` + `.vl-chip[aria-pressed]`、反馈句 `.vl-msg`；触控目标 ≥44px；反馈句 `aria-live=polite`。选中态文字对底 ≥4.5:1（反例：DS 视图切换白字压 accent2，约 1.6:1）。
- **动效**：反馈类（按下 ≤150ms，失败轻抖 280ms）。
- **皮肤**：笔记本＝纸板 + 墨线 + 硬投影｜纸片＝白纸 + 牛皮纸垫层｜像素＝像素框 + 斜边｜小镇＝木边工作台 + 铜牌标题。

```html
<div class="vl-board" id="c05-board">
  <h3>全靠实力还是全靠运气？</h3>
  <p class="vl-try" data-try="luck-90" data-done="……">……</p>
  <div class="c05-stage">…</div>                  <!-- 舞台、控制行的排法写在页内，类名加章节前缀 -->
  <label class="vl-ctl">运气占比 <output>30%</output><input type="range"></label>
  <p class="vl-msg" aria-live="polite">……</p>
  <button type="button" class="vl-btn alt" id="c05-reset">重来</button>
</div>
```

### G2 滑块 + 活图
- **功能**：拖一个参数，图立刻变——"改一个数会怎样"。
- **内容**：滑块两端写白话（"全靠实力 / 全靠运气"）；当前值同时写在读数里；图里一个强调色；1–3 个"现实对照"预设按钮。
- **交互**：原生 range；图只读，`role=img` + 读数 `aria-live`。绘图用一个共享的坐标绘图函数（计划取 AI `M.Plot`；kit 里暂无 `VL.plot()`），不在每章重写 `X()/Y()`（反例：GD 15 章各写一份）。
- **动效**：帮助理解类（拖动时直接重画；预设切换可 300ms 过渡）。

### G3 种子模拟器
- **功能**：一键跑 N 次随机实验，看平均、分布、偶然。
- **内容**：首屏固定种子（`VL.rng(seed)`），保证正文写的数和读者第一次看到的一致（反例：GD `ch14` 用 `Math.random`，正文数字对不上）；"再来一次"换种子；先用 M1 then-run 让读者预测。
- **交互**：再来 N 次 / 重来 / 播放 / 暂停 / 单步。
- **动效**：帮助理解类（逐个落下；减少动态时一次画完）。

### G4 拖拽对象
- **功能**：把东西拖到图上某个位置（位置就是答案），或拖动图里的点 / 线 / 圈看量变化。
- **内容**：落点后显示"参考位置"；拖动中读数实时变。正例：DS `ch03-average-person.html` 九个可拖工资点。
- **交互与键盘**：pointer 事件 + `setPointerCapture` + `touch-action:none`；**必须有键盘替代**：Tab 选中对象，方向键移动，Shift 大步（反例：GD `ch01`、`ch03`、`ch06` 拖拽疑似无键盘）。
- **动效**：反馈类（落点 ≤250ms 淡入参考圈）。

### G5 拼装台（拆 / 拼 / 槽位）
- **功能**：像"拆房子"：把构件一个个拆掉看整体怎么垮，或从调色板挑零件进槽位组成方案。
- **内容**：每个零件有名字和小图；每次操作后整体给看得见的后果（垮、曲线变、警告）；可撤销。正例：GD `ch01-what-is-a-game.html` 拆房子、`ch24-case-mario.html` 槽位（`.sl.full/.warn/.over` 状态最清楚）、GD `ch02` 点一环削弱或拆掉核心循环。
- **交互与键盘**：点零件再点槽位（键盘天然可用），拖动可选；槽位状态用图形 + 文字。
- **动效**：帮助理解类（垮塌、回弹 ≤600ms；减少动态时直接显示结果）。

### G6 动手题引擎（分拣 / 排序 / 配对 / 调到区间 / 逐条判定）

G6–G9 的代码在 `kit/vl-interact.js`，写法见 kit/README.md 第七节；下面写的是要求。

- **功能**：动手归类、排序、连线、把滑块调进区间、一张张判案例；没有失败。
- **内容**：每题 = 题干 + 数据 + `hints:[看哪里, 为什么]` + 对 / 错各一句；打乱后不等于正确顺序；判定题每张写"本书判断 + 理由"。
- **交互与键盘**：拖放 + 点选替代；排序 ↑↓ 按钮；配对点左再点右（①②③编号）；状态用 ✗、虚线框、删除线。错误两级："有 N 张放错了，标了 ✗ 的再想想" → 点名一张说为什么；提示三级：看哪里 → 为什么 → 直接摆好（照样算完成）。正例：DS boss 引擎（它的自测脚本不随 skill 提供；kit 的 `VL.task` 返回 `_solve / _spoil / _next` 自测钩子）。
- **动效**：反馈类（放错轻抖 280ms、放对变绿）。

### G7 分局小游戏
- **功能**：能真玩、能输、几局由易到难；玩法就是概念，最后一局揭示局限，结束有复盘。
- **内容**：默认设置不能不动就赢；复盘写意思不报数；收起时摘要写"几局、约几分钟、可以跳过"。
- **交互与键盘**：`keys` 映射；舞台可聚焦；手机屏幕方向键 `.vl-pad`（3×3，见 kit/README.md 第七节）；按钮 ≥44px；消息 `aria-live`。正例：AI `GD.game`（`ch08` 等 10 章）。
- **动效**：反馈类（输了抖）、激励类（赢了星 / 粒子，交给模块，可关）。

### G8 逐步演示（步进 / 慢放 / 短片）
- **功能**：把过程拆成步骤，可前进、后退、拖到任一步，或看带旁白的短片。
- **内容**：每步说明 ≤2 句；旁白 `aria-live`。三种模式共用一条控制条（◀▶、进度条、⏮ ▶⏸ ⏭、从头）。正例：AI `ch11-backpropagation.html` 一条路三站的步进。
- **动效**：帮助理解类（换步 ≤350ms；减少动态时短片画终态、手动翻页）。

### G9 公式拆解
