# 组件库

用途：每个核心组件做什么、什么时候用、内容怎么写、交互和皮肤样子；排版式、选组件时逐个对照。总规则（节奏、视觉底线、互动底线）在 `SKILL.md`，这里不重复。**组件是装答案的容器**：先在章纲的元素表里写出它服务哪一问或哪种阅读体验（content-rules 第四节），再来这里挑，不要按组件清单往章里放；下面的数字都是默认值（旁边写了为什么），课程可以调整。类名前缀 `vl-`，JS 命名空间 `VL`；下面的 HTML 已按 kit 现有代码写（`kit/vl.js`、`kit/README.md`）；标“kit 里暂无”的，代码还没进 kit，写法只是示意。**API 以 `kit/README.md` 为准**，两处不一致时以代码为准。


## 零、所有组件共守的五条

| # | 规则 | 正例 / 反例 |
|---|---|---|
| 1 | 组件只管结构、交互、无障碍；颜色、字体、描边、纹理由皮肤给。组件里不写死颜色，界面文字走 `VL.t()`，不写进 CSS `::before` | 反例：用 `::before` 写死"一句话总结""例 / 反例"，英文版只能打补丁 |
| 2 | **框也算正文**：任何框里超过 2 段就配图，或拆成"图 + 短文"；概念卡必有图位（`.vl-cc-fig`），原理框等 2 段以内的框，图位（`.vl-why-fig`）有机制可画才留 | 反例：原理框写成 250 字以上的长文却没有图 |
| 3 | 不用 emoji 当图标；图标走插图库小图 | 反例：卡片图标大量用 emoji |
| 4 | 动效按四类（帮助理解 / 反馈操作 / 阅读激励 / 氛围）归档，细则和全部时长见 `interaction.md` 第四节（下面各组件的"动效"只写它属哪一类）；组件自己只播反馈类，激励类只派事件 | 正例：`VL.tryDone()` 只打勾存档，纸屑由别的模块订阅 |
| 5 | 文字长度的通则：以放得进组件、不换行成墙为准，下面不再逐项写字数上限；框里的段数仍按第 2 条。技术底线照旧：图位 ≤240px（更大会把卡片撑成大图配小字）、触控目标 ≥44px 和键盘替代见 `interaction.md` 第三节、图中字 ≥13px、对比度见 `skin-contract.md` 第一节 | 反例：定义写成三行的长句，把概念卡撑成一堵墙 |

各皮肤样子以 `skins/<名>/gallery.html` 为准（田野手账另见 `skins/fieldbook/README.md`）。

## 二、导航

### N1 顶栏
- **功能**：回目录、看全课进度、跳到任一章、开关偏好（动效 自动 / 全开 / 轻量 / 关、语言）。声音开关、激励面板由可选模块加进顶栏，见 kit/README.md 第八节。
- **用 / 不用**：每页都用，vl.js 按章节表（`js/course.js` 的 `VL_COURSE`）和 `<body data-ch>` 自动生成，章节不手写；`data-part` 由 vl.js 写，不用手写。`VL_COURSE.topbar:false` 可关。
- **内容**：只放导航和开关，不放正文提示。全课进度用"迷你图 + 弹层列表"两件套；手机上迷你图可以藏，弹层必须在（手机上若连弹层也藏了就没法跳章）。
- **交互与键盘**：全部是 `button` / `a`；弹层 Esc 关、点外面关、关后焦点回按钮；迷你图里的格子不能 `tabindex=-1` 又 `aria-hidden`。
- **动效**：反馈类。

```html
<body data-ch="3">   <!-- 顶栏 header.vl-topbar 由 vl.js 生成；vl.js 另写 body[data-part]、body[data-pat]、--vl-dh、--vl-chnum -->
```

### N2 章首
- **功能**：一屏内说清第几章、讲什么、读完能做到什么、要多久。
- **用 / 不用**：每章一个。章数 >15 时加"你在这里"小地图（kit 里暂无；顶栏的章节点 `.vl-tb-dots` 和“第 N / 共 M 章”弹层已能跳章）。
- **内容**：徽记（vl.js 自动补“第 N 章”）+ h1 + 副标题 1 句（从处境或反直觉问题出发，不写定义）+ **插画位（必有，走 T1，不手写 SVG）** + 学习目标 3 条（"读完你能……"，各一句）+ 用时。
  反例：题头小画直接写在 HTML 里，没进插图库，没法查重、没法换皮。
- **交互**："你在这里"格子可点跳章。
- **动效**：氛围类，全归皮肤，可关。

```html
<div class="vl-hero">
  <div class="vl-hero-txt"><h1>平均人不存在</h1>
    <p class="vl-sub">一架按"平均飞行员"造的座舱，为什么谁坐都不合适？</p></div>
  <span data-illus="c03-hero"></span>          <!-- 徽记 .vl-badge 缺了自动补 -->
</div>
<div class="vl-goals"><h3>读完你能</h3><span class="vl-time">约 30 分钟</span>
  <ul><li>……</li><li>……</li><li>……</li></ul></div>
```

### N3 分节
- **功能**：把一章切成若干节，每节回答问题链上的一个问题（节数由问题链定），可折叠。
- **用 / 不用**：每章都用。**小标题不挂"是什么 / 发明故事……"层级标签**，五层只用于写作自检（`.tag.what/.why` 这类层级标签不进库）。
- **内容**：h2 的写法见 `zh-teaching-prose` 的"章名和小标题"（唯一保留处）。✗"调参的目标是让损失最低，损失是给一组参数打的分"（塞了两个概念）；✓"《文学文摘》的民调败给了选择偏差"。每节从问题或处境开始。
- **交互与键盘**：点标题 / Enter / 空格折叠；`role=button aria-expanded`；打印前全展开。
- **动效**：反馈类（内容显隐不做高度动画）。

```html
<div class="vl-sec"><h2>《文学文摘》寄出了一千万张明信片</h2></div>
<p>……这一节的内容直接跟在后面……</p>
<!-- .vl-sec 必须是 <main> 的直接子元素；到下一个 .vl-sec 或 .vl-pager 之前的内容由 vl.js 收进 .vl-sec-body，节号 .vl-n 自动加 -->
```

### N4 章内目录与阅读进度
- **功能**：跳到任一节、一键全部展开 / 收起、回顶部、看读到哪了。
- **用 / 不用**：分节 ≥2 自动出现（右下浮钮 `.vl-fab` → 面板 `.vl-navpanel`；顶端进度条 `.vl-readbar`）。皮肤可以把它画成塔楼梯、窄栏，功能和键盘行为不变（换形态时要单独测窄屏）。
- **内容**：目录项就是 h2 原文；当前节判定统一"顶边过视口 35%"。
- **交互与键盘**：浮钮 → 面板；Esc / 点外面关；点链接先展开那一节再滚过去。
- **动效**：反馈类。
- **注意**：阅读进度条只显示位置，**不触发任何奖励或"已读"记录**（见 `modules.md` 第一节"明确不做"）。

### N5 章末导航
- **功能**：上一章 / 下一章（`nav.vl-pager`，vl.js 自动生成）；有概念关系图时加"相关章节"（先修与原理 / 延伸与应用 / 对照与关联，`modules/vl-concepts.js` 生成，见 kit/README.md 第八节）。
- **内容**：不预告后面章节的内容；未开放的章（章节表里 `open:false`）不给链接，翻页处写"第 N 章还在写"并回目录。
- **动效**：反馈类；跨页过场属氛围，可关。

## 三、讲概念

### K1 概念卡
- **功能**：把一章的核心概念（个数由难度分定，见 content-rules 一A）"立起来"，读者一眼知道这一章在讲什么。用户最看重的组件之一。
- **用 / 不用**：每个核心概念一张，放在**概念首次被命名处**（读者已经见过处境和例子之后）；次要概念不用卡，用 K7 起名标记。
- **内容**（固定字段，卡内不写第二段）：

  | 字段（类名） | 写什么 |
  |---|---|
  | 名称 `.vl-cc-name` | 通行名，大字，短 |
  | 原文名 / 组成 `.vl-cc-en` | 英文原名，或"由哪几项组成"，1 行 |
  | 出处 `.vl-cc-by` | 一个人 · 一本书或论文 · 年份；**只写一个名字**，不堆学者；1 行，可省 |
  | 通俗地说 `.vl-cc-plain` | 大白话的一句（小签"通俗地说"自动加） |
  | 定义 `.vl-cc-def` | 一句定义，皮肤加粗 |
  | 例子 `.vl-cc-eg` | 回指正文里已经讲过的那个例子（可以就是贯穿全章的主例子），用一句，不新开例子，也不把例子再讲一遍（小签"例子"自动加） |
  | **图位 `.vl-cc-fig`（必有）** | 画出要素或机制的小图（不是装饰角标），≤240px；宽屏在右、窄屏（≤700px）按源码顺序排，模板里写在最后，所以在卡底；没有专门的图时写"看图 3"并给缩略图。缺了 vl.js 显示红色"缺概念图"占位并 console.warn |

  正例：字段齐全、用 `<aside aria-label>`。反例：卡片没有图位；道具角标只是装饰，不算解释图。
- **重复规则**：概念卡的例子只写一句回指，不重讲（同一个例子的重复规则见 `SKILL.md` 第一节第 5 条第 6 款）。
- **交互**：无；阅读激励模块可在"读懂后"点亮它，触发条件见 `modules.md` 第一节。
- **动效**：无（激励挂钩除外）。

```html
<aside class="vl-cc">                         <!-- 顶边小签"概念卡"（data-tag 可改）和 aria-label 自动加 -->
  <p class="vl-cc-name">核心循环</p>
  <p class="vl-cc-en">Core loop</p>
  <p class="vl-cc-by">（可省）一人 · 一书 · 年份</p>
  <p class="vl-cc-plain">玩家一遍遍重复的那组动作。</p>
  <p class="vl-cc-def">玩家在游戏里反复做的一串事情，做完回到起点，再来一轮。</p>
  <p class="vl-cc-eg">开头那局俄罗斯方块。</p>
  <div class="vl-cc-fig"><span data-illus="c02-cc-loop"></span></div>
</aside>
```

### K2 并列卡阵
- **功能**：一个概念下 3–7 个同级要素或类型并排看（少于 3 个不必成阵，多于 7 个一眼数不过来，要分组）。
- **用 / 不用**：要素、分类、"可带走的经验"；不用于长文，不用于正反对比（用 E2），有层级或因果的用图解（`diagrams.md`）。
- **内容**：每张 = 小图（必有，插图库，不用 emoji）+ 名称 + 一句话；同组同一画法。
- **交互**：默认静态；可选"点一张看详情"（即 M2 的卡片版）。

```html
<!-- kit 里暂无卡阵组件；现在用等宽栅格 .vl-grid2/3/4 排（≤700px 变单栏），卡片外观写在页内、类名加章节前缀 -->
<div class="vl-grid3">
  <div class="c03-card"><span data-illus="c03-mot-a"></span><b>自主</b><p>……</p></div>
</div>
```

### K3 原理框
- **功能**：讲"为什么成立"：一条原理 + 出处 + 一个能亲手验证的实验，必要时一句争议。
- **用 / 不用**：有一条值得单讲、能标出处的"为什么"时用（难度 ≥2 的核心概念默认讲到这一层，不一定用框），挂在具体现象之后；不放定义（定义进 K1）。
- **内容**：标题是一句原理（不写"原理"二字）；**正文 ≤2 段**（框也算正文，见第零节第 2 条）；有机制可画就留**图位**（`.vl-why-fig`：示意图、真实图片或上方互动的缩略图；代码不强制，缺了不报错，靠检查第 3 步配图密度兜底）；小签"为什么成立"自动加；出处行 = 谁 · 哪项研究 · 年份 + "验证：上面的××"；争议一句："也有人不同意：……（某某）"。
  正例：出处里写"验证：上面的模拟器"。反例：带投影的平涂长文卡（版式见 `SKILL.md` 第二节）。
- **外形**：轻块（页边竖线 + 小签），不是浮起来的卡片。

```html
<div class="vl-why">                          <!-- 有 .vl-why-fig 时宽屏两栏，图 34% 在右 -->
  <h3>大脑对"比预期好"反应最强</h3>
  <div class="vl-why-fig"><span data-illus="c02-why-rpe"></span></div>
  <p>……（≤2 段）</p>
  <p class="vl-src">舒尔茨的猴子实验，1997。验证：上面的抽卡模拟。</p>
</div>
```

### K4 演化链
- **功能**：把"问题 → 方案 → 新问题 → 新方案"画成一串，让读者看到概念是被逼出来的。
- **用 / 不用**：发明故事的骨架、状态转移；没有先后因果的并列内容不用（用 K2）。
- **内容**：3–5 个节点（只留推动故事的，多了读者记不住，少了看不出"逼出来"的过程；带年份、每节点配大图的版本是 T5，节点数规则相同）；每节点 = 小图 + 一句话。先给前两个节点让读者猜下一个（接 M1），再揭晓。
- **交互**：可选逐个揭晓（"然后呢？"按钮；kit 里暂无，现在是静态链）。宽屏横排，≤600px 自动竖排、箭头朝下。
- **动效**：帮助理解类（依次出现；关掉动效直接显示全部）。

```html
<ol class="vl-chain">
  <li><span data-illus="c03-ev1"></span>七次观测对不上一条轨道</li>   <!-- 节点配图：插画放 data-illus，照片放 <span class="vl-chain-img"><img …></span>，最宽 200px；图里少放字 -->
  <li class="vl-chain-ar" aria-hidden="true">→</li>
  <li>……</li>
</ol>
```

### K5 立场卡（哲学时刻 / 争议）
- **功能**：一个真正值得想的问题，先表态，再翻看 2–3 种立场（标明是谁的观点），最后留开放问题。
- **用 / 不用**：本章概念引出一个真问题时用（频率见 content-rules 第一节第 12 条）；有标准答案的题不用。
- **内容**：第一张 = 问题 + 表态按钮；中间每张一种立场，≤2 段、可带图，立场名写观点不写人名（"规则先于游戏"），人名放出处行；最后一张 = 开放问题，可接 P3。
- **交互与键盘**：表态 `aria-pressed`、可改票，翻到立场页时回显"你选的是……"；◀▶ / ←→ / 横滑 / 带立场名的圆点；打印全展开。
  写法见 kit/README.md 第七节 K5（`.vl-philo` / `.vl-vote`）。
- **动效**：反馈类（翻页）。

### K6 收束块（常见误区 / 要点 / 一句话）
- **功能**：章末收紧理解：纠正最常见的错想法、列带走的东西、压成一句话。
- **内容**：误区每条 = 错想法原句（加粗）+ 为什么错 1–2 句；要点 3–5 条，各一句；一句话压成一句。**标签文字写在 HTML 里**（如 `<p class="tldr"><b>一句话</b>：…</p>`）。误区多于 3 条时改成 M1 翻牌"你也这么想过吗"。

```html
<div class="vl-misc"><p><b>"随机就是均匀"</b>——……</p></div>
<div class="vl-key"><p><b>要点</b></p><ul><li>……</li></ul></div>
<p class="vl-tldr"><b>一句话</b>……</p>      <!-- 皮肤把第一个 <b> 排成小标签 -->
```

### K7 行内标记（术语释义 / 起名 / 着重）
- **功能**：新术语当场看一句释义；概念第一次起名被看见；一段里最要紧的一句被看见。
- **内容**：术语首次出现用 `.vl-term`，`data-def` 一句话、不重复术语名（`data-name` 可改释义框标题）；概念首次起名、着重号一段最多两处，不用 `<b>` 堆强调（起名用 `<span class="vl-cn">`，皮肤画成荧光笔，只给核心概念和次要概念第一次被命名处；着重用 `<span class="vl-em">`，笔记本皮肤画成着重号、英文页画成下划线；普通 `<b>` 只是加粗，不当起名用）。核心概念的名字四处凸显、保持一致，见 SKILL.md 第一节第 4 条。术语表和汇总术语数据的做法见 `modules.md` 第四节。
- **交互与键盘**：`tabindex=0`（vl.js 自动加）；悬停 / 聚焦 / 轻点切换；Esc、滚动关闭；释义框用 JS 定位，夹在视口内、上下自动翻（反例：纯 CSS `::after` 在屏幕边缘出屏）。
- **动效**：反馈类（可无动画）。

```html
<span class="vl-term" data-def="把一类东西里挑过的样本当成全体">选择偏差</span>
<span class="vl-cn">核心循环</span>   <!-- 起名：荧光笔，只用于概念第一次被命名 -->
<span class="vl-em">最里面的循环不好玩，外面再多层也转不起来</span>   <!-- 着重：一段最多两处 --> 
```

### K8 旁注与出处
- **功能**：放不进主线但有用的一句话、出处、"示意"声明、操作提示。
- **内容**：旁注只放一两句，放得进几行；出处跟在图、原理框、引用后；教学用示意模型必标"示意"。小字的对比度和字重见 `skin-contract.md` 第一节"对比度"。

```html
<p class="vl-src">数字是示意。</p>  <p class="vl-src">John Snow, 1855，公有领域，Wikimedia Commons</p>
<!-- 注意：.vl-note 是笔记框 textarea 的类，不能拿来写旁注；旁注专用类 kit 里暂无，现在都用 .vl-src -->
```

### K9 文档道具
- **功能**：把一段叙事做成"一件东西"（案卷、报告、日记、报纸、实验笔记、纸条、信、告示），长文有实体，又不是平涂卡片。
- **用 / 不用**：开场钩子、案例、发明故事的原始现场；一章里别堆多件（默认 ≤2：每件都是一整块实体，堆多了又成一排卡片）；不用于原理讲解。
- **内容**：`data-kind` 定外形；正文 ≤2 段，超出就分成两件或配图；纸条只写几行。
- **动效**：无（轻微旋转是静态皮肤）。

写法和五种 `data-kind`（file / news / diary / letter / lab）见 kit/README.md 第七节 K9，外观在皮肤的 `interact.css`；五套皮肤的 CSS 都画了这五种，fieldbook 另有 ticket / clipping / copy（见它的 README）；哪些摆进了展示页以各 `gallery.html` 为准。

### K10 发明故事框
- **功能**：装一个核心概念的发明故事（问题 → 早期尝试 → 关键洞察 → 演化），默认收起，想看的人点开。
- **用 / 不用**：每个核心概念最多一个。**正文主线里保留一两句关键洞察**（读者不展开也知道"它为什么非发明不可"），细节、时间线、人物进框。
- **内容**：
  - 收起时露：类型签"发明故事" + **具体问题式标题**（✓"1898 年，一只猫被关进笼子：奖励规律是怎么被发现的"；✗"你想穿越历史重新踏上冒险吗？"）+ 一句介绍（说清里面有什么）+ 展开按钮。
  - 展开后：受"框也算正文"约束（第零节第 2 条），用 K4 演化链、T5 时间线、T6 漫画或 T4 真实图片分担；人名只留推动故事的一两个。
- **交互与键盘**：同 P4（原生 `details/summary`，记住展开状态，打印全展开）。
- **动效**：反馈类。

```html
<p>……正文里一两句关键洞察……</p>
<details class="vl-story">
  <summary><b>1898 年，一只猫被关进笼子：奖励规律是怎么被发现的</b><small>桑代克的迷笼和一条学习曲线。</small></summary>
  ……   <!-- 类型签"发明故事"（data-tag 可改）、"展开 ▾ / 收起 ▴"按钮自动加；内容自动收进 .vl-side-body -->
</details>
```

## 四、图与配图

### T1 插画位
- **功能**：写一个名字，自动换成插图库里的图。图画出"为什么"：正例要素齐全，反例画出缺的那一项。
- **用 / 不用**：所有插画都走它；数据图、概念图解不走它（用 T3、G2）。
- **内容**：同一张图全课只用一次（见 `SKILL.md` 第一节第 5 条第 6 款）；必有 alt；人物规范见 content-rules.md 第二节，插画画法的坑见 `visuals.md`；文字放在滤镜组外。
- **装载**：`VL.illus.add(名字, alt, 图形, 文字层, 选项)` 注册（竖版画布用选项 `{vb}`，见 `kit/README.md`"插画位"），alt 自动成为 SVG 的 `aria-label`；缺图不报错，显示写着名字的占位 `.vl-illus-miss`；动态插入的内容用 `VL.illus.mount(根)` 或 `VL.enhance(根)` 补装；每章插画包 `js/illus-chNN.js` 在 `kit/illus.js` 之后用 `<script>` 引入（kit 现在不按章节表自动加载）。

```html
<span data-illus="c02-eg-tetris"></span>   <!-- alt 写在 VL.illus.add 的第二个参数里 -->
```

### T2 图文并排
- **功能**：长文旁边就有图。
- **规则**：宽屏一栏图（38%）一栏文字，**顶端对齐、不绕排、不垂直居中**；≤700px 上下排（图在上）。图注短，解释写进正文；人像等高图加 `.narrow`（图栏 26%）；默认图在左，`.rev` 图在右。文字比图长很多时，把图换成更高的竖图，或拆成两组并排，不让文字绕到图下。
  反例：垂直居中；浮动绕排；文字变长时又回到绕排。正例：栅格 38% / 1fr 顶端对齐；用 `tools/shot.mjs` 截 420 / 1100 两张图人眼查。

```html
<div class="vl-withimg">                    <!-- 第一个子元素是图，第二个是文字 -->
  <figure class="vl-fig"><span data-illus="c01-pump"></span><figcaption>……</figcaption></figure>
  <div><p>……</p><p>……</p></div>
</div>
```

### T3 编号图
- **功能**：示意图、概念图解、数据图带"图 N"和图注，正文可以说"见图 3"。
- **内容**：和正文同宽、约 2:1、高 ≤300px；一张图一个强调色；图中字 ≥13px；`role=img aria-label` 写清图里画了什么；**图注写"为什么"**（这张图说明了什么），不复述图里的字；数据图边缘笔直，不加抖动。编号由 vl.js 自动生成，图注前写"图 N"，不要手写；正文用 `<a data-figref="图的id" href="#图的id">图</a>` 回指，自动改成"图 N"；动态加图后调 `VL.figs()`（反例：内联 SVG 无编号无图注）。

```html
<figure class="vl-fig" id="fig-axis"><svg role="img" aria-label="……" viewBox="0 0 700 300">…</svg>
  <figcaption>同一份数据，切掉纵轴起点后差距看起来翻了十倍。</figcaption></figure>
```

### T4 真实图片
- **功能**：历史人物、实物、地点、论文页的真实照片，让读者相信"这真发生过"。用户希望多用。
- **内容**：只用公共领域 / CC，下载到本地；图注 = 一句说明 + 作者、授权、来源；登记进课程项目文档的"图片来源清单"（图多时 `img/CREDITS.md`）。流程见 `visuals.md`。人像放进 `.vl-withimg.narrow`。
  正例：历史地图 + 人物肖像 + 实物照片。反例：整门课没有一张真实图片。
- **交互**：可选点开大图。

```html
<div class="vl-withimg narrow">
  <figure class="vl-fig photo"><img src="img/ch01/john-snow-portrait.jpg" alt="约翰·斯诺肖像照">
    <figcaption>约翰·斯诺，约 1856 年。<span class="vl-src">Wellcome Library，公有领域</span></figcaption></figure>
  <div><p>……</p></div>
</div>
```

### T5 带图时间线
- **功能**：发明故事的节点按年份排开，每个配够大的小图（K4 演化链的带年份版本，节点数和取舍见 K4）。
- **用 / 不用**：放在 K10 发明故事框或 P4 支线里，默认收起；正文不放完整时间线。
- **内容**：每节点 = 年份 + 小图（必有，≥120px 宽，更窄的图里东西看不清）+ 一两句；只留推动故事的节点。
  正例：每个节点都带图。反例：时间线无图；时间线全部展开。
- **交互**：一次看一个节点，窄屏横滑（scroll-snap；kit 里暂无，现在是竖排列表，≤600px 图在上）。

```html
<div class="vl-timeline">
  <div class="vl-ev hasimg"><span data-illus="c01-tl-1854"></span><div><b class="vl-yr">1854</b> ……</div></div>   <!-- 带图加 .hasimg -->
</div>
```

### T6 漫画分镜
- **功能**：把一段过程或故事拆成 2–4 格；"框内超过 2 段"（第零节第 2 条）时最自然的改法。
- **用 / 不用**：发明故事现场、过程、误会；不用于抽象原理。
- **内容**：每格 = 插画 + 一句短旁白；整体 `aria-label` 一句概括。这个组件很少用到，写作时遇到"一个人做了一件事，接着发生了另一件事"的长段，先考虑它。
- **动效**：帮助理解类（滚到时逐格亮起；关掉就全亮）。

写法见 kit/README.md 第七节 T6。

### T7 读数条与图例
- **功能**：几个量并排用横条比（随操作变长变短），单个量用仪表，图例用"形状 + 文字"。
- **内容**：每行 = 名称 + 条 + 数值；图例每项有形状差异（实线 / 虚线 / 点 / ✓）。数值 `aria-live=polite`。反例：每章各写一份横条。
- **动效**：帮助理解类（条长过渡；关掉直接到终值）。

```html
<!-- kit 里暂无，下面是示意 -->
<div class="vl-bars" data-rows='[{"nm":"实力","v":0.7},{"nm":"运气","v":0.3}]'></div>
<ul class="vl-legend"><li data-shape="solid">实际</li><li data-shape="dash">预期</li></ul>
```

### T8 表格与横滚包
- **功能**：≤8 行的对照表、真值表（再长手机上要滚很久，改成分组或横滚包）；手机上宽表 / 宽图横滚而不撑破页面。
- **内容**：不做符号表；表头用 accent；可点一行高亮（接 M2）。横滚包 `tabindex=0` 可键盘滚动。

```html
<div class="vl-scroll" tabindex="0"><table class="c05-tbl">…</table></div>   <!-- .vl-scroll 在 kit 里；表格样式 kit 里暂无，写在页内 -->
```

## 五、例子

### E1 例子轮播
- **功能**：一个概念的多个例子横向切换，省纵向长度。例子数量和反例（"差一点"）的要求见 `content-rules.md` 第一节第 7 条。
- **内容**：每张 = 插画（默认配，反例画出缺的那项；学术课的例子可以是算式、数据图或原文摘录）+ ≤2 段；页签用短词（`data-t`）；反例加 `.bad`，靠文字签 + 图形区分，不只靠颜色。宽屏带图时两栏。例子不在别处重复讲。只有一个例子时不用 `.vl-eg`（单个 `.vl-eg` 会把图撑成半屏），用 `.vl-withimg` 图文并排。

```html
<div class="vl-eg" data-t="俄罗斯方块"><span data-illus="…"></span><p>……</p></div>
<div class="vl-eg" data-t="消消乐"><span data-illus="…"></span><p>……</p></div>

<!-- 连续的 .vl-eg 自动合成轮播 -->
```

### E2 对比
- **功能**：正反、前后、两类并排看；或用一条拖线在同一位置揭开两张图。
- **用 / 不用**：两类区分、改前改后；三类以上用 K2。
- **内容**：两栏各配图；正反用文字标签 + ✓ / ✗ 区分。反例：每章各写一份两栏。
- **交互与键盘**：拖线模式 `role=slider`，←→ Home End，pointer capture。
- **动效**：帮助理解类（拖线首次出现晃一下提示，可关）。

```html
<div class="vl-vs"><div><b>✓ 有反馈</b>…</div><div class="bad"><b>✗ 没反馈</b>…</div></div>   <!-- 反面加 .bad（虚线） -->
<!-- 拖线对比：kit/README.md 第七节 E2，分隔线的 role=slider 由 vl-interact.js 加 -->
<div class="vl-compare" data-mode="slider"><div class="vl-cmp-a bad" data-label="改前">…</div><div class="vl-cmp-b" data-label="改后">…</div></div>
```

## 六、微互动

### M1 预测 → 揭晓
- **功能**：先让读者猜，再揭晓；差距本身就是教学。
- **用 / 不用**：只在能暴露一个错误直觉时用（`interaction.md` 第 3 条）：节开头的钩子、发明故事"他们当时怎么办"、模拟前的预测。不能代替招牌互动，更不能只为清零配图密度的字数计数。
- **模式**（一个组件 `.vl-guess`，`data-mode` 切换；kit/vl.js 现有 think、pick、estimate；cards 用 `.vl-flip`（kit/README.md 第七节“M1 补：翻牌”）；draw、then-run kit 暂无，需页内自写）：

  | 模式 | 写法 | 正例 |
  |---|---|---|
  | think | 问题 + "看看想法"按钮 + 答案 | `.reveal` |
  | pick | 选项 chip + 每项各自的反馈（`.right/.wrong/.miss`） | 先选 |
  | estimate | 滑块（线性 / 对数）+ 你 / 答案两标记 + 偏差 + 评语 | 估数后看偏差 |
  | draw | 在图上手画曲线 → 真实曲线 + 差值（kit 暂无，需页内自写） | 某课例：训练曲线画板 |
  | cards | 2–6 张翻牌 | `.flip` |
  | then-run | 选了预测才能点"运行"，结果对照预测（kit 暂无，需页内自写） | 先猜再跑 |
- **内容**：问题一句话，答案 ≤2 段；揭晓后要说"为什么"，不只给对错。
- **交互与键盘**：原生按钮 / range；翻牌 `aria-pressed` + Enter / 空格；**draw 必须有键盘替代**（↑↓ 调各段高度，或改成几个滑块）。
- **动效**：反馈类；翻牌 3D 属帮助理解（关掉时直接显示背面）。

```html
<div class="vl-guess" data-mode="estimate" data-min="0" data-max="100" data-answer="62" data-unit="个">
  <p class="vl-q">每 100 个被抽中的人里，有几个会回信？</p>
  <div class="vl-ans">……为什么……</div>
</div>
<div class="vl-guess" data-mode="pick">
  <p class="vl-q">……？</p>
  <ul class="vl-opts"><li data-right>选项<span class="vl-fb">这一项的反馈</span></li><li>…</li></ul>
  <div class="vl-ans">揭晓</div>
</div>
<!-- estimate 的全部属性和 vl:guess 事件见 kit/README.md 第三节"先猜后揭晓" -->
```

### M2 热区图
- **功能**：点图上一块（或表格一行），旁边信息框换成这一块的解释。概念图解"点一层看一层"就用它。
- **内容**：每热区有可读名称；信息框写短（几句）；初始提示"先点一块"。
  正例：套娃图写明"点任意一层，或用 Tab 选中后按回车"；轰炸机弹孔图。
- **交互与键盘**：SVG `g[tabindex=0][role=button]` + Enter / 空格；hover / focus 加粗描边。
- **动效**：反馈类。

概念图解的"点一层看一层"已在 `VL.diagram`（`select:true`，派发 `vl:dgselect`）；通用热区图写法见 kit/README.md 第七节 M2。

### M3 试试看
- **功能**：给每个招牌 / 辅助互动一个明确的小任务，完成时当场确认。
- **内容**：写可观察的目标（"试试看："和小方框由 vl.js 自动加，不要手写）（✓"把误差降到 5% 以下"；✗"玩一玩"）；每个互动 1–3 条；完成条件写在 JS 里，不靠读者自报；默认状态下不能不动就达成。
- **交互**：被动；互动达成时调 `VL.tryDone(id, 可选反馈)`（存档、`data-done`、事件见 `kit/README.md` 第三节"试试看"）。组件只打勾，奖励由激励模块订阅 `vl:try`，只在 `first` 时给。
- **动效**：反馈类（变绿打勾）。

```html
<p class="vl-try" data-try="luck-90" data-done="完成！第一名换人了：运气一大，实力就排不出名次。">把运气调到九成，看第一名还是不是那个最强的人。</p>
```

## 七、招牌互动骨架

互动设计规则（一句话说清问题、3 秒上手、先预测、可撤销、难玩法进抽屉）在 `interaction.md`，下面只写骨架。

### G1 互动台
- **功能**：所有招牌 / 辅助互动的外壳：问题句 + 试试看 + 舞台 + 控制行 + 读数 + 反馈句 + 重来。
- **内容**：标题就是这台互动要回答的问题（✓"定义检验器：你能写出零错误的定义吗？"）；控件默认 ≤3 组（理由和一章大互动的总数见 `interaction.md` 规则 2、14）；读者能把状态搞乱的必须有"重来"或"撤销"（见 `interaction.md` 规则 5）。全课层级见 `skin-contract.md` 第二节末（粗框只给互动台和概念图解）。
- **控件族**：`.vl-btn`（主；`.alt` 次；`disabled`）、`.vl-chip`（`.on/.right/.wrong/.miss`）、`label.vl-ctl > output + input[type=range]`、分段切换 `role=group` + `.vl-chip[aria-pressed]`、反馈句 `.vl-msg`；触控目标和键盘替代见 `interaction.md` 第三节；反馈句 `aria-live=polite`。选中态文字对底的对比度见 `skin-contract.md` 第一节"对比度"。
- **动效**：反馈类（按下、失败轻抖，时长见 `interaction.md` 第四节）。

```html
<div class="vl-board" id="c05-board">
  <h3>全靠实力还是全靠运气？</h3>
  <p class="vl-try" data-try="luck-90" data-done="……">……</p>
  <div class="c05-stage">…</div>                  <!-- 舞台、控制行的排法写在页内，类名加章节前缀 -->
  <label class="vl-ctl">运气占比 <output>30%</output><input type="range"></label>
  <p class="vl-msg" aria-live="polite">……</p>
  <button type="button" class="vl-btn alt" id="c05-reset">重来</button>
</div>
```

### G2 滑块 + 活图
- **功能**：拖一个参数，图立刻变——"改一个数会怎样"。
- **内容**：滑块两端写白话（"全靠实力 / 全靠运气"）；当前值同时写在读数里；图里一个强调色；1–3 个"现实对照"预设按钮。
- **交互**：原生 range；图只读，`role=img` + 读数 `aria-live`。绘图用共享的 `VL.plot()`（G11 活图），不在每章重写 `X()/Y()`（反例：每章各写一份）。
- **动效**：帮助理解类（拖动时直接重画；预设切换可做短过渡）。

### G3 种子模拟器
- **功能**：一键跑 N 次随机实验，看平均、分布、偶然。
- **内容**：首屏固定种子（`VL.rng(seed)`），保证正文写的数和读者第一次看到的一致（反例：用 `Math.random`，正文数字对不上）；"再来一次"换种子；先用 M1 then-run 让读者预测。
- **交互**：再来 N 次 / 重来 / 播放 / 暂停 / 单步。
- **动效**：帮助理解类（逐个落下；减少动态时一次画完）。

### G4 拖拽对象
- **功能**：把东西拖到图上某个位置（位置就是答案），或拖动图里的点 / 线 / 圈看量变化。
- **内容**：落点后显示"参考位置"；拖动中读数实时变。正例：九个可拖的工资点。
- **交互与键盘**：写法和必须有的键盘替代见 `interaction.md` 第三节"拖拽"。
- **动效**：反馈类（落点淡入参考圈）。

### G5 拼装台（拆 / 拼 / 槽位）
- **功能**：像"拆房子"：把构件一个个拆掉看整体怎么垮，或从调色板挑零件进槽位组成方案。
- **内容**：每个零件有名字和小图；每次操作后整体给看得见的后果（垮、曲线变、警告）；可撤销。正例：拆房子；槽位（`.sl.full/.warn/.over` 状态最清楚）；点一环削弱或拆掉核心循环。
- **交互与键盘**：点零件再点槽位（键盘天然可用），拖动可选；槽位状态用图形 + 文字。
- **动效**：帮助理解类（垮塌、回弹；减少动态时直接显示结果）。

### G6 动手题引擎（分拣 / 排序 / 配对 / 调到区间 / 逐条判定）

G6–G9 的代码在 `kit/vl-interact.js`，写法见 kit/README.md 第七节；下面写的是要求。

- **功能**：动手归类、排序、连线、把滑块调进区间、一张张判案例；没有失败。
- **内容**：每题 = 题干 + 数据 + `hints:[看哪里, 为什么]` + 对 / 错各一句；打乱后不等于正确顺序；判定题每张写"本书判断 + 理由"。
- **交互与键盘**：拖放 + 点选替代；排序 ↑↓ 按钮；配对点左再点右（①②③编号）；状态用 ✗、虚线框、删除线。错误两级："有 N 张放错了，标了 ✗ 的再想想" → 点名一张说为什么；提示三级：看哪里 → 为什么 → 直接摆好（照样算完成）。kit 的 `VL.task` 返回 `_solve / _spoil / _next` 自测钩子。
- **动效**：反馈类（放错轻抖、放对变绿）。

### G7 分局小游戏
- **功能**：能真玩、能输、几局由易到难；玩法就是概念，最后一局揭示局限，结束有复盘。
- **内容**：默认设置不能不动就赢；复盘写意思不报数；收起时摘要写"几局、约几分钟、可以跳过"。
- **交互与键盘**：`keys` 映射；舞台可聚焦；手机屏幕方向键 `.vl-pad`（见 kit/README.md 第七节，触控规则见 `interaction.md` 第三节）；消息 `aria-live`。
- **动效**：反馈类（输了抖）、激励类（赢了星 / 粒子，交给模块，可关）。

### G8 逐步演示（步进 / 慢放 / 短片）
- **功能**：把过程拆成步骤，可前进、后退、拖到任一步，或看带旁白的短片。
- **内容**：每步说明 ≤2 句（一步只讲一件事，说不完就是该拆步）；旁白 `aria-live`。三种模式共用一条控制条（◀▶、进度条、⏮ ▶⏸ ⏭、从头）。
- **动效**：帮助理解类（换步；减少动态时短片画终态、手动翻页）。

### G9 公式拆解
- **功能**：公式片段和白话解释同色联动（数学五级台阶第 4 级，见 `optional-ai-math.md` 第二部分）。
- **内容**：紧跟它所属概念的图或互动；每片段一色、淡底圈出（不用下划线）；解释每行 = 读法 + 意思 + 在例子里等于多少；全课量的颜色编码 `--q1…--q6` 固定，正文、公式、图同色。推导进 P4。
- **交互与键盘**：悬停 / 聚焦 / 点击钉住，两边同时高亮、其余变淡；解释行可 Tab（kit 自动加）。某课例：损失函数 J 的拆解，J、d² 各一色，读者悬停公式片段，白话行同色亮起。
- **动效**：帮助理解类（只变透明度）。

写法（`data-k` 取 1–6，KaTeX 的 `\htmlClass{vl-k3}` 也认）见 kit/README.md 第七节 G9。

### G10 选格子
- **功能**：一排排可点的格子，读者点格子做选择，格子随之划掉、高亮或标出命中：猜数、选座位、日历、棋盘、抽样。
- **用 / 不用**：选项本来就排成网格、位置有意义时用；只有三五个并列选项用按钮或 chip。手机上 10 列每格约 30px，格子多时减列。
- **写法**：`VL.cells(容器, { n, cols, label, onPick, name })`（`name` 写容器的 `aria-label`，缺省按页面语言补默认），见 `kit/README.md` 第七节"G10 选格子"。正例：`examples/pixel-binary-search` 的 10×10 猜数格（页内实现，写法同理）。
- **交互**：方向键走格、回车选中；状态类 `is-out / is-last / is-hit / is-sel`。
- **皮肤**：结构样式在 `kit/vl-interact.css`，各皮肤可在 `interact.css` 里覆盖 `.vl-cell` 外观。

### G11 活图
- **功能**：坐标图：柱状图、折线图（可柱线混排）、分布、增长曲线、对比；配 G2 滑块时一拖就重画。
- **用 / 不用**：要读出"多少、怎么变"时用；讲结构、关系用概念图解（`diagrams.md`）。一张图 ≤3 个系列。
- **写法**：`VL.plot(容器, 配置)`，按需引 `kit/vl-plot.js` + `kit/vl-plot.css`，选项和行为（轴、`marks` 标注自动避让、`hi` 高亮、`aria`、手机字号）见 `kit/README.md` 第七节"G11 活图"。滑块联动由页面自己在 `input` 事件里调 `p.set(…)`；标签文字写短。
- **无障碍**：图只读；读数另写在 `aria-live` 的反馈句里；颜色不是唯一信息（图例、虚线、点形由 kit 给）。
- **皮肤**：颜色全走皮肤变量（系列 `--q1…`，轴和字 `--ink`，高亮 `--accent`）。

G2–G9 的外观都随 G1 互动台；舞台内的图形按当前皮肤的画法。

## 八、练习与收起

### P1 章末测验
- **功能**：检验学习目标（题数和题型要求见 content-rules.md 一A）。选择题只放练习，见 `interaction.md` 第二节规则 12。
- **内容**：每题 `{q, opts, a, why, fixed, img}`，带解析；选项按章号 + 题号种子洗牌（`fixed:true` 不洗），洗完正确项一定不在原位；查"正确项总是最长"（skill 里没有现成脚本，交付前逐题看一遍）；题目可带图（`img`）。
- **交互与键盘**：一次一题横翻（◀ 圆点 ▶ / ←→，圆点三态 `.tried` 答错过 / `.ok` 答对 / `.on` 当前）；错项划掉禁用并轻抖、对项显示解析。作答两种：点选项（`mode:"pick"`）；或把答案卡拖进答题位（`mode:"drag"`：点选卡片 + 在答题位按回车放入）。全对记"读懂了"并派发 `vl:quiz-perfect`（`progress:false` 不记），细节见 `kit/README.md` 第三节"测验"。
- **动效**：反馈类；全对庆祝交给激励模块。

```html
<div id="c05-quiz"></div>          <!-- .vl-quiz 由 VL.quiz 加 -->
<script>VL.quiz('#c05-quiz', [{q:'…', opts:['…','…'], a:0, why:'…'}], { mode:'pick' });</script>
```

### P2 篇末综合关
- **功能**：分篇的课，每篇最后一章：本篇知识地图 + "你现在能看懂什么" + 跨章综合动手题。
- **内容**（代码在 `kit/vl-interact.js`，见 kit/README.md 第七节）：地图用 `diagrams.md` 的网络 / 流程模板，节点可点回章节；综合题默认 3 回合（每回合拆一条错误论断，3 条够覆盖一篇的主线又不拖；篇短可减为 2），题型用 G6；无血条、不计分、无失败。正例：篇末回顾关、守关回合。"守层者 / BOSS"是皮肤外观。

### P3 笔记框
- **功能**：写下自己的想法，自动保存。
- **内容**：跟在开放问题（哲学时刻）或"你的设计"任务后；placeholder 给一个具体开头；存档键由 vl.js 拼（规则见 `kit/README.md` 第三节"笔记框"），`data-save` 只写这一章里的短名，不手写"chN"（反例：沿用别章的短名，两章笔记互相覆盖）。
- **交互**：输入即存，停手 0.5 秒显示一行"已保存"。

```html
<textarea class="vl-note" data-save="reflect" placeholder="我会先改的是……"></textarea>
```

### P4 选读支线
- **功能**：次要内容默认收起，只露钩子；想深挖的点开。
- **用 / 不用**：时间线、延伸、推导、补充案例、原始文献、可跳过的大游戏；有这类内容时用，个数由内容定；正文主线不放进去。发明故事用 K10。
- **内容**：摘要 = 类型签（`data-kind`：history 历史 / math 数学 / play 多玩一会儿 / debate 争议 / source 原始文献 / extra 加练 / more 延伸，自动加）+ 具体问题式标题 + 一句介绍 + 展开按钮（自动加）；内文同样受"框也算正文"约束。
  正例："1854 年，已经有人在显微镜下看到了霍乱细菌 / 看到了细菌，为什么还没人把它当成病因"。
- **交互与键盘**：原生 `details/summary`；默认收起，记住展开状态；打印全展开；按页编号"支线 N"（kit 里暂无）。

```html
<details class="vl-side" data-kind="math">
  <summary><b>高斯到底有没有用最小二乘？</b><small>一封信、一场优先权之争。</small></summary>
  ……   <!-- 类型签、展开按钮、.vl-side-body 自动加 -->
</details>
```

## 九、候补组件

候补 = 有价值但只在少数课用到；需要时先在一章里验证再进核心。

| 候补 | 做什么 | 进核心前要补的 |
|---|---|---|
| 引语卡 | 一句关键原话单独排出 | 各课按项目文档决定能不能用 |
| 大数字 | 一个惊人的数，滚到终值 | RM 时直接显示终值；一章一个就够，多了就不惊人 |
| 人群方阵 | 100 个小人表示比例 | 小人画法随皮肤 |
| 场景过场条 | 节与节之间一条小场景 | 先证明它帮理解 |
| 自查清单 | 读者对照自己的设计逐条打勾 | 抽 `VL.checklist(el,key)` |
| 代码实验室 | 改代码、Ctrl+Enter 运行 | 输出要画成图或一句话，不吐一串数字 |
| 网格编辑 | 点 / 拖过格子涂格 | 键盘涂格 |
| 生成器 | 填表 → 文档，可复制 / 打印 | — |
| 回放标注 | 拖时间轴 + 打类型标签 | 并入 G8 scrub |
| 感知模拟 | 取色、键位、听声、反应计时 | 领域专用；声音默认静音 |
| 反事实卡组 | 并列的"如果"情形，点一个看故事 | 每条标"想象"；可键盘 |
| 案例拆解面板 | 点一个学过的概念，看它在案例里的体现 | 是 M2 的固定用法，三章 CSS 合一 |
| 原始文献卡 | 论文 / 书页 + 一句"它说了什么" | 作 P4 `data-kind="source"` 的内文 |
