# 互动课程工具箱（course-kit）

这套规矩来自多门已经做完的互动课程，经用户逐轮验收。目标：普通人读起来**舒服、看得懂、有趣**，画面和谐，不像 AI 拼出来的。

分工：内容怎么讲（五层、验收数字、工作流）在 `references/content-rules.md`（可整份复制进你的项目）；句子怎么写在 `zh-teaching-prose`；**画面、组件、版式、交互、动效**在这里。

## 用之前读什么

| 要做的事 | 读 |
|---|---|
| 定内容怎么讲、验收标准 | `references/content-rules.md` |
| 排一章的版式、选组件 | 本文件 + `references/components.md` |
| 画概念图解 | `references/diagrams.md` |
| 找配图、画插画 | `references/visuals.md` |
| 做互动、加动效 | `references/interaction.md` |
| 加阅读激励、陪伴角色、关系图等 | `references/modules.md` |
| 选皮肤、做新皮肤 | `references/skin-contract.md` + `skins/<名>/README.md` |
| 搭新课骨架 | `starter/README.md`：`node starter/new-course.mjs <课程文件夹绝对路径> <皮肤名>` 一条命令生成；API 见 `kit/README.md` |
| 检查 | 第七节 + `tools/check.mjs` |

## 一、一章的节奏

**一个主题娓娓道来。** 从读者熟悉的处境出发，一层层自然展开，每段接住上一段留下的问题。难度适中：讲到读者"懂了"就停，推导、数学、研究细节进默认收起的抽屉。

**按"这一段在干什么"选视觉**，不按组件的重要性排：

| 这一段在做的事 | 用什么 |
|---|---|
| 抛出处境、勾起兴趣 | 场景插画、漫画格 |
| 讲历史、真人真事 | 真实图片、文档道具、带图时间线 |
| 讲清一个结构或机制（循环、层级、因果、对比、分类） | **概念图解**（`diagrams.md` 的模板） |
| 讲"改一个东西会怎样" | 活图、招牌互动 |
| 举例、举反例 | 例子插画轮播 |
| 点出名字 | 概念卡（带小图） |

判断要不要画图解：这段话里有没有"结构"？有就画图解，没有就用插画或照片。

**让读者随时知道在讲哪个概念。** 每个核心概念四处凸显，名字四处一致：
1. 所在分节的小标题写出概念名（✓"凌晨一点停不下来的核心循环"，✗"凌晨一点的最后一局"）；
2. 正文里概念第一次被命名处套荧光笔起名标记 `<span class="vl-cn">核心循环</span>`，荧光笔只给这里用，不拿来划重点；
3. 紧接着一张带图的概念卡（K1）；
4. 章末要点里再回顾一次。
次要概念只做起名标记，不做卡。一段里要读者记住的那句用着重标记 `.vl-em`，一段最多两处。`tools/check.mjs` 会查：有概念卡却没有同名起名标记或小标题的，报错。

**节奏规则**
1. 每 1–2 段正文就有一个视觉。**框也算正文**：原理框、概念卡、故事框里超过 2 段就要配图，或者拆成"图 + 短文"。
2. 一节的开头和结尾放有温度的图（插画、照片、例子），图解放中间。
3. 不连放两张静态图解，中间隔一个插画、例子或互动。能点、能拖的图解算半个互动。
4. 整章大致配比：图解约三分之一，插画、照片、例子约一半，其余是互动。按课调整（数学多的课图解多，历史多的课照片多）。
5. 次要内容默认收起：发明故事框、完整时间线、延伸、推导、补充案例。只露一个**具体问题式**的钩子标题 + 一句介绍 + 展开按钮。钩子说清里面有什么（✓"1898 年，一只猫被关进笼子：奖励规律是怎么被发现的"），不替读者安排体验（✗"你想穿越历史重新踏上冒险吗？"）。
6. 重复的元素横向翻：例子、练习、时间线卡，一次显示一个。
7. 同一张图全课只用一次；同一个例子不在开场、概念卡、例子卡里讲三遍。

**版式自由组合。** 固定的只有五层内容（写作自检用，小标题不挂层级标签）和导航；其余从组件库里按内容挑，每章不必长得一样。

## 二、视觉的底线

- **只用验收过的皮肤**（`skins/`），不让 AI 自由拼风格。开课时先问用户要哪套（第六节），不替用户默认。新皮肤先做一章样稿给用户验收，过了才进库（流程见 `skin-contract.md` 第五节）。
- **安静的底子**：长文直接排在底上（纸、墙、版面），不在平涂底色上浮一张卡片放长文。只有"东西"才有实体（图、互动台、概念卡、文档道具），带同向投影。
- **粗框只给主角**：招牌互动、概念图解用粗描边；其他用细线或无框。不用 emoji 当图标、渐变字、发光阴影。
- **一章一个主题色**，同篇各章在主色、纹理、题头装饰上小变化，字体和组件形状不变。
- **字体**：装饰字体只给大标题，手写体验证过才用于小标题和图中字，正文用清晰字体；细则见 `skin-contract.md` 第一节"字体规则"。
- **对比度** ≥4.5:1，包括图注、图中文字、选中态按钮。
- **图文并排**：宽屏一栏文字一栏图，顶端对齐，不绕排、不垂直居中；窄屏上下排。
- 读者可以切换**配色**（亮、护眼；暗色已有变量但未完整验收）；**皮肤**在开课时定好，因为插画按皮肤画法画。

## 三、互动的底线

- 互动出场前用一句话说清它要回答什么问题；"试试看"写明要做什么，完成时给反馈。
- 控件少，读者 3 秒内知道怎么玩；关键处先预测，再看结果；能撤销、能重来。
- 难的玩法进进阶抽屉。选择题只放在练习里。
- 键盘能用，触屏目标够大。
- 细则见 `interaction.md`。

## 四、动效的底线

按作用分四类，各有规矩（细则见 `interaction.md`）：

| 作用 | 规矩 |
|---|---|
| 帮助理解 | 关掉动效也保留最终状态，信息不丢 |
| 反馈操作 | 150–300ms；减少动态时只留颜色变化 |
| 阅读激励 | 只在读懂后触发一次，不打断阅读 |
| 氛围 | 只在正文以外，默认轻量，可一键关 |

全局尊重 `prefers-reduced-motion`；顶栏"显示"里可选"自动 / 全开 / 轻量 / 关"（三档 + 自动判定，细则见 `interaction.md` 第四节）。

## 五、可选模块（开课时逐项决定，写进项目文档）

- **阅读激励**：机制通用，外观随皮肤（笔记本→集邮册、图鉴、盖章；纸片爬塔→背包、亮灯）。只奖励"读懂了"（答对、完成试试看），不奖励滚动到底或停留时长。
- **陪伴角色**：默认不加。有世界观或读者年纪小时才加（世界观只在简报、题头图、角色台词里露面，正文仍讲概念本身，见 `content-rules.md` 一C）；点击才说话，台词和读到的内容有关，可关，键盘可触发，语气平常。
- **概念关系图**：概念多、彼此牵连时加；和概念卡、图鉴共用一份概念数据。
- 声音、术语表、闪卡、学习路径等，见 `modules.md`。

## 六、开新课的流程

**第一件事是问美术风格。** 用户说"做一门课"时，先用提问工具（AskUserQuestion，没有就直接问）让用户选皮肤，不要默认、不要自己拼风格。每个选项写一句"适合什么课"，有截图就附验收页 `skins/<名>/gallery.html` 的路径：

| 皮肤 | 一句话 | 适合 |
|---|---|---|
| `notebook` 手绘笔记本 | 横线纸、墨线火柴人、色块 | 设计、思维、文科；成人和高中生 |
| `paper` 纸片 | 卡纸剪纸、白裁边、柔和投影，目录页是一座塔 | 有故事、有角色的课；初中到高中 |
| `pixel` 掌机像素 | 四阶绿液晶屏、像素插画、阶梯动效 | 计算、编程、游戏化的课 |
| `fieldbook` 田野手账 | 方格活页纸、彩铅、胶带贴的照片和票根 | 人文、社科、田野和历史类 |

用户要的风格不在表里时，说明只能用验收过的皮肤；要新皮肤就按 `skin-contract.md` 第五节先做一章样稿给用户验收。`examples/` 下有三章用真实内容做的样板章（`paper-survivorship`、`pixel-binary-search`、`fieldbook-gift`），可以给用户看、也可以当样稿的参照。

**第二件事是问课程安排。** 选完皮肤，接着用提问工具一次问完四个问题（选择题，用户点一下就能答）：

| 问题 | 选项示例 |
|---|---|
| 读者是谁 | 零基础成人 / 高中生 / 初中生 / 有基础想深入 |
| 学多久 | 入门短课 5–8 章 / 标准课 15–25 章 / 完整课 25 章以上 |
| 语言 | 只做中文 / 中英双语 / 只做英文 |
| 加哪些模块（多选） | 关系图、术语表、闪卡、集邮册、陪伴角色（第五节） |

**然后交一份课程方案给用户确认**，确认前不生成骨架、不写章：
- 知识地图：分几篇、每篇几章、先学什么；
- 章节表：每章一句话说清讲什么，标出 1–3 个核心概念；章名直接对应核心概念或主题；
- 学完能做到什么（可观察）。
结构铺开后很难改（改编号要全课重映射），所以这一步宁可多问一句。

然后：
1. 内容按 `references/content-rules.md` 写；把读者、章数、语言、模块写进项目文档。
2. 用 `starter/new-course.mjs <课程文件夹绝对路径> <皮肤名>` 生成骨架（kit、皮肤、配置、目录页、第 1 章模板、项目文档模板），改 `js/course.js` 的章节表和模块开关。
3. 做一章样板给用户确认写作、版式、节奏，再铺开。
4. 每章交付前跑检查（见第七节），不能只看汇报；交付后派读者审读（`content-rules.md` 第八节第 5 步）。

## 七、检查（防止"写的时候看不见"的错）

代码是盲写的：字体实际宽度、屏幕宽度、几个文件之间的类名对不对得上，都只有打开页面才知道。所以写完必须跑检查，agent 不能自己跳过；用户明确说"先不测"时可以跳过，但交付时列出未测清单。

**一键检查**（工具都在本 skill 的 `tools/`，必须传绝对路径）：

```
node <skill>/tools/check.mjs <课程文件夹绝对路径> [ch02,ch03] [--fast]
```

| 步 | 查什么 | 抓得到的错 |
|---|---|---|
| 1 语法 | 每个 .js `node --check`，每段内联脚本试编译 | 整页脚本不跑 |
| 2 接线 | JS 去找的 `vl-` 类，页面和脚本里有没有造出来（报错）；页面写的类没有样式也没被脚本用到（只提示） | 改名没同步、按钮没反应、样式不生效 |
| 2b 凸显 | 每张概念卡的名字，正文有没有同名起名标记 `.vl-cn`、小标题有没有写出它 | 概念凸显漏了一处 |
| 3 配图密度 | 两个视觉之间超过约 220 字，或单段超过约 160 字。计法和算作视觉的元素见 `visuals.md` 第四节 | 长文无图 |
| 4 链接 | 本地 href / src 是否存在 | 图片、脚本路径写错 |
| 5 运行 | `qa.mjs`：420 和 1100 宽度下点遍按钮、拖遍滑块 | JS 报错、横向溢出、图内文字压线/出界/重叠 |
| 6 截图 | 每页 420、1100 整页图，存在 `%TEMP%/course-check-shots/<课程文件夹名>/`（英文页前缀 `en-`） | 打印路径，**必须用 Read 打开看** |

`--fast` 只跑 1–4（几秒，不开浏览器），适合边写边查；交付前跑完整版。第 5、6 步要 Edge 或 Chrome，`tools/browser.mjs` 自动找；找不到时把浏览器路径写进环境变量 `EDGE_PATH`。

**脚本之外必须人眼看的**（截图后逐项看）：图解文字是否压线、插画人物是否合规（脚落地、手握物、不悬空，用 `tools/illus-overlap.mjs` 辅助）、配色对比度、一节的节奏是否符合第一节。单张图用 `tools/shot.mjs <html> <png> "选择器@序号" 1100` 截下来放大看；html 后加 `?scheme=sepia`（或 `dark`）截别的配色；整页超过 16000px 时只截到 16000px 并警告，下半截用选择器分段截。

**交付汇报必须写**：跑了哪几步、结果（贴 ✗ 行）、看了哪些截图、没测的项目。"语法通过"不等于"测试过"。

**流程**：写完 → `--fast` 修到 0 → 完整版修到 0 → 看截图 → 修 → 再跑一次 → 交付。主控收到 agent 交付后，自己再跑一次完整版并看截图。

## 八、学新的

**中英两份**：英文版 skill 在 `../course-kit-en/`，两份共用同一套代码（kit、skins、tools、starter），以中文版为准。改了代码就跑 `node tools/sync-en.mjs` 同步过去（`examples/` 不在同步范围内）；改了规则（SKILL.md、references/）就在英文版对应条目同样改一遍。kit/README.md 英文版另有译本，不随 sync-en 同步，改中文版时手动同步。

用户每次对画面、组件、交互的反馈，归纳成一条规则改进对应文件的原条目；新皮肤验收后加进 `skins/`。
