# 互动课程工具箱（course-kit）

这套规矩来自三门已经做完的课：游戏设计课（手绘笔记本）、数据科学课（爬塔纸片）、AI 课（各世界复古媒介）。用户逐条确认过。目标：普通人读起来**舒服、看得懂、有趣**，画面和谐，不像 AI 拼出来的。

分工：内容怎么讲（五层、验收数字）在 `references/content-rules.md`（可整份复制到你的项目当 `CLAUDE.md`）；句子怎么写在 `zh-teaching-prose`；**画面、组件、版式、交互、动效**在这里。

|---|---|
| 定内容怎么讲、验收标准 | `references/content-rules.md` |
| 排一章的版式、选组件 | 本文件 + `references/components.md` |
| 画概念图解 | `references/diagrams.md` |

| 搭新课骨架 | `starter/README.md`：`node starter/new-course.mjs <课程文件夹绝对路径> notebook` 一条命令生成；API 见 `kit/README.md` |
| 检查 | 第七节 + `tools/check.mjs` |

## 一、一章的节奏

**一个主题娓娓道来。** 从读者熟悉的处境出发，一层层自然展开，每段接住上一段留下的问题。难度适中：讲到读者"懂了"就停，推导、数学、研究细节进默认收起的抽屉。

**按"这一段在干什么"选视觉**，不按组件的重要性排：

| 这一段在做的事 | 用什么 |
|---|---|
| 抛出处境、勾起兴趣 | 场景插画、漫画格 |
| 讲历史、真人真事 | 真实图片、文档道具、带图时间线 |
| 讲清一个结构或机制（循环、层级、因果、对比、分类） | **概念图解**（`diagrams.md` 的模板） |
| 讲"改一个东西会怎样" | 活图、招牌互动 |
| 举例、举反例 | 例子插画轮播 |
| 点出名字 | 概念卡（带小图） |

判断要不要画图解：这段话里有没有"结构"？有就画图解，没有就用插画或照片。

**让读者随时知道在讲哪个概念。** 每个核心概念三重凸显，名字三处一致：
1. 所在分节的小标题写出概念名（✓"凌晨一点停不下来的核心循环"，✗"凌晨一点的最后一局"）；
2. 正文里概念第一次被命名处套荧光笔起名标记 `<span class="vl-cn">核心循环</span>`，荧光笔只给这里用，不拿来划重点；
3. 紧接着一张带图的概念卡（K1）。
次要概念只做起名标记，不做卡。一段里要读者记住的那句用着重标记 `.vl-em`，一段最多两处。`tools/check.mjs` 会查：有概念卡却没有同名起名标记或小标题的，报错。

**节奏规则**
1. 每 1–2 段正文就有一个视觉。**框也算正文**：原理框、概念卡、故事框里超过 2 段就要配图，或者拆成"图 + 短文"。
2. 一节的开头和结尾放有温度的图（插画、照片、例子），图解放中间。
3. 不连放两张静态图解，中间隔一个插画、例子或互动。能点、能拖的图解算半个互动。
4. 整章大致配比：图解约三分之一，插画、照片、例子约一半，其余是互动。按课调整（数学多的课图解多，历史多的课照片多）。
5. 次要内容默认收起：发明故事框、完整时间线、延伸、推导、补充案例。只露一个**具体问题式**的钩子标题 + 一句介绍 + 展开按钮。钩子说清里面有什么（✓"1898 年，一只猫被关进笼子：奖励规律是怎么被发现的"），不替读者安排体验（✗"你想穿越历史重新踏上冒险吗？"）。
6. 重复的元素横向翻：例子、练习、时间线卡，一次显示一个。
7. 同一张图全课只用一次；同一个例子不在开场、概念卡、例子卡里讲三遍。

**版式自由组合。** 固定的只有五层内容（写作自检用，小标题不挂层级标签）和导航；其余从组件库里按内容挑，每章不必长得一样。

## 二、视觉的底线

- **只用验收过的皮肤**（`skins/`），不让 AI 自由拼风格。没指定时用 `notebook`（手绘笔记本）。新皮肤先做一章样稿给用户验收，过了才进库。
- **安静的底子**：长文直接排在底上（纸、墙、版面），不在平涂底色上浮一张卡片放长文。只有"东西"才有实体（图、互动台、概念卡、文档道具），带同向投影。
- **粗框只给主角**：招牌互动、概念图解用粗描边；其他用细线或无框。不用 emoji 当图标、渐变字、发光阴影。
- **一章一个主题色**，同篇各章在主色、纹理、题头装饰上小变化，字体和组件形状不变。
- **字体**：书法、粉笔等装饰字体只用于大标题；验证过清晰的手写体（字母数字另配清晰字体，用 `unicode-range`）可用于小标题、图中文字、按钮；正文用清晰字体。
- **对比度** ≥4.5:1，包括图注、图中文字、选中态按钮。
- **图文并排**：宽屏一栏文字一栏图，顶端对齐，不绕排、不垂直居中；窄屏上下排。
- 读者可以切换**配色**（亮、暗、护眼）；**皮肤**在开课时定好，因为插画按皮肤画法画。

## 三、互动的底线

- 互动出场前用一句话说清它要回答什么问题；"试试看"写明要做什么，完成时给反馈。
- 控件少，读者 3 秒内知道怎么玩；最好先预测，再看结果；能撤销、能重来。
- 难的玩法进进阶抽屉。选择题只放在练习里。
- 键盘能用，触屏目标够大。
- 细则见 `interaction.md`。

## 四、动效的底线

按作用分四类，各有规矩（细则见 `interaction.md`）：

| 作用 | 规矩 |
|---|---|
| 帮助理解 | 关掉动效也保留最终状态，信息不丢 |
| 反馈操作 | 150–300ms；减少动态时只留颜色变化 |
| 阅读激励 | 只在读懂后触发一次，不打断阅读 |
| 氛围 | 只在正文以外，默认轻量，可一键关 |

全局尊重 `prefers-reduced-motion`，顶栏有"全开 / 轻量 / 关"三档开关。

## 五、可选模块（开课时逐项决定，写进项目文档）

- **阅读激励**：机制通用，外观随皮肤（笔记本→集邮册、图鉴、盖章；纸片爬塔→背包、亮灯）。只奖励"读懂了"（答对、完成试试看），不奖励滚动到底或停留时长。
- **陪伴角色**：默认不加。有世界观或读者年纪小时才加；点击才说话，台词和读到的内容有关，可关，键盘可触发，语气平常。
- **概念关系图**：概念多、彼此牵连时加；和概念卡、图鉴共用一份概念数据。
- 声音、术语表、闪卡、学习路径等，见 `modules.md`。

## 六、开新课的流程

1. 和用户定主题、读者、篇章（内容按 content-rules.md）。
2. 从 `skins/` 推荐 1–2 套皮肤，用户选；选可选模块。
3. 用 `starter/new-course.mjs` 生成骨架（kit、皮肤、配置、目录页、第 1 章模板、项目文档模板），改 `js/course.js` 的章节表和模块开关。
4. 做一章样板给用户确认写作、版式、节奏，再铺开。
5. 每章交付前跑检查（见第七节），不能只看汇报。

## 七、检查（防止"写的时候看不见"的错）

代码是盲写的：字体实际宽度、屏幕宽度、几个文件之间的类名对不对得上，都只有打开页面才知道。所以写完必须跑检查，agent 不能自己跳过；用户明确说"先不测"时可以跳过，但交付时列出未测清单。

**一键检查**（工具都在本 skill 的 `tools/`，必须传绝对路径）：

```
node <skill>/tools/check.mjs <课程文件夹绝对路径> [ch02,ch03] [--fast]
```

| 步 | 查什么 | 抓得到的错 |
|---|---|---|
| 1 语法 | 每个 .js `node --check`，每段内联脚本试编译 | 整页脚本不跑 |
| 2 接线 | JS 去找的 `vl-` 类，页面和脚本里有没有造出来；页面写的类有没有样式 | 改名没同步、按钮没反应、样式不生效 |
| 3 配图密度 | 两个视觉之间超过约 300 字（框里也算；英文按词折算） | 长文无图 |
| 4 链接 | 本地 href / src 是否存在 | 图片、脚本路径写错 |
| 5 运行 | `qa.mjs`：420 和 1100 宽度下点遍按钮、拖遍滑块 | JS 报错、横向溢出、图内文字压线/出界/重叠 |
| 6 截图 | 每页 420、1100 整页图 | 打印路径，**必须用 Read 打开看** |

`--fast` 只跑 1–4（几秒，不开浏览器），适合边写边查；交付前跑完整版。

**脚本之外必须人眼看的**（截图后逐项看）：图解文字是否压线、插画人物是否合规（脚落地、手握物、不悬空，用 `tools/illus-overlap.mjs` 辅助）、配色对比度、一节的节奏是否符合第一节。单张图用 `tools/shot.mjs <html> <png> "选择器@序号" 1100` 截下来放大看。

**交付汇报必须写**：跑了哪几步、结果（贴 ✗ 行）、看了哪些截图、没测的项目。"语法通过"不等于"测试过"。

**流程**：写完 → `--fast` 修到 0 → 完整版修到 0 → 看截图 → 修 → 再跑一次 → 交付。主控收到 agent 交付后，自己再跑一次完整版并看截图。

## 八、学新的

**中英两份**：英文版 skill 在 `../course-kit-en/`，两份共用同一套代码（kit、skins、tools、starter），以中文版为准。改了代码就跑 `node tools/sync-en.mjs` 同步过去；改了规则（SKILL.md、references/）就在英文版对应条目同样改一遍。

用户每次对画面、组件、交互的反馈，归纳成一条规则改进对应文件的原条目；新皮肤验收后加进 `skins/`。
