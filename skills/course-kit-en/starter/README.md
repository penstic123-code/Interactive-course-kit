# starter/: starter templates for a new course

Purpose: when starting a new course, one command sets up the shared skeleton (kit + skin + config + contents page + chapter 1 skeleton + project document), after which you build the sample chapter. `kit/README.md` is the authority for the component API, and section 1 of `SKILL.md` for pacing.

This is the English translation of the Chinese `course-kit/starter/README.md`, which remains the source of truth. The templates themselves are shared with the Chinese edition; the English-only versions are in `starter/en/`.

## 1. One command

```
node <skill>/starter/new-course.mjs <absolute course folder path> <skin name> [--lang en] [--update-kit]
```

- `<skin name>` is required and has no default: notebook / paper / pixel / fieldbook. Ask the user first (`SKILL.md` section 6). If it is missing or wrong, the script lists the available skins and exits.
- The course folder is created if it doesn't exist; **existing files are never overwritten** (they are skipped and listed).
- `--lang en`: an English-only course. Pages, config, illustration pack and the course's own stylesheet come from the same-named templates under `starter/en/` (`<html lang="en">`; placeholders and comments are in English, and UI text goes through the kit's English table automatically). The project document is generated as `course-rules.md` (from `course-rules.template.md`) and `项目规则与经验.md` is not generated. Without the flag you get a Chinese course. A bilingual course doesn't use this flag; see section 5.
- `--update-kit`: replaces only `kit/` and `skin/` with the latest versions from the skill (for upgrades) and touches nothing else.
- The storage prefix `id` is derived from the folder name (lower-case English, hyphens, a trailing `-course` removed, at most 24 characters; `course` if the name is all Chinese). Check it once in `js/course.js` after generating, and never change it after the course is live.

## 2. What gets generated

| Path in the course | Comes from | Edit it in the course? |
|---|---|---|
| `kit/` | the skill's `kit/` (no demo pages at all: `demo*.html`, `modules/demo-*.html`, `modules/demo/`) | **No**: overwritten wholesale on upgrade |
| `skin/` | the skill's `skins/<skin name>/` (without `gallery.html`) | **No**: the course's adjustments go in `css/style.css` |
| `css/style.css` | `starter/style.css` | The course's own small styles (adjustments beyond the skin, content-rules.md section 5) |
| `js/course.js` | `starter/course.config.js` | Chapter table, parts, open chapters, language, learning paths, module switches |
| `js/illus-ch01.js` | `starter/illus-ch01.js` | Chapter 1's illustration pack; one `js/illus-chNN.js` per chapter |
| `index.html` | `starter/index.html` | Contents page (chapter cards grouped by part, progress, learning paths; language switch in the top bar) |
| `ch01-intro.html` | `starter/ch01-template.html` | Chapter 1 skeleton; placeholders are written in `【】` and HTML comments |
| `项目规则与经验.md` | `starter/项目规则与经验.template.md` | The course's positioning, numbers, skin, modules, image credits list |
| `lib/README.md` | generated by the script | Register of third-party libraries (content-rules.md section 7) |
| `img/` | the script creates an empty folder | Real images, `img/chNN/english-name.jpg` |

With `--lang en`: `css/style.css`, `js/course.js`, `js/illus-ch01.js`, `index.html` and `ch01-intro.html` come from the same-named files under `starter/en/` (placeholders are written as `[Fill in: …]`; `css/style.css` gets one extra rule that hides the language button, because the top bar on an English page always shows a "中文" button and an English-only course has no Chinese pages). `项目规则与经验.md` is replaced by `course-rules.md` (from `starter/course-rules.template.md`), and `lib/README.md` is in English.

The folder structure matches section 5 of content-rules.md. No demo page is copied: a fresh course has only the two pages `index.html` and `ch01-intro.html`.

The script writes the `<link>` for the interactive components `kit/vl-interact.css`, the skin's `skin/interact.css` and `skin/diagrams.css` (the skin look of the concept diagrams), and the `<script>` for `kit/vl-interact.js`, into the template at the `<!--VL:EXTRA-CSS-->` and `<!--VL:EXTRA-JS-->` markers. The optional modules in `kit/modules/` are only listed in comments, because each loads at a different point (`vl-concepts.js`, for example, must come before `vl.js`); add the ones you chose by hand, following `kit/README.md` section 8.

## 3. Steps for starting a course

1. Ask for the art style first (choose a skin), then readers, length, language and modules, and give the user a course plan to approve (`SKILL.md` section 6).
2. Run `new-course.mjs`.
3. Edit `js/course.js`: `id`, `title`, `CH` (chapter name / English name / file name / one-line description), `OPEN`, `PARTS`, `PATHS`, `MODULES`.
4. Fill in sections 1, 4, 5 and 6 of `项目规则与经验.md`.
5. Edit the contents page `index.html`: the subtitle, "what it covers / who it is for / what you can do afterwards", and the header illustration.
6. **Build the sample chapter first**: fill in every placeholder in `ch01-intro.html` (prose per `zh-teaching-prose`, or `en-teaching-prose` for English), draw the illustrations into `js/illus-ch01.js`, and show the user so they can approve the writing, layout and pacing before you roll out. Copy the sample chapter for new chapters, not the empty template (the empty template is only for the first use).
7. Before delivering each chapter, run the checks (`SKILL.md` section 7):

   ```
   node <skill>/tools/check.mjs <absolute course folder path> ch01 --fast    # fix until 0
   node <skill>/tools/check.mjs <absolute course folder path> ch01           # fix until 0, then open the printed screenshots with Read and look
   ```

   A freshly generated course shows many dashed illustration placeholders (with the illustration's name written in them). These are reminders, not errors; none may remain at delivery.

## 4. Adding a chapter

1. Add an entry to `CH` in `js/course.js`, and add the chapter number to `OPEN` once it is written.
2. Copy the sample chapter as `chNN-english-kebab-name.html`, and change `<body data-ch="N">`, `<title>`, the `js/illus-chNN.js` reference, and the in-page class prefix to `cN-`.
3. Create `js/illus-chNN.js`, with illustration names prefixed `cNN-`.
4. People standing in illustrations: feet are not at the same height in every skin, and the y values in the examples follow notebook. When you change skins, check with `k.feetY(x, y, opts)` that the feet land on `ground()` (see `references/skin-contract.md` section 3) instead of copying the numbers.
5. Run the checks. Reordering or renumbering follows the remapping process in section 5 of content-rules.md.

## 5. English courses and bilingual courses

| Course | How to start | Where the pages are |
|---|---|---|
| Chinese only | default | course root |
| English only | `--lang en` | course root (`<html lang="en">`) |
| Chinese and English | default (Chinese first); add `en/` once the Chinese is final | Chinese in the root, English as same-named files in `en/` |

**UI text**: the kit picks the language from `<html lang>`. A page with `lang="en"` automatically uses the English tables in `kit/vl.js` and `kit/vl-interact.js` (top bar, Try it, concept card tags, expand / collapse, quiz buttons, diagram hints…). To change a UI string for a course, put it in `window.VL_I18N.en` in `js/course.js`. English demo page: `kit/demo-en.html`.

**The `en/` pages of a bilingual course** (content-rules.md section 6):
1. Copy `starter/en/ch01-template.html` or the matching Chinese chapter into `en/`, with a file name **identical** to the Chinese page; set `<html lang="en">`.
2. Add one `../` to every asset path: `../kit/vl.css`, `../skin/skin.css`, `../css/style.css`, `../js/course.js`, `../kit/vl.js`, `../js/illus-chNN.js`… Links between chapters don't get it (pages in `en/` link to each other).
3. Share one `js/course.js`: give every chapter in the chapter table both `zh` and `en`, give the parts `en`, write `descEn` for the contents page's one-liners, and `nameEn` / `whoEn` for the learning paths. The English contents page `en/index.html` is `starter/en/index.html` with the paths changed.
4. **Do not** copy the rule in `starter/en/style.css` that hides the language button (that is for English-only courses). The top bar's language button: on Chinese pages it stays hidden until `enReady: true`; on English pages it is always shown and points to `../same-name file`. Set `enReady` to `true` only after all the English pages are done.
5. **Progress and notes are shared between the two languages**: the storage key is `<id>-…` plus the file name, with no language in it, so `en/ch03-x.html` and `ch03-x.html` read and write the same progress, Try-it state, notes and open/closed state. So the id, file name, `data-save` and `data-try` must match on both sides; change one and you must change the other.
6. Illustration packs can be shared (write the text layer so it picks Chinese or English by `VL.lang`), or the English edition can have its own `js/illus-chNN-en.js`.
7. Checking: `check.mjs` checks `en/` along with the rest, and runs the same way.
